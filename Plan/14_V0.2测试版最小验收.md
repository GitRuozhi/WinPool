# WinPool V0.2 测试版最小验收

## 1. 目标与定位

本文件定义 2026-08-08 起的 **V0.2 可全面试用测试版** 验收范围。它取代发布级、
大型、长周期矩阵作为当前切换门槛，但不改变正式发布前仍须补做的完整验收。本文件本身
不授权 Git 操作；用户已于 2026-08-08 另行明确授权提交并推送当前 V0.2 版本，但仍未授权
tag 或 release。

测试版目标是：六个产品页面和已有功能可用；App、可见托盘 Agent、TestWorker、一次性
Broker、SQLite、只读采集、模拟编辑、文件型测试、监控、历史、比较、导出和 Settings
形成一条可实际使用的 V0.2 主线。暂不要求大型目录、填满卷、多小时压力、全部 DPI/主题
组合或全部外部工具真实执行。

## 2. 本机授权边界

### 2.1 唯一允许结构修改的磁盘

用户已人工确认 E: 无需保留数据，并授权在必要时修改其存储结构。2026-08-08 只读核验值：

| 字段 | 必须匹配的值 |
| --- | --- |
| DriveLetter | `E:` |
| Disk Number（本次枚举） | `0` |
| FriendlyName | `WDC WD40EZAZ-00SF3B0` |
| SerialNumber | 用户当次授权值；仅在运行时内存核验，不写入文档、日志或导出 |
| UniqueId | 用户当次授权值；仅在运行时内存核验，不写入文档、日志或导出 |
| BusType | `SATA` |
| IsBoot / IsSystem | `False / False` |
| 当前布局 | GPT；E: 为 Partition 2、NTFS、约 4 TB |

任何可能改变结构的动作都必须在动作前重新从 E: 反向解析磁盘，并同时核对型号、序列号、
UniqueId、非启动盘和非系统盘。Disk Number 不得单独作为授权依据。任一字段缺失、变化、
多重匹配或 E: 已映射到其他磁盘时立即拒绝。

本授权只说明 E: 可以作为可处置目标，不要求为了验收而无目的清盘、重分区或格式化。
V0.2 测试版若无需真实结构修改即可完成当前能力验收，应保留现有布局。

### 2.2 绝对禁止的目标

- C:（当前 Disk 1）和 D:（当前 Disk 2）及所有其他本机、外接、网络磁盘，不允许任何
  初始化、清盘、联机状态切换、分区、格式化、存储池、Tier 或 VirtualDisk 结构修改。
- D: 只允许在明确登记的测试目录中创建、读写、验证和清理临时测试文件。
- 不清理 Windows Update、组件存储、Installer、Recovery、WRP 或其他受保护系统内容。

## 3. 最小工具范围

2026-08-08 本机检测：

- DiskSpd 2.2：已安装，可执行最小真实文件测试；
- RoboCopy 10.0：系统自带，可执行最小复制与验证；
- fio：未检测到；测试版只要求 Settings 正确显示缺失、允许配置路径并在使用时提示安装；
- 兼容 Dite.exe：未检测到；测试版只要求缺失提示及旧 CSV 只读导入链路；
- RAMMap 1.63：已安装并可检测；不作为本轮真实执行的必要条件。

外部工具仍不随 WinPool 发布，也不得用 C#、Win32 或 PowerShell 重写其测试引擎。

## 4. 测试版最小验收矩阵

### 4.1 自动门

- Release x64 全 solution 构建零错误、零警告；
- 串行全量 .NET 测试全部通过；
- Dite FileGen Python 恢复测试通过；
- 205 个兼容 ID 集合精确一致；
- `git diff --check` 通过；
- 发布输出不包含 `.ps1`；真实存储结构修改仍无自由命令入口。

截至 2026-08-08，本节自动门已完成：Release 构建零警告、零错误，.NET 448/448、
Dite FileGen 4/4 通过，`git diff --check` 通过，Release 输出未发现 `.ps1`。GUI、真实小型
工具和短时监控仍按下列章节继续验收。

### 4.2 GUI 与生命周期

- 启动 App，Agent 托盘可见，正常只读采集完成；
- `Ctrl+1`～`Ctrl+6` 和标题栏入口可到达 Manage、Edit、Test、Monitor、Development、Settings；
- 关闭主窗口后 Agent 继续存在；重新打开只产生或激活一个 App；
- 从托盘退出后 App、Agent、Worker、Broker 和受监督工具树全部退出；
- 中英文各完成一次主路径烟雾；系统主题至少完成当前主题和相反主题各一次；
- 不要求发布级全部 DPI、高对比度、窄窗和截图像素矩阵。

### 4.3 功能主路径

- Manage：启动缓存、后台刷新、五分类、完整拓扑、本机与模拟比较、CSV 导出；
- Edit：至少完成模拟重命名、分区操作、建池和虚拟磁盘计划各一次；本机非授权目标仍拒绝；
- Test：在 D: 登记目录执行一个小型 DiskSpd 测试和一个小型 RoboCopy 复制/验证；验证历史、
  比较、取消和至少一种导出；
- Monitor：运行 5～10 分钟，关闭主窗口后继续采样，重开后恢复窗口并可导出；
- Development：能查看运行时、计划/步骤、算法和脱敏事件，不能执行自由命令；
- Settings：工具检测、自定义路径、缺失提示、语言/主题、数据位置计划摘要均可用；
- R3：至少审阅并执行一个低风险、身份绑定的允许动作；其警告、审计和结果可见。若动作会
  改变可逆系统状态，必须验证恢复。

### 4.4 数据与恢复

- 使用测试专用小数据副本完成一次标准→便携→标准 Plan/Apply/回退烟雾；来源始终保留；
- 强制终止一次无外部大 I/O 的测试 Worker，证明 Agent 收敛状态并回收受监督子进程；
- 不要求百万级以外的新压力规模，也不要求大型附件迁移耗时基准。

## 5. 测试版切换条件

满足本文件第 4 节后：

1. 产品显示版本统一为 `V0.2`；schema、算法和 IPC 版本继续独立；
2. 新架构成为唯一正常启动主线，旧 JSON 仅保留无 Agent 开发回退；
3. 在 `09_实施状态台账.md` 记录每项最小验收的实际结果和未执行的发布级矩阵；
4. 生成测试版已知限制：fio/Dite/RAMMap 可能未安装，真实存储结构管理仍以模拟和安全端口
   为主，发布级长时间、全视觉和大型 I/O 验收尚未完成；
5. 当前版本的 commit/push 已获用户明确授权；tag 和 release 仍须另行明确授权。

## 6. 失败停止条件

出现以下任一情况立即停止实机动作并保留证据：

- E: 身份字段不再完全匹配；
- 计划或 UI 指向 C:、D:、其他磁盘、磁盘根目录或未登记路径；
- 出现未预期的 UAC、自由命令、原始设备写入、镜像/移动/清除参数；
- Agent、Worker、Broker 或工具进程树不能被识别和回收；
- SQLite quick_check、计划哈希、附件哈希或恢复状态不一致；
- 测试过程出现文件系统错误、Event 55、永久写失败或其他存储健康异常。
