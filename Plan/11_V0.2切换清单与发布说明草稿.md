# WinPool V0.2 切换清单与发布说明草稿

## 1. 文件定位

本文件是 WP7 的执行草稿，不代表已经达到 V0.2 完成定义，也不授权 Git 提交、推送、
发布、安装外部工具或执行真实存储结构修改。实际状态以
`09_实施状态台账.md` 和 `10_兼容性审计台账.md` 为准。

## 2. 冻结前阻断门

只有以下项目全部有当前工作树证据时，才允许进入一次性切换：

- Release x64 全解决方案构建零错误、零警告；
- 串行全量 .NET 测试及 Dite FileGen 恢复测试全部通过；
- 205 个兼容 ID 不再包含未开始、实现中或仅凭旧实现推断通过的条目；
- 主界面关闭后可见托盘 Agent 持续运行，从托盘退出后 App、Agent、TestWorker、
  ElevatedBroker 和外部工具进程树全部退出；
- 当前机器和 Broker 底层持续拒绝建池、删池、分区、格式化等真实存储结构修改；
- 文件型测试只能写入计划登记目录，路径逃逸、reparse point 和超配额均被拒绝；
- DiskSpd、fio、RoboCopy、RAMMap 和兼容 Dite 仍由外部工具适配器执行；
- R3 动作完成真实 UAC、取消、失败、崩溃恢复、审计和用户警告验收；
- Monitor 完成长周期、背压、断连重连和关闭主界面后持续采样验收；
- 中英文、主题、强调色、100%/125%/150%/200% DPI、高对比度、键盘、窄窗和
  截图基线全部通过；
- 标准与便携数据位置的 Plan→Apply、失败回退和保留旧文件演练通过；
- 三项隐私/采集策略未决事项得到用户确认并写回计划。

## 3. 人工迁移清单

V0.2 不自动读取或双写全部 V0.13 内部格式。迁移由用户显式选择并保留原文件：

1. 关闭所有 WinPool 测试运行，确认托盘没有正在恢复的 R3 状态。
2. 记录旧发布包、数据根、版本、文件数、总字节数和重要文件 SHA-256。
3. 复制而非移动旧数据到独立备份位置；不得覆盖旧数据库或 JSON。
4. 启动 V0.2 Agent，让其创建当前 schema 的全新 SQLite 数据库。
5. 只通过受支持的导入入口导入模拟系统和 Dite 历史；逐项核对计数、主键、来源哈希
   和算法版本。
6. 工作区 UI 状态不迁移；手工重新选择页面、系统、分类和对象。
7. 外部工具只重新检测或由用户选择自定义路径，不复制第三方二进制到发布包。
8. 对标准/便携位置切换先执行 Plan，核对来源、目标、数据库、附件数量和可写性，再
   Apply；旧位置必须保留。
9. 完成一次 App/Agent 重启，复核模拟文档、测试历史、监控历史、工具路径和偏好。
10. 记录迁移报告；任何计数或哈希不一致都停止切换并保留两侧证据。

## 4. 一次性切换步骤

1. 停止功能开发，只处理阻断缺陷。
2. 重新执行 Release 构建、串行全量测试、依赖漏洞审计和 `git diff --check`。
3. 完成人工 UI、安全、外部工具、长周期监控和数据位置矩阵。
4. 在模拟环境执行完整 Test 工作流；在当前机器只执行已批准的文件型测试和 R3 动作。
5. 证明所有真实存储结构修改在 Application、Execution、Agent 和 Broker 边界均被拒绝。
6. 完成第 3 节的手工迁移演练并保存报告。
7. 将所有产品显示版本统一改为 V0.2，同时保留数据库 schema 和协议的独立版本号。
8. 将新架构设为唯一活动实现；旧 V0.13 源码、发布包和数据备份移入项目根 `Old` 的
   对应保留结构，不直接删除。
9. 再次执行全量构建、测试和 GUI 启动/托盘退出烟雾。
10. 只有用户另行明确授权后，才允许提交、推送、打标签或发布。

## 5. 回退演练

- 回退恢复 V0.13 发布包及其原数据副本，不把 V0.2 SQLite 反向写回旧格式；
- 保留失败时的 V0.2 数据库、WAL/SHM、附件、日志、计划、审计和崩溃证据；
- 记录停止点、失败代码、进程状态、数据位置和已执行的 R3 恢复结果；
- 如果临时电源计划或进程调度尚未恢复，保持可见 Agent 和托盘警告，禁止静默退出；
- 不直接删除失败实现，按项目规则移动到项目根 `Old` 或 `Rubbish`。

## 6. 发布说明草稿

WinPool V0.2 是一次架构重写：主界面、可见托盘 Agent、隔离 TestWorker 和一次性提权
Broker 通过当前用户保护的类型化命名管道协作。关闭主界面不会停止后台监控，从托盘
退出会执行有界的监控停止、数据库 flush、临时系统状态恢复和受监督进程回收。

V0.2 使用 SQLite 保存监控、测试、计划、事件、证据索引、模拟系统和工作区状态；真实
I/O、复制和缓存辅助仍调用 DiskSpd、fio、RoboCopy、Dite 和 RAMMap 等外部工具，第三方
工具不随 WinPool 发布。设置页提供检测、自定义路径和受控安装入口。

当前版本禁止创建、删除或修改真实 Storage Spaces、分区和文件系统结构。文件型测试及
受控临时清理、Flush、TRIM/Optimize、测试进程调度和临时电源计划需要目标复核、计划
哈希、警告/确认、审计与恢复。现有只读脚本暂时保留，原生采集替换路径已经建立。

经本项目当前测试得到的 Storage Spaces 配置结论仍为：64K interleave + 64K NTFS
cluster 是当前已测试推荐；Windows 11 尚未获得等效完整测试。
