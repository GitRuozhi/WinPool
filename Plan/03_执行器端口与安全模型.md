# V0.2 执行器端口与安全模型

## 1. 目标

V0.2 现在设计完整执行器边界。保护目标是防止真实存储结构被意外修改，
不是禁止正常监控、测试文件读写和测试所需的受控系统操作。

安全不能只依赖按钮禁用。限制必须同时存在于：

1. Presentation：清楚展示模式和风险。
2. Application：拒绝不符合上下文的用例。
3. Policy：根据环境、目标、操作和能力作出决定。
4. Executor：在最底层再次验证授权。
5. Infrastructure：不提供可绕过的自由命令入口。
6. Tests：证明任何绕过上层的调用仍会被拒绝。

## 2. 不可破坏的安全不变量

1. 当前机器的 `EnvironmentProfile` 固定为 `ProtectedDevelopmentMachine`。
2. 任何真实磁盘初始化、分区、格式化、存储池、存储层、虚拟磁盘等存储结构修改计划都必须返回 `Rejected`。
3. Real 模式、管理员权限和 UAC 成功都不等于修改授权。
4. 模拟对象永远不能解析成真实 Windows 对象并执行。
5. 真实目标必须在执行前重新发现并核对稳定身份。
6. UI 生成的字符串、导入文件和数据库内容都不能直接成为命令。
7. PowerShell 端口只接受程序集内固定的只读脚本。
8. 测试文件只能位于用户明确选择并经计划确认的测试目录，且只能操作本次运行登记的文件。
9. 计划变化后原授权立即失效。
10. 审计和持久化内容必须先脱敏。
11. DiskSpd、RoboCopy、fio、RAMMap 等只能通过已登记工具适配器和参数数组启动。
12. 开发阶段允许临时文件清理、RAMMap 系统缓存/standby list 清理、卷 Flush、
    TRIM/Optimize、进程优先级/CPU affinity 和临时电源计划；发布版本执行前必须
    警告或确认。
13. 托盘 Agent 存活时托盘图标必须可见；不得完全静默后台运行。

## 3. 执行能力模型

```csharp
[Flags]
internal enum ExecutionCapability
{
    None = 0,
    ReadInventory = 1 << 0,
    ReadPerformanceCounters = 1 << 1,
    OpenNativeProperties = 1 << 2,
    SimulateStorageMutation = 1 << 3,
    ReadFileTest = 1 << 4,
    WriteFileTest = 1 << 5,
    RunExternalTestTool = 1 << 6,
    CleanTemporaryFiles = 1 << 7,
    FlushVolume = 1 << 8,
    TrimOrOptimizeVolume = 1 << 9,
    AdjustProcessScheduling = 1 << 10,
    UseTemporaryPowerPlan = 1 << 11,
    InstallExternalTool = 1 << 12,
    ClearSystemFileCache = 1 << 13,
    MutateStorageStructure = 1 << 14
}
```

能力不从管理员身份自动推导。能力来自受控环境配置和用户对具体环境的明确授权。

当前机器允许：

- `ReadInventory`
- `ReadPerformanceCounters`
- `OpenNativeProperties`
- `SimulateStorageMutation`
- `ReadFileTest`
- `WriteFileTest`
- `RunExternalTestTool`
- `CleanTemporaryFiles`
- `FlushVolume`
- `TrimOrOptimizeVolume`
- `AdjustProcessScheduling`
- `UseTemporaryPowerPlan`
- `ClearSystemFileCache`
- 经用户确认的 `InstallExternalTool`

当前机器禁止：

- `MutateStorageStructure`

发布版本中的允许不代表静默执行：

- R2 文件测试显示测试根目录、预计写入量和清理范围。
- R3 系统辅助操作在首次或每次运行按设置警告/确认。
- 工具安装始终需要明确用户确认；需要管理员权限时使用一次性提权 Broker。

## 4. 环境配置

```csharp
internal sealed record EnvironmentProfile(
    EnvironmentId Id,
    EnvironmentKind Kind,
    string MachineBinding,
    ExecutionCapability AllowedCapabilities,
    bool IsUserProvidedDisposableEnvironment,
    DateTimeOffset CreatedAt);
```

环境类型：

- `ProtectedDevelopmentMachine`：当前机器，允许受控测试，但禁止存储结构修改。
- `Simulation`：纯内存或 SQLite 模拟系统。
- `Replay`：读取历史测试和监控证据。
- `UserProvidedDisposableMachine`：未来由用户明确提供。
- `RemoteAgent`：仅保留概念，不在 V0.2 实现。

`MachineBinding` 必须基于不可逆摘要和本机稳定信息生成；不得保存原始序列号。

## 5. 操作请求和不可变计划

UI 先创建 `OperationRequest`，不能直接调用执行器：

```csharp
internal sealed record OperationRequest(
    OperationId Id,
    EnvironmentId EnvironmentId,
    SystemId SystemId,
    OperationIntent Intent,
    IReadOnlyList<StorageObjectId> Targets,
    IReadOnlyDictionary<string, object?> Parameters,
    DateTimeOffset RequestedAt);
```

Planner 生成不可变 `OperationPlan`，至少包含：

- 操作和环境身份；
- 目标稳定身份及扫描版本；
- 类型化参数；
- 所需能力；
- 风险等级；
- 前置条件；
- 预计写入量和影响范围；
- 步骤与依赖；
- 取消边界；
- 验证步骤；
- 回退说明；
- 不可回退说明；
- 计划生成算法版本；
- `PlanHash`。

计划展示给用户的是这些结构化内容的本地化视图，而不是先生成 PowerShell 字符串再解析。

## 6. 风险等级

| 等级 | 示例 | 当前机器 |
| --- | --- | --- |
| R0 只读 | 扫描、PDH 监控、查看属性 | 允许 |
| R1 模拟写入 | 修改模拟文档、模拟测试 | 允许 |
| R2 文件级可恢复写入 | 在专用测试目录创建、写入、校验和清理登记文件 | 允许，显示计划 |
| R3 受控系统辅助 | 临时文件清理、RAMMap 缓存/standby list 清理、Flush、TRIM/Optimize、进程调度和临时电源计划 | 开发默认允许；发布警告或确认 |
| R4 存储结构修改 | 初始化、磁盘状态/类型、分区、格式化、建池、建层、建虚拟磁盘 | 禁止 |
| R5 不可逆或广泛破坏 | 清盘、移除池、强制修复、原始设备写入 | 不实现 |

风险等级只会上调，不得由适配器自行下调。

## 7. 授权流程

```text
OperationRequest
  -> Planner
  -> Static validation
  -> Refresh target inventory
  -> Identity and state comparison
  -> Policy evaluation
  -> Capability check
  -> User review
  -> Authorization token
  -> Executor revalidation
  -> Execute
  -> Post-verification
  -> Audit result
```

当前机器的 R4–R5 在 `Policy evaluation` 阶段无条件拒绝，不显示可绕过按钮。
R2–R3 需要目标限定、审计和恢复策略。开发策略可默认批准已列入计划的 R2–R3；
发布策略必须按操作类型显示警告或确认对话框。

未来授权令牌应：

- 只对应一个 `PlanHash`；
- 绑定环境和机器；
- 绑定目标集合；
- 有短有效期；
- 一次性使用；
- 不持久化为下次自动授权；
- 不因进程管理员身份而自动生成。

## 8. 执行器端口

### 8.1 当前实现

- `SimulationOperationExecutor`
  - 修改模拟文档；
  - 生成与真实计划相同形状的事件；
  - 支持故障注入、取消和恢复测试。
- `ReadOnlyWindowsExecutor`
  - 固定只读采集；
  - PDH/只读系统信息；
  - 打开 Windows 原生属性界面。
- `ReplayExecutor`
  - 重放历史执行和测试事件；
  - 不接触真实目标。
- `ExternalToolTestExecutor`
  - 在 Test Worker 中启动 DiskSpd、RoboCopy、fio 等已配置测试工具；
  - 限定工作目录、测试根目录、参数、超时和子进程树；
  - 解析结构化或已知版本输出并保存原始日志。
- `SystemTestSupportExecutor`
  - 执行临时文件清理、RAMMap 缓存清理、Flush、TRIM/Optimize；
  - RAMMap 只接受已登记清理模式；需要管理员权限时委托一次性提权 Broker；
  - 调整并恢复测试进程优先级和 CPU affinity；
  - 临时切换并恢复电源计划。
- `ToolInstallExecutor`
  - 根据官方安装计划下载或启动安装；
  - 用户确认后按需使用一次性提权 Broker；
  - 不在 WinPool 发布包内捆绑工具。

### 8.2 V0.2 设计但禁止真实实现

- `LocalStorageMutationExecutor`
  - 只定义 contract、计划模型和拒绝实现；
  - V0.2 不包含可调用 Windows 修改命令的生产实现。

### 8.3 禁止的实现方式

- 对 UI 暴露 `Execute(string command)`；
- 从 UI、SQLite 或导入文件读取自由命令；
- 通过 `cmd.exe /c` 或 `powershell -Command` 拼接参数；
- 允许工具访问已批准测试根目录之外的文件；
- 用盘符或显示名称作为唯一目标；
- 在执行器内部偷偷提升权限；
- 发现授权缺失后回退为“尽力执行”。

外部工具适配器可以启动固定可执行文件，但必须传递参数数组、固定工作目录、
受控环境变量和显式标准输入；不得经过通用 shell 字符串。

## 9. 测试目录与文件边界

每次测试创建 `AuthorizedTestWorkspace`：

- 用户选择的根目录；
- 规范化绝对路径；
- 卷和系统身份；
- 计划生成的运行子目录；
- 允许创建的文件清单或命名规则；
- 最大总写入量；
- 清理规则；
- 有效期。

要求：

1. 所有路径先规范化并验证仍在运行子目录内。
2. 拒绝 reparse point、junction 或符号链接逃逸。
3. 不覆盖未登记的现有文件。
4. RoboCopy 源和目标分别授权。
5. 清理只删除本次运行登记且身份匹配的文件。
6. 原始磁盘设备路径和卷设备路径不可作为写入目标。
7. 用户取消清理时保留文件和证据，不扩大删除范围。

## 10. 允许的系统辅助操作

### 10.1 临时文件清理

允许范围由类型化 provider 枚举：

- WinPool 自身临时目录；
- 当前用户临时目录；
- Windows Temp 中符合明确规则的普通临时文件。

强制排除：

- Windows Update 和 Delivery Optimization 数据；
- WinSxS/component store；
- Windows Installer；
- System32、驱动、恢复环境；
- Windows Resource Protection 管理的文件；
- 用户未明确选择的应用数据；
- reparse point 指向的外部目录。

清理先扫描和展示预计范围，再执行；保存成功、跳过和失败清单。

### 10.2 Flush 与 TRIM/Optimize

- 目标卷在计划和执行前各解析一次。
- Flush 记录调用方式、耗时和结果。
- TRIM/Optimize 记录 Windows 工具/API、模式、开始结束和输出。
- 不把 TRIM/Optimize 与建池、修复或格式化混为同一能力。
- 发布版本必须警告其会影响当前卷性能状态。

### 10.3 进程调度

- 只调整 WinPool 启动的 Test Worker 和工具进程树。
- 保存原优先级和 affinity。
- finally、取消、错误和崩溃恢复时还原。
- 禁止修改无关系统进程。

### 10.4 临时电源计划

- 切换前保存活动计划 GUID。
- 新状态和原状态写入执行事件。
- 正常、取消、错误和下次 Agent 启动时尝试恢复。
- 恢复失败必须通知用户。

### 10.5 RAMMap 系统缓存/standby list 清理

- RAMMap 是外部测试辅助工具，不随 WinPool 发布，也不由 C#/Win32 重新实现。
- 初始兼容 Dite 已使用的 `-Es`、`-Et` 组合；具体语义和支持版本在适配器样例测试中锁定。
- Application 只提交类型化 `RamMapCacheClearMode`，适配器映射为白名单参数数组；
  UI、导入文件、数据库和 IPC 都不能注入自由参数。
- 执行前重新检测 RAMMap 路径、版本、签名/发布者和 SHA-256；缺失时提示安装或
  配置自定义路径。
- 该动作属于独立的 `ClearSystemFileCache` 能力，不能由 `CleanTemporaryFiles`
  或普通 `RunExternalTestTool` 隐式获得。
- 开发策略默认允许；正式产品执行前警告或确认缓存清理会改变测试条件和系统当前
  内存状态。
- 每次保存请求模式、实际参数、工具身份、开始结束、退出码、stdout/stderr，以及
  可获得的执行前后内存/缓存监测快照。
- RAMMap 需要提升权限时由一次性 `WinPool.ElevatedBroker` 执行；Broker 仍只接受
  计划哈希绑定的固定 RAMMap 动作，不接受可执行文件路径或自由命令行。

## 11. PowerShell 保留策略

当前程序集内嵌的只读 PowerShell 脚本保留，并封装为
`LegacyPowerShellInventoryProvider`：

- 脚本文本固定并随程序集构建；
- 通过标准输入传递；
- 不接受用户片段；
- `ReadOnlyStorageCommandPolicy` 继续扫描禁止词；
- 输出仅进入规范化采集模型；
- 脚本文件不落盘。

原生采集器采用并行比较方式替代：

1. 同一次扫描调用两种提供程序。
2. 按 154 个稳定字段 ID 比较。
3. 区分一致、格式差异、来源不支持、真实冲突。
4. 对真实冲突保存脱敏诊断。
5. 每个字段都有通过标准和验证记录。
6. 全部必要字段通过后，再由用户批准移除脚本。

## 12. 外部工具安装安全

- 工具不随 WinPool 发布。
- Settings 显示缺失、已发现、路径无效、版本不支持和可更新状态。
- 用户可配置自定义可执行文件路径。
- 安装按钮先显示工具、来源、许可、目标位置、需要的权限和预计动作。
- 只从登记的官方来源获取安装信息。
- 下载使用 HTTPS，并在可用时验证数字签名、发布者和官方哈希。
- 没有可验证哈希时明确警告并保存下载来源和实际 SHA-256。
- 安装先使用 WinPool 当前进程权限；仅在目标位置或安装器确实要求管理员权限时，
  才使用一次性 `WinPool.ElevatedBroker`，完成后立即退出。
- 功能需要缺失工具时给出安装或配置路径提示，不静默下载。
- 开发期间如果工具缺失，可以在开发者确认后直接执行相同安装流程。

## 13. 目标重确认

执行前必须重新读取目标状态并比较：

- 系统和环境身份；
- 磁盘号与稳定硬件键；
- 分区号、起始偏移、大小和卷身份；
- Pool、Tier、VirtualDisk 的稳定标识；
- 健康和只读状态；
- 自计划生成后的扫描版本变化。

任何关键差异都使计划失效并要求重新生成。不得把旧计划自动套用到新目标。

## 14. 审计模型

每个计划和执行保存：

- 请求、计划和 `PlanHash`；
- 策略决策及规则版本；
- 环境和能力；
- 目标身份摘要；
- 每个步骤的开始、结束、结果和验证；
- 取消、异常和恢复；
- 算法 ID 和版本；
- 用户可见提示的本地化键；
- 脱敏诊断。

不保存：

- 明文硬件序列号；
- 任意命令行中的敏感路径；
- 可重放的授权令牌；
- 用户导入的未验证脚本内容。

## 15. 必须存在的安全测试

1. 当前机器的每一种 R4–R5 请求都被拒绝。
2. 管理员进程仍不能获得存储结构修改能力。
3. Real 模式仍不能获得存储结构修改能力。
4. R2 测试文件只能位于授权运行目录。
5. 路径穿越、junction、符号链接和未登记文件被拒绝。
6. 模拟对象不能映射到本机对象。
7. 计划参数变化使授权令牌失效。
8. 目标扫描变化使计划失效。
9. 过期、复用、其他机器或其他环境的令牌被拒绝。
10. 导入文件不能产生自由命令。
11. 日志和数据库中没有未脱敏序列号。
12. Test 页可以创建和清理登记测试文件，但不能覆盖无关文件。
13. 临时清理不能进入 Windows Update、component store、Installer、保护目录。
14. 电源计划和调度设置在成功、取消、失败和崩溃恢复时还原。
15. 工具安装未经用户确认不能开始。
16. 工具适配器不能经通用 shell 执行自由命令。
17. PowerShell 提供程序拒绝任何非内嵌采集脚本。
18. 托盘退出会停止 Agent、主界面、Worker、Broker 和工具子进程。
19. RAMMap 缺失、路径/哈希变化、未确认或参数不在白名单时均被拒绝。
20. RAMMap 只能通过 `ClearSystemFileCache` 执行，不能借普通外部工具能力绕过。

这些测试是切换到 V0.2 的阻断条件。
