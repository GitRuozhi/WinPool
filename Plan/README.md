# WinPool V0.2 重写计划

## 计划状态

本目录是用户明确批准的 WinPool V0.2 一次性重写计划包。

- 当前可运行基线：V0.13。
- 目标版本：V0.2。
- 计划语言：中文。
- 实施方式：一次性大爆炸重写，在新架构完整达到验收条件后整体切换。
- 外观基线：冻结当前 V0.13 的整体外观、信息架构和主要交互结果。
- 内部实现：允许重写、修错、重构和重新划分项目。
- 后端范围：不要求在 V0.2 完成所有真实后端，但必须先设计稳定的内部 Application contracts、执行器端口和安全模型。
- 数据策略：引入 SQLite；旧测试数据格式和当前 JSON 持久化格式不要求自动兼容，必要时手工迁移。
- 安全边界：除 `14_V0.2测试版最小验收.md` 精确登记的 E: 物理磁盘外，当前机器禁止真实存储结构修改；D: 只允许在明确测试目录内创建、写入、读取、校验和清理本次运行登记的测试文件。

版本号 `V0.2` 是本次明确指定的产品里程碑名称，不得因为当前版本为
`V0.13` 而自行改成其他编号。

## 决策基线

以下决策在本计划中视为已确认：

1. 计划文件集中存放在 `Plan`，可包含多个文件。
2. 计划和实施说明使用中文。
3. 前端不禁止继续开发；后端暂不要求完整实现，但执行器端口和安全模型必须现在设计。
4. 当前需要保留的能力、脚本和产品行为继续保留，直到对应原生替代完成并通过验收。
5. 只冻结外观和最终用户可见的主要布局结果；允许修复错误并重构前端。
6. 本阶段是重写，不是对现有三项目结构的小修小补。
7. 新架构必须覆盖并兼容全部已有功能，同时完整实现测试页产品能力。
8. 测试能力吸收 Dite、KS、WEMigration 等现有工具的调度、恢复、测量和证据思想；DiskSpd、RoboCopy、fio、RAMMap 等测试与辅助能力继续通过外部工具使用，不在 C# 或 Win32 中重新实现。
9. 当前 PowerShell 采集脚本保留；原生采集完成并对照验证后再移除。
10. 旧持久化格式不要求自动完整兼容；测试阶段允许手工迁移。
11. 测试和监控高容量数据进入 SQLite。
12. 允许为架构目标增加必要项目、进程、内部依赖和经过审查的第三方包。
13. 不冻结公共 API；先形成稳定、可测试的内部 Application contracts。
14. 计划纳入完整算法；推测性算法必须在文档和代码注释中明确标记，后续逐项验证。
15. 保持当前产品的双语、主题、隐私、便携模式和可访问性方向。
16. 接受一次性架构切换及由此带来的内部格式变化。
17. 除 2026-08-08 用户明确授权且必须逐次复核型号、序列号和 UniqueId 的 E: 磁盘外，当前机器禁止修改真实存储结构；D: 允许受控测试文件操作，并允许临时文件清理、RAMMap 系统缓存/standby list 清理、卷 Flush、TRIM/Optimize、进程优先级/CPU affinity 和临时电源计划。
18. 已有备份允许本阶段采用一次性大爆炸重写，之后通过持续测试修复稳定。
19. 重写目标版本为 V0.2。
20. 范围包含全部现有页面、已有功能、测试、监控、数据、执行器端口和安全模型。
21. 监控运行在带托盘图标的独立用户进程；关闭主界面不停止监控，从托盘退出才完整退出全部 WinPool 进程。
22. DiskSpd、fio、RAMMap 等外部工具不随 WinPool 发布。Settings 提供检测、安装和自定义路径；安装前必须由用户确认，缺少工具时按功能提示安装。安装先使用 WinPool 当前进程权限，仅在动作确实需要管理员权限时启动一次性 UAC Broker。

## 适用优先级

- 当前 V0.13 的实际运行外观是外观冻结基线。
- 本目录定义 V0.2 的目标架构和实施边界。
- 根目录四个现有文档仍描述当前版本；开始实施 V0.2 时应同步更新。
- 任何冲突都采用更严格的真实存储结构保护、隐私脱敏、证据保留和禁止直接删除规则；
  “保护”不禁止计划明确允许的监控、登记测试文件读写或 R3 系统辅助操作。
- `14_V0.2测试版最小验收.md` 构成对其中精确登记 E: 磁盘的有限测试授权；不构成对任何其他磁盘、卷、存储池、Tier 或 VirtualDisk 的授权。

## RAMMap 补充决定

- RAMMap 是允许使用的外部测试辅助工具，处理系统缓存/standby list 清理；它与删除系统临时文件是两种独立能力。
- 沿用 Dite 已有 RAMMap 经验作为初始基线，但 WinPool 只暴露类型化白名单动作，不接受自由参数。
- 开发阶段默认允许执行；正式产品执行前必须警告或确认，并保存工具版本、路径、SHA-256、参数、结果及清理前后监测证据。
- RAMMap 不随 WinPool 发布；Settings 提供检测、经用户确认的安装按钮和自定义路径。

## 成功标准摘要

当前优先目标是 `14_V0.2测试版最小验收.md` 定义的可全面试用测试版；以下仍是后续正式替换与发布级完成标准。

V0.2 只有在以下条件同时满足时才能替换 V0.13：

- 所有已有页面和功能通过兼容矩阵。
- 测试页成为完整产品模块，而非占位页。
- Dite 的调度和证据思想进入 WinPool，实际测试及缓存清理通过 DiskSpd、RoboCopy、fio、RAMMap 等外部工具适配器执行。
- 监控和测试数据可持续写入 SQLite，UI 不因写入阻塞。
- 真实存储结构修改在最底层执行端口被拒绝；测试目录文件操作和批准的辅助系统操作正常执行并审计。
- 主界面关闭后托盘 Agent 可继续监控；托盘退出会完整停止所有 WinPool 进程。
- 缺少的外部工具可从 Settings 经用户确认安装，或配置自定义路径。
- PowerShell 采集仍可用，原生采集可并行对照，未验证前不移除旧路径。
- 构建、单元、集成、安全、数据库、算法和 UI 验收全部通过。
- 切换后仓库只保留一套活动架构，不长期维护双实现。
