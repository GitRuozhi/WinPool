- `dotnet list WinPool.slnx package --vulnerable --include-transitive` 对全部项目报告无已知漏洞。

`dotnet format WinPool.slnx --verify-no-changes --no-restore` 仍会报告 V0.13 前端既有大段
对象初始化器的空白格式差异；本轮没有为消除该基线差异而批量改写已冻结外观代码。

SQLite 初次还原时，`Microsoft.Data.Sqlite 10.0.10` 的传递依赖解析到存在高危公告的
`SQLitePCLRaw.lib.e_sqlite3 2.1.11`。项目已显式固定到兼容的 `2.1.12`，并以 NuGet
漏洞审计重新验证为无告警；不得移除该固定而不重新执行漏洞审计。

## 6. 未决策事项

以下事项不阻塞 WP1 的无副作用安全骨架，但在对应工作包开始前必须由用户确认：

1. V0.2 原生采集器是完整可选 provider，还是仅交付骨架和首批字段、继续以脚本为主。
2. 多进程模式下，隐私开关需要显示明文硬件 ID 时，是否允许在当前用户受 ACL
   保护的命名管道中短时传输，或必须把该查看能力限制在不经 IPC 的本机流程。
3. 外部工具“原始证据”中可能含绝对路径或机器字段：选择持久化前脱敏，还是采用
   加密证据库并在导出时强制脱敏。
工具集合不再固定为四项：当前四项是首批适配器，内部契约允许以后增加外部工具。
Release 的 R3 执行核心要求显式用户确认；Development 策略允许开发验证，但仍必须通过
目标复核、登记/身份门禁和结构化审计。
