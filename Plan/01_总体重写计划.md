# WinPool V0.2 总体重写计划

## 1. 重写目标

V0.2 将 WinPool 从“前端原型加少量服务”重写为边界清晰、可测试、可扩展的
Windows 存储管理、测试和监控应用。

本阶段不要求完成真实存储修改后端，但必须形成足以承载未来实现的完整架构：

- 前端可继续迭代和修错；
- Application 层用例与内部契约稳定；
- Domain 层不依赖 WinUI、PowerShell、SQLite 或具体 Windows API；
- 所有外部行为通过端口进入；
- 执行器先完成计划、验证、安全、审计和模拟执行；
- 测试与监控从第一天按高数据量设计；
- 当前机器禁止真实存储结构修改，但允许受控的文件型测试和已批准的测试辅助系统操作。

## 2. 外观冻结与允许修改

### 2.1 冻结内容

以 V0.13 实际运行界面为准冻结以下结果：

- 标题栏页签和整体窗口结构；
- Manage、Edit、Test、Monitor、Development、Settings 的页面身份；
- Manage 上部完整拓扑、下部对象操作区及水平分隔方式；
- System、Pool、Tier、Disk、Partition 的纵向分类和横向对象比较表；
- 嵌套块表达拓扑、无关系连线的视觉语言；
- 当前主题、强调色、中文/英文和欢迎界面的整体风格；
- Monitor 的曲线、表格、控制区三部分外观；
- 当前图标、卡片、间距和主要交互反馈的总体视觉方向。

冻结的是用户看到的结果，不是 XAML、控件树、ViewModel 或事件处理代码。

### 2.2 允许修改

- 修复布局、主题、焦点、键盘、缩放、高对比度和本地化错误；
- 重构页面、控件、ViewModel 和导航；
- 拆分过大的 code-behind；
- 使用新 Application contracts 替换直接服务调用；
- 为性能和可测试性调整内部状态模型；
- 在不改变总体外观的前提下修复不一致的控件行为；
- 为完整测试页加入当前尚不存在的界面内容；
- 为错误、进度、执行计划和结果增加必要但风格一致的界面。

## 3. V0.2 功能兼容矩阵

| 当前能力 | V0.2 目标 | 主要归属 | 验收重点 |
| --- | --- | --- | --- |
| 单实例和激活已有窗口 | 完整保留 | Shell | 重复启动只激活一个窗口 |
| Simulation/Real 状态与 UAC 交接 | 保留 UX，重写状态机 | Application/Execution | 模式不持久化；不解除存储结构保护 |
| Manage 完整拓扑 | 完整保留 | Presentation/Application | 关系、选择、排序和高亮一致 |
| 对象比较表和 CSV 导出 | 完整保留 | Presentation/Export | 列选择、冻结列、换行和导出一致 |
| 本机只读扫描 | 保留脚本并增加原生替代端口 | Inventory | 两实现可对照；不得执行修改 |
| `machine.json` 快速启动 | 改为 SQLite 快照，允许人工迁移 | Persistence | 启动可先显示上次快照再后台刷新 |
| 模拟系统持久化、导入导出 | 完整保留 | Simulation/Persistence | 导入只作为数据，不执行命令 |
| Edit 模拟修改 | 完整保留并迁入用例层 | Application/Simulation | 本机对象在所有层都被拒绝 |
| 本机原生属性与优化入口 | 保留 | WindowsIntegration | 每次点击重新解析目标 |
| Monitor 实时采样、曲线、CSV | 完整保留并迁入独立托盘 Agent 和 SQLite | Monitoring/Agent | 主界面关闭后继续，高吞吐、取消、导出 |
| Development 命令日志 | 扩展为计划、步骤和事件检查器 | Diagnostics | 可追踪但不泄露敏感信息 |
| Settings、主题、语言、隐私 | 完整保留 | Presentation/Preferences | 即时切换、默认跟随系统 |
| 标准/便携数据位置 | 完整保留 | Persistence | SQLite 与附件根目录一起切换 |
| Test 占位页 | 重写为完整测试工作区 | Testing | 预设、工具、计划、运行、图表、历史、比较、导出 |
| Dite/KS/WEMigration 思路 | 吸收调度、恢复、采集和证据设计 | Testing/Application | 不把旧程序本身作为唯一架构边界 |
| DiskSpd、RoboCopy、fio、RAMMap 等 | 通过类型化外部工具适配器调用 | Testing.Tools | 检测、版本、路径、解析、取消和证据完整 |
| 外部工具安装 | Settings 提供安装按钮和自定义路径 | ToolManagement | 不随包发布；用户确认后安装 |
| 当前 PowerShell 采集 | 暂时保留 | Inventory.Legacy | 原生结果验证完成前不得移除 |

## 4. 目标解决方案结构

建议目标结构如下；实施时允许按编译依赖进一步合并小项目或增加进程，但不得破坏依赖方向：

```text
WinPool.slnx
src/
  WinPool.Shell/                    WinUI 主界面、导航和前台生命周期
  WinPool.Agent/                    托盘、后台会话协调、监控和 SQLite 单写入
  WinPool.Presentation/             页面、控件、ViewModel、本地化与主题
  WinPool.Application/              用例、内部 contracts、协调和策略
  WinPool.Domain/                   领域对象、值对象、规则和纯算法
  WinPool.Execution/                计划、验证、授权、执行状态机和审计
  WinPool.Inventory/                采集协调、规范化和来源比较
  WinPool.Infrastructure.Windows/   Win32、PDH、PowerShell、系统集成适配器
  WinPool.Infrastructure.Sqlite/    SQLite、迁移、批量写入和查询
  WinPool.Simulation/               模拟执行器、场景和故障注入
  WinPool.Testing/                  测试定义、调度、指标和结果分析
  WinPool.Testing.Tools/            DiskSpd、RoboCopy、fio、RAMMap 等外部工具适配器
  WinPool.ToolManagement/           工具发现、版本、安装、路径和校验
  WinPool.Monitoring/               采样、缓冲、聚合和会话管理
  WinPool.Ipc/                      命名管道消息、握手、版本和访问控制
workers/
  WinPool.TestWorker/               隔离运行测试工具和解析结果
  WinPool.ElevatedBroker/           一次性提权安装或执行批准的系统辅助动作
tests/
  WinPool.Domain.Tests/
  WinPool.Application.Tests/
  WinPool.Execution.Tests/
  WinPool.Inventory.Tests/
  WinPool.Persistence.Tests/
  WinPool.Testing.Tests/
  WinPool.Monitoring.Tests/
  WinPool.Presentation.Tests/
  WinPool.Safety.Tests/
```

依赖方向：

```text
Shell/Presentation
        |
        v
   Application
   /    |     \
Domain Execution  Application Contracts
        ^                ^
        |                |
Infrastructure / Testing.Windows / Sqlite / Simulation
```

Domain 和 Application 不引用 WinUI、SQLite、PowerShell、外部工具进程或 Win32。
主界面、Agent、测试 Worker 和提权 Broker 的职责与关闭语义见
`08_多进程托盘与IPC架构.md`。

## 5. 一次性大爆炸重写策略

“一次性”指最终切换，不等于不做阶段性验证。

### 阶段 A：基线冻结

- 记录 V0.13 功能清单、页面状态、快捷键、主题和双语表现。
- 保存主要窗口尺寸和高 DPI 下的截图基线。
- 固定当前 40 项测试作为最低回归集合。
- 记录当前存储采集、模拟系统、监控 CSV 和导出样例。
- 保留当前代码和发布包作为回退基线。

退出条件：兼容矩阵中的每项都有明确测试或人工检查方法。

### 阶段 B：建立新骨架

- 新建目标项目和依赖边界。
- 定义内部 Application contracts。
- 建立组合根、依赖注入和统一时钟、ID、取消、日志抽象。
- 建立 SQLite schema、迁移器和数据位置服务。
- 建立执行计划和安全状态机。

退出条件：空壳应用可启动；架构依赖测试通过；当前机器修改端口默认拒绝。

### 阶段 C：迁移领域与模拟能力

- 迁移存储对象、拓扑、选择、布局和发现算法。
- 迁移全部模拟操作与模拟作业。
- 把命令文本从“可执行字符串”改为计划预览或诊断说明。
- 迁移隐私脱敏、导入导出和查找规则。

退出条件：现有 Core 行为全部在新 Domain/Application 测试中通过。

### 阶段 D：重写前端但保持外观

- 重建 Shell、导航和页面 ViewModel。
- 按页面迁移 Manage、Edit、Monitor、Development、Settings。
- 用新 contracts 替换 code-behind 中的业务协调。
- 保持 V0.13 视觉基线，修复已知主题、布局和交互错误。

退出条件：除 Test 外的现有功能矩阵全部通过。

### 阶段 E：外部工具测试页、托盘 Agent 与监控数据层

- 实现测试定义、任务调度和 DiskSpd、RoboCopy、fio、RAMMap 等工具适配器。
- 实现工具发现、Settings 安装按钮、自定义路径、版本和哈希记录。
- 新建带托盘图标的用户 Agent；关闭主界面后由 Agent 持续监控。
- 使用命名管道连接主界面、Agent 和按需 Test Worker。
- 完成 Test 页完整工作区。
- 监控和测试数据改用 SQLite 批量写入。
- 保留 CSV/JSON/Markdown 导入导出作为交换和证据格式。
- 在明确选择的测试目录运行真实文件型测试；运行登记之外的文件不得触碰。
- 开发阶段允许临时文件清理、RAMMap 系统缓存/standby list 清理、卷
  Flush、TRIM/Optimize、进程优先级/CPU affinity 和临时电源计划；最终产品
  执行前警告或确认。

退出条件：测试模块可通过已配置工具端到端运行；存储结构修改仍被安全模型拒绝；
关闭主界面后监控继续，托盘退出后所有 WinPool 进程退出。

### 阶段 F：采集器并行替换

- 保留当前 PowerShell 提供程序。
- 开发原生 Windows 采集提供程序。
- 建立字段级结果对照、来源标记和差异报告。
- 只有在全部目标字段通过验证后，才提出移除脚本的单独计划。

退出条件：V0.2 可以选择旧脚本或原生提供程序，失败时有明确诊断。

### 阶段 G：整体切换

- 冻结新架构。
- 完成全量自动测试和人工 UI 验收。
- 手工迁移必要测试数据。
- 将产品版本改为 V0.2。
- 一次性替换活动实现，不保留长期双架构。

退出条件见 `05_实施切换与验收.md`。

## 6. 明确不在当前阶段实施的内容

- 真实建池、建层、建虚拟磁盘、初始化磁盘、格式化、创建/调整/删除分区或其他存储结构修改。
- 原始磁盘设备写入和未限定目录的测试写入。
- 未经计划与授权端口直接执行任意 PowerShell、CMD 或外部命令。
- 公共 API、公共插件 ABI、远程控制协议或稳定 wire format。
- 为旧 JSON、旧测试数据和中间开发数据库提供长期自动迁移承诺。

测试文件操作和允许的系统辅助动作必须使用类型化计划、限定目标、记录审计并在结束时恢复可逆设置；不得借测试之名修改存储结构。

## 7. 主要风险

| 风险 | 控制方法 |
| --- | --- |
| 大爆炸重写遗漏现有功能 | 以兼容矩阵和 V0.13 回归基线逐项验收 |
| 前端重构破坏冻结外观 | 截图基线、主题矩阵和人工视觉检查 |
| 执行器端口被误用为存储结构修改授权 | 能力分级、目标限定和底层二次检查 |
| SQLite 高速写入拖慢 UI | 有界通道、批事务、独立写入线程和背压指标 |
| 外部工具版本或输出格式变化 | 工具适配器版本检测、解析契约、样例回放和失败隔离 |
| Agent 隐藏运行或无法完整退出 | 托盘可见性不变量、进程注册表和完整退出测试 |
| 工具安装来源不可信 | 官方来源、用户确认、签名/哈希和安装审计 |
| PowerShell 与原生采集结果不一致 | 字段级来源、差异报告和逐项验收 |
| 手工迁移遗漏数据 | 迁移清单、校验和、行数与抽样核对 |
| 推测算法被误当成结论 | 文档和代码统一标记 `【推测，待验证】` |

## 8. 当前推荐工作顺序

1. 先建立架构与安全测试，不先写真实执行器。
2. 再迁移 Domain、Simulation 和数据层。
3. 重写前端并恢复全部现有功能。
4. 完成外部工具 Test 编排、独立托盘 Agent 和 Monitoring 数据管线。
5. 并行开发原生采集，但保留 PowerShell。
6. 全量验收后一次性切换为 V0.2。

任何阶段都不得在当前机器上使用真实修改作为验证手段。
