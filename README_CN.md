# WinPool

[English](README.md) | [简体中文](README_CN.md)

WinPool 是一款第三方 Windows 存储系统图形界面，旨在以一个现代、统一的工作区，替代 Windows 系统中老旧且相互割裂的“磁盘管理”和“存储空间”图形界面。

WinPool 的目标包括：

- 清晰展示存储系统、存储池、存储层、磁盘、虚拟磁盘、分区及其他存储对象之间的层级关系；
- 使用完整、可检查的参数建立存储对象；
- 提供现代化的存储测试与监控功能；
- 为开发者预留稳定的集成接口；
- 提供清晰、结构化、可预测的操作方式，方便 AI Agent 理解和调用。

## 当前开发阶段

WinPool 当前处于 **V0.2 一次性架构重写与集成阶段**。已经确认的 V0.13 外观继续作为视觉基线，同时允许修复前端错误和进行重构。

合并后的架构现在以产品版本 **V0.21** 对外显示。V0.2 继续作为已批准重写计划和架构里程碑的名称；数据库 schema、算法和 IPC 版本继续独立演进。

仓库中包含可运行的 WinUI 3 主程序，以及独立的可见托盘 Agent、TestWorker 和按次启动的提权 Broker。项目正在整合稳定的内部 Application contracts、类型化命名管道、SQLite 持久化、测试、监控、模拟和默认拒绝的执行边界，但不冻结公共 API。

当前初稿能够同时管理一个只读本机系统和多个可持久化模拟系统。第一个模拟系统来自
KS/StatSys 采集快照；完整系统文档可以导出，也可以重新导入为新的可编辑模拟系统。

当前阶段遵循以下原则：

- 模拟存储数据是正常且允许使用的开发数据源；
- 后端不需要完整实现前端所表达的所有未来真实存储管理能力；
- 已有功能和原测试页范围都要在重写架构中保留和吸收；
- 当前 Windows 信息采集保持只读，在前端完善期间可以是不完整的；
- 本机采集通过 Windows PowerShell 5.1 执行程序集内嵌的固定只读命令，不再发布可写的 `.ps1` 采集文件；
- 内置 KS 参考系统保留 13 类、154 项结构化结果；本机实时报告已原生采集全部条目，
  仅少数 Windows 无法通过只读查询提供的条目明确标记为不可用；
- 模拟重命名、盘符、格式化、删除分区、磁盘状态和池优化作业只修改模拟文档；
- “编辑”页现在可以完整演练模拟流程——可选 MSR 的磁盘初始化、分区扩展/压缩/删除/新建、
  拖拽磁盘建池、以及带 64K 交织与 64K 簇默认参数的虚拟磁盘创建——本机的所有修改入口保持禁用；
- “测试”页通过类型化适配器编排用户另行安装或配置的 DiskSpd、fio、Dite、RoboCopy、RAMMap；这些工具不随 WinPool 捆绑发布；
- 主窗口关闭后，可见的当前用户托盘 Agent 可以继续监控；它不是服务，从托盘退出会请求完整退出整个软件；
- 正常启动由托盘 Agent 执行固定只读采集，把脱敏规范化快照和有界完整文档写入 SQLite v10，并向主界面提供缓存；`machine.json` 只保留为无 Agent 开发启动的回退；
- 前端需求不冻结公共 API、数据库、插件协议或 C#/Python 通信格式。

界面表达的是产品的目标方向，不代表每一个可见流程都已经连接到可用于生产环境的后端。

## 产品方向

### 存储管理

WinPool 希望把 Windows 存储对象作为一个相互关联的整体呈现，而不是继续分散在多个缺乏关联的管理对话框中。主要界面应同时提供：

- 面向当前对象的工作区，用于显示属性、警告和适用操作；
- 完整存储拓扑，用于保留存储池、存储层、磁盘、虚拟磁盘和分区之间的关系。

未来的创建和管理流程应提供完整的相关参数、可检查的操作计划，并在执行前清晰展示操作结果和影响。

### 测试与监控

WinPool 把存储测试、健康监控、性能观察、结果对比和证据导出整合到同一个产品中。V0.2 的主要集成已完成相当一部分，真实工具、长时间运行、UAC、恢复和完整 GUI 验收仍在进行。

### 开发者与 AI 集成

面向开发者和 AI Agent 的未来集成应采用类型明确的对象、稳定标识、显式参数、结构化结果，并严格区分读取操作和修改操作。当前尚未冻结任何公共集成协议。

## 当前安全边界

当前程序仍禁止修改真实存储结构。

- 不得创建、初始化、格式化、扩容、修复、删除或以其他方式修改存储对象。
- 文件型测试只能在用户明确选择的测试目录中创建、读写、验证和清理本次运行登记的文件。
- 类型化并审计的系统辅助动作可以清理允许的临时文件、执行卷 Flush、TRIM/Optimize、调整已登记测试进程或临时切换电源计划；最终软件必须先警告或确认，并恢复可逆状态。
- 外部测试工具独立安装，可在设置中配置路径或经用户确认安装。
- 程序默认使用“模拟”，所有前端开发和演示均可以使用模拟数据。
- 存储修改能力必须等待单独批准的实现阶段，并且只能在可抛弃的测试环境中验证。

## 技术方案

当前初稿使用：

- C# 与 WinUI 3；
- .NET 10；
- Windows App SDK；
- 未打包、自包含的 x64 桌面部署方式。

开发环境、工程结构、构建命令和实现边界见 [DEVELOP.md](DEVELOP.md)。

## 研究背景

WinPool 来源于 WinPool Storage Spaces 研究项目。在已经完成的 Windows 10 22H2 测试范围内，当前经过测试的建议是：

```text
64K interleave + 64K NTFS allocation unit size
```

Windows 11 尚未完成等价测试。
