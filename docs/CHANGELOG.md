# WinPool 变更记录

## 2026-09-15：硬件报告与 KS 能力接线

硬件页改为 Computer、System、Mainboard、CPU、Memory、VirtualMemory、Storage、GPU、Monitor、Network 十段纵向报告，Memory 总体与模组分开，多设备在段内横向查看。新增只读 DXGI/D3D12 显卡与输出事实、原生网络接口事实和 BIOS 模式；关联只使用 LUID、接口 ID、硬件 ID 或唯一 PCI 标识，不按名称和顺序猜测。属性详情显示原值、类型、单位、状态、来源与时间；本机刷新可取消，完整系统 JSON 导出保留来源事实，不做脱敏。

管理页和硬件页改用同一存储摘要，失败、未采集、成功空集合和真实零值分开表达；只小范围复用表格单元格样式。内部格式保持 SQLite 16 / IPC 7 / 文档 3 / 来源事实 1。全套 546/546 测试、Release 构建和依赖审计通过；中文深色、英文浅色、多设备横向滚动、窄窗、键盘详情、刷新、系统切换、导出和取消保存已用隔离 WinUI 核对。当前机器只有 96 DPI 显示器，192 DPI 为 `unverified`。证据与范围见[硬件报告实施核对](Reference/20260915_硬件报告实施核对.md)。未执行真实存储写入。

## 2026-09-15：分区联合体与本机采集修复

管理属性移除独立卷分类，分区、卷和逻辑磁盘来源组合为同层业务对象；来源 ID 可解析到联合体，旧选择与编辑入口同步映射。未知关联的对象保留在“其它”，不伪造磁盘或偏移。分区与文件系统容量分别保留。统一属性选择修复 NTFS、分配单元和可用容量被旧缺失标记遮盖的问题，盘符的 C / C: 视为同值，来源冲突仍可追溯。

存储刷新补齐 DiskDrive、分页/转储角色及 Windows 版本；不支持的可选电池类标为不可用，失败查询仍保留旧事实和来源时间。重复刷新不累积状态记录，主机单例身份不随显示名称改变。管理系统区域移除 CPU/内存。模拟编辑保留有效补充关联，删除附属对象时不遗留逻辑盘。

Release App/Agent 编译 0 警告、0 错误。按用户要求未运行自动测试。使用 native-winui-control 在独立运行目录与数据库副本上检查：本机属性补齐；连续两次存储刷新及一次完整硬件刷新后均为 67 条来源对象、33 个来源、29 条关联（原始来源计数，并非界面业务对象数）；可选电池来源不可用，整体采集成功。模拟卷标编辑在编辑页与管理页一致生效；导入断开分区—卷关联的副本后，孤立文件系统仍显示，磁盘/偏移未知且几何编辑禁用。未进行真实存储写操作；不将这些人工检查宣称为全部设备场景验收。

## 2026-09-14：V0.52 统一事实、只读硬件与模拟编辑

采集、保存、管理、硬件和模拟使用统一来源事实；物理/虚拟/OS 磁盘、分区/卷保持独立身份并按可靠关联组合。新增只读硬件页，完整硬件按需刷新；字段原值、单位、读取状态、来源、时间和空/失败原因可见。普通名称、描述和路径保留，硬件标识脱敏。

修复缺失安全字段误变 false/0、部分刷新丢关系、本地逻辑盘误分类网络盘、无对象时隐藏采集失败等问题。无依据的层归属显示未知；旧报告模型/工厂和旧快照解释路径已移出构建，有效补充采集保留。

编辑会话集中管理基线、MAX、历史和创建意图，单一类型化请求贯通预检查、模拟及逐步命令；目标分组、用途与分区表类型不再混用名称参数。名称 Enter 独立提交，放弃和撤销不回滚名称。原生验收补修放弃后的延迟表单事件，空计划不能应用；用途待办显示友好名称。

内部格式为 SQLite 16 / IPC 6 / 文档 3 / 来源事实 1，旧格式明确拒绝，不迁移或删除旧数据。真实存储仍只读，命令预览不执行。本轮 546/546 自动测试、Release 构建和审计通过，有限原生实测与性能边界见 [核对证据](Reference/V0.52-实施核对.md)；不代表所有设备、全部 DPI 交互和长期可靠性验收。

## 2026-09-11：V0.51 磁盘编辑与入口一致性

联机/脱机通过类型化操作写入模拟文档并持久化，脱机对象只读；初始化、MBR 转 GPT、最大空隙创建和固定 GPT 分区类型使用统一规则。允许正式空池，建池拆为池、虚拟磁盘、分区三个动作；管理页补齐热备/退役层，换行按行数平均分配，并修复 MAX、草稿名称和六组入口不一致。

后续修复新池自动 VD 缺少 OS 磁盘身份、已有池新 VD 的身份碰撞、池属性绕过脱机 VD 保护，以及切换分区类型后文件系统选项残留。再次实测发现“使用最大容量”只修复了文本解析：含数据池仍禁用按钮，WinUI 延迟事件还会清掉 MAX 模式，未编辑层的显示舍入和可空参数也会被误报为结构修改。现已只允许含数据层通过 MAX 扩大容量，继续拒绝手工容量、缩小和层参数修改；原生界面验证 `Pool01` 从 SSD 232.5 GiB 规划到 236 GiB 后可保存且应用按钮可用。

补充复查发现嵌套 Flow 仍按固定列数形成 6+1，原 4+3 用例没有经过实际布局引擎；脱机虚拟磁盘虽受提交规则保护，结构页池属性仍可编辑；已有空池的创建按钮会继承自动 VD 开关，且显式分区步骤错误指定未分配区域起点。现已在实际拓扑引擎中均分每行对象，脱机关联池的全部结构控件立即只读，并让已有空池稳定生成独立的虚拟磁盘和分区动作。物理磁盘、虚拟磁盘和 OS 磁盘卡片会按关联的持久化状态，在既有右上角状态图标组内显示主题色脱机图标；分区页自适应单行磁盘标题补齐类型图标和 Windows 标记。脱机状态跨 App/Agent 完全重启保留、图标与固定/有数据图标同组且不重叠，已用原生 WinUI 验证。Application 212 项、Architecture 43 项及全套 510 项测试通过，完整 Release 构建 0 警告、0 错误；其它原生 UI 与真实设备场景仍未验证。

- 内部格式切换为 SQLite schema 15、IPC 5、StorageSystemDocument 2、StorageSnapshot 3；旧格式拒绝，无迁移。
- 2026-09-10 用户确认带成员的建池/改池可用并结束阶段。自动测试 460 项通过。完整设备、DPI、高对比度、托盘与长期运行仍为 unverified。真实存储结构修改继续拒绝。阶段计划见 [V0.48 归档](Archive/V0.48/README.md)。
