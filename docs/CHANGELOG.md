## 2026-09-16：统一层模拟池与模拟层

热备层、退役层、未划层统一为“模拟层”类型；其它磁盘池和网络磁盘池统一为“模拟池”类型。它们只在统一呈现中生成，不进入来源事实或持久化，不作为存储修改目标。管理页可选中、查看属性；无来源参数留空，原始字段显示“无原始来源”。层归属不清的成员仍进入未划层并标明未知；热备或退役用途优先决定拓扑位置，原始层关联不删改。

假池、假层不计算容量。实际层使用自己的来源容量，缺失与零分别保留，管理和编辑页不再以成员总容量回填。管理页只显示有成员的假对象，编辑器主动开启的空用途容器仍可用于拖放。

新增[统一对象与派生属性产品设计](UnifiedModel.md)，记录联合体、显示容器、自定义属性及设备计数口径，明确显示用假对象与模拟系统的区别。监控数据库轮换与 7z 归档计划保持未激活，未归档、未实施。

全套 Release 613/613 通过，完整构建 0 警告/0 错误。有限原生 WinUI 核对了中英文呈现、选择、空容量及无来源弹窗；完整主题/DPI/拖放与真实设备验收未执行，详见 [Quality](Quality.md)。

## 2026-09-16：USB 物理磁盘关联回退

固定只读采集在 `Get-Disk | Get-PhysicalDisk` 未返回关联时，按唯一的 `MSFT_PhysicalDisk.DeviceId = MSFT_Disk.Number` 回退连接物理盘与 OS 磁盘。该回退仅在编号唯一时启用，解决可移动 USB 已属于原始池却被展示为“其他磁盘”的问题；不会改动 Windows 存储配置。下次扫描会刷新既有本机记录。

“其它与网络”内置模拟系统新增一块 64 GB USB 闪存盘：USB 总线、不可池化（`RemovableMedia`）、MBR/exFAT 分区，以及与 OS 磁盘和原始池的完整关联均可用于界面和投影验证；该模拟快照版本升至 v6。

## 2026-09-16：恢复历史优先与 Agent 两阶段采集

管理页、硬件页在等待 Agent 之前先从只读 SQLite 连接加载历史事实；不创建或迁移数据库，Agent 仍是唯一写入者。每次 Agent 启动自动依次采集存储和完整硬件，保存后分阶段主动通知 App；存储阶段失败仍尝试完整采集，失败保留历史。App 晚连接或重连补读最新结果，旧回报不覆盖新结果。两页手动刷新继续触发对应采集，取消退出会等待后台启动采集结束。

移除“有缓存就不采集”的旧实现与测试，补充历史先于连接、两阶段采集、失败/取消、手动刷新、晚连接/重连、只读数据库和真实命名管道事件回归。IPC 升至 9，SQLite 17 和文档 3 保持不变；需要配套重启 App 与 Agent。全套 Release 测试 598/598 通过，独立 Release 构建 0 警告/0 错误。本轮原生页面目视验收为 `unverified`。

## 2026-09-16：本机默认选择与模拟版本区分

没有已保存工作区状态时，启动默认选择本机系统；有效的历史选择仍照常恢复。标题栏的系统选择器及其弹出选项均改为左对齐；设置和标题栏中的“本机真实操作”改名为“真实编辑”，不改变本机存储仍为只读、真实结构写入仍不可用的边界。

标题栏系统选择器使用固定 320 DIP 宽度的 `ComboBox`，使按钮和下拉列表的左边缘不随当前系统名称变化；选项文字保持左对齐。选择结果仍在下拉关闭后应用，保持切换工作区时不在打开的 WinUI 弹出层中重建页面。正在显示的存储结构编辑或磁盘分区编辑页会随系统选择重建自身，绑定新系统的池和磁盘快照，而不跳转到其它页面。

管理页已移除按分类导出 CSV 的命令与实现；“导出模拟系统”仍是独立的系统文档导出。旧“来源详情”侧栏命令改为硬件页和管理页表格的组级右键菜单：仅提供“复制当前值”“复制整组”“原始字段”。原始字段对话框显示当前选中组在统一层使用的来源字段、原值、类型、读取状态、采集来源和时间；复制整组使用“项名: 项值”逐行文本。

11 个策划内置模拟现在覆盖 Windows 10 Home / Pro、Windows 11 Home / Pro / Pro for Workstations、Windows Server 2022 Standard、Windows Server 2025 Standard / Datacenter；内核版本覆盖 10.0.19045、10.0.20348、10.0.26100、10.0.26200。快照版本已再次递增，现有内置文档会在下次加载时刷新。模拟版本仅用于参考展示，不构成 Windows 平台或真实存储配置的测试证据。

## 2026-09-16：设置布局、IPC 交接与整套提权重启修复

“开发者模式”已从外观卡片移至通用设置，外观卡片只保留主题、强调色和语言。标题栏的系统选择框新增与强调色联动的 40% 透明悬停底色和边框；高对比度模式不覆写系统可访问性外观。

真实执行模式的 UAC 交接现在是整套重启，而非“仅把 GUI 提权”：新管理员 bootstrap 在 WinUI、单实例和 Agent 连接之前等待；旧 App 保存工作区，旧 Agent 按既有顺序停止监控、写入、租约与管道，二者都退出后才创建新的管理员 App + Agent。新实例用 PID、启动时间和路径核验旧实例，不一致、取消、信号失败或超时不会接管、复用旧 endpoint 或强杀进程。修复了 SID 事件名哈希大小写不一致导致 bootstrap 误判 `signal_invalid` 的实际故障；阶段失败写入 `Diagnostics/elevation-handoff.jsonl`。交接启动后也不会再刷新已关闭的 WinUI 窗口，修复 `The WinUI Desktop Window object has already been closed` 未处理异常。

Agent 控制管道把已接通客户端的正常提前断开和断管视为连接结束，不再弹出误导性的 IPC 故障提示；其它真正异常仍会报告，并追加到数据目录 `Diagnostics/agent-control.jsonl`。进程身份核验改用受限进程查询，因此普通完整性的 Agent 可以核验 UAC 提升后的 App，不再依赖可能被拒绝访问的 `Process.MainModule`。隔离原生 WinUI 已连续三次验证旧 App+Agent 全退出、新 App 标题为 `WinPool [管理员]`、新 endpoint session 与 Agent PID 更换；取消和 30 秒 continuation 超时均保留旧实例。586/586 Release 测试通过，Release 源代码编译 0 警告、0 错误，依赖审计无已知漏洞包。未执行真实存储写操作。

## 2026-09-15：静态审查五项可靠性问题修复

修复控制管道被零字节或半帧握手长期占用，以及单次进程登记持久化异常终止监听的问题。握手读取现在有独立 5 秒期限；连接级异常以稳定诊断代码报告并释放当前连接，监听器继续接收后续客户端；监听任务自身若意外终止则进入 Failed 并通过托盘呈现。

SQLite schema 升至 17，监控样本保存当前全部 14 类指标，缺失写为 NULL、真实零仍为零，读取和 CSV 均保持区别。模拟文档 IPC 升至 8，列表改为最多 256 项的元数据分页，正文按 ID 单独读取，多个合法文档合计超过 4 MiB 时不再组成超限单帧。CommitId 现在绑定文档、前后哈希、修订、OperationId 和 PlanHash；幂等重试返回提交时的不可变文档回执，冲突请求明确拒绝，结果未知查询由 Agent 与客户端双重核验。审查输入保存在 [WinPool-static-review-7cd2b7c](WinPool-static-review-7cd2b7c.md)。全套 556/556 Release 测试通过，完整 Release 构建 0 警告、0 错误，依赖审计无已知漏洞包；未执行原生 UI 或真实存储操作。
