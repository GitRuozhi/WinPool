## 1. 开发者已经提出的决定

以下十条是本阶段的产品意图，优先于当前编辑页实现。它们不能覆盖真实存储变更安全边界。

1. 编辑页上下两个分区各占一半高度，分别上下滚动，不要一起滚动。
2. 不显示这两个区域的标题。
3. 上区左右两个子区域：左边逻辑拓扑，右边控件组。
4. 下区左右两个子区域：左边逻辑拓扑，右边控件组。
5. 上区逻辑拓扑复用管理页的逻辑拓扑视觉结构，并做如下投影：
   - 显示所有可管理分区的磁盘。
   - 池内物理磁盘不显示。
   - 虚拟磁盘可以分区则显示。
   - 磁盘内显示分区。
   - 只显示两级：磁盘和分区。不显示系统、池、层。
   - 所有磁盘竖排；磁盘内分区横排。
6. 下区逻辑拓扑复用管理页的逻辑拓扑视觉结构，并做如下投影：
   - 显示所有内部池，包括原始池。
   - 不显示外部池（例如网络池）。
   - 原始池显示到磁盘，不显示分区。
   - 存储池内显示层、磁盘、虚拟磁盘；虚拟磁盘显示分区。
   - 所有池右边再增加一个假池，显示加号；点击后创建一个新池。新池默认显示虚拟磁盘、性能层、容量层；虚拟磁盘显示未建立；两个层为空，无磁盘成员。
7. 下区右侧控件组按两列显示：左边项名、右边项值。项依次为：执行修改/创建新池、池名、虚拟磁盘名、性能层复原类型、性能层交织大小、性能层大小、容量层复原类型、容量层交织大小、容量层大小、分区系统格式、分区簇大小。
8. 下区逻辑拓扑中，可以自由把物理磁盘在各个池内拖动。
9. 物理磁盘自动进入对应层：SSD 进性能层，HDD 进容量层。
10. 有任何问题或边界不清晰时必须提问，不能在代码里猜。

## 2. 阻塞问题

这些问题未回答前不得开始实施。下面的建议默认值**不是**决定。

### Q1. 上区右侧控件组（阻塞）

下区右侧的行已经指定。上区右侧控件组没有指定。当前编辑页上区右侧是：扩展、压缩、删除、格式化、新建分区、初始化、脱机/联机，以及选中分区摘要。

重做之后，上区右侧控件组里放什么？

### Q2. 拖放何时写入文档（阻塞）

当前编辑页把磁盘拖到池上会立刻调用 `MovePhysicalDisk`。新下区右侧第一行是“执行修改/创建新池”。

在已有池（含原始池）之间拖动磁盘，是立刻提交模拟移动，还是等到点执行？

### Q3. 点击加号创建什么（阻塞）

加号是：

- 只在编辑工作区插入**本地草稿**池，执行成功后才写入文档；还是
- 立刻在模拟文档里创建一个空池？

当前 `CreateStoragePool` 至少需要一块原始池成员磁盘，并且不会创建层和虚拟磁盘。

### Q4. 本阶段是否修改已有池（阻塞）

“执行修改/创建新池”可以指：

- A. 创建在范围内；同时也可以改已有池的名称、复原、交织、大小和分区格式。
- B. 本阶段只创建。选中已有池时表格只读，或不显示执行。

当前模拟可以建池、建虚拟磁盘、移动磁盘、编辑分区。不能创建存储层，不能移动已经属于某层的磁盘，也不能改已有池/层/虚拟磁盘参数。

### Q5. 原始池“显示到层级到磁盘”（阻塞）

两种读法：

- A. 原始池显示到磁盘这一级；没有层；没有分区。
- B. 原始池显示层和磁盘；仍然没有分区。

除非另有说明，本计划按读法 A。Windows 存储空间的原始池没有存储层。

### Q6. 上区磁盘集合（阻塞）

`PartitionableDiskPolicy` 当前显示容量大于 0 的 RAW/GPT/MBR 操作系统磁盘，包括启动盘和系统盘。请确认上区列表：

- 可分区的启动盘/系统盘是否仍显示？
- 非原始池的物理成员不显示（已说明）？
- 可投影为操作系统磁盘的虚拟磁盘显示（已说明）？
- 没有物理/虚拟关联的“其他”操作系统磁盘是否显示？
- 网络磁盘隐藏（假定）？

### Q7. 上区未分配空间（阻塞）

当前分区条把未分配空间显示成可点击段。新的两级拓扑是磁盘 → 分区。未分配空间要不要作为磁盘的子节点出现，还是只出现在上区右侧控件里？

### Q8. SSD/HDD 以外的介质（阻塞）

SSD → 性能层、HDD → 容量层已说明。请确认：

- SCM：进性能层（与当前 finding 规则一致）还是别的？
- Unknown / Unspecified：拒绝拖放、留在池级未分配组，还是强制进某一层？

### Q9. 拖放目标（阻塞）

用户是可以拖到具体层，还是只能拖到池、再由自动规则选层？如果拖到介质不匹配的层，是拒绝，还是仍自动纠正到匹配层？

### Q10. 产品版本（阻塞）

本阶段保持 V0.45，还是在工作被接受后把产品版本设为 V0.46？在决定之前，本计划不改 `Directory.Build.props`。

### Q11. 创建默认值与执行内容（阻塞）

当前创建路径在确认后是：建池 → 建虚拟磁盘 → 建分区 → 格式化为 NTFS。以下是建议默认值，不是决定：

| 字段 | 建议默认 |
| --- | --- |
| 性能层复原 | Simple（当前单一复原默认） |
| 容量层复原 | Simple |
| 两层交织 | 64K |
| 两层大小 | 留空 = 由成员磁盘推导 |
| 文件系统 | NTFS |
| 簇大小 | 64K |
| 执行时新池为空 | 拒绝；至少一块成员磁盘 |
| 创建之后 | 仍自动建一个分区，并用表格中的文件系统和簇大小格式化 |

另请确认 64K + 64K 研究说明是否仍作为簇大小行下的辅助文字。它不是分区标题。

### Q12. 布局细节（若接受建议默认则不阻塞）

建议默认：

- 上下高度初始 1:1。允许行 `GridSplitter`；不能恢复整页一起滚。
- 每一半内拓扑 : 控件初始 2:1，与当前编辑页列比一致。允许列分割条。
- 四个窗格各自纵向滚动，避免长拓扑把表单顶走。这比“两个半区分别滚”更严，除非要求每半区共用一个滚动条。
- 两个半区没有标题，也不额外加“逻辑拓扑 / 控件组”标题。

## 3. 本阶段不得悄悄破坏的基线

- 产品仍在 V0.4 线。真实存储结构变更保持禁止。模拟是唯一编辑执行路径。
- 管理页 `TopologyProjector.Project` 仍是完整系统视图（系统、含原始池的池、层、磁盘、虚拟磁盘、分区、网络组、其他操作系统组）。本阶段只新增编辑页投影，不改管理页拓扑规则。
- 视觉复用指 `TopologyNodeControl`、`AdaptiveFlowPanel`、`WeightedPoolPanel` 以及现有 Stack / Flow / WeightedFlow。不是把管理页整棵树塞进编辑页。
- 当前编辑页上区用 `PartitionableDiskPolicy` 过滤 `OsDisks`。下区是非原始池磁贴、暂存加号磁贴、原始池磁盘 `ListView`。
- 当前 `CreateStoragePool` 把原始池成员移进新池，不建层。当前 `CreateVirtualDisk` 建一块 RAW 操作系统磁盘。当前 `MovePhysicalDisk` 拒绝启动/系统/页面文件/崩溃转储盘，也拒绝已经属于存储层的磁盘。
- 今天没有模拟 `CreateStorageTier` 路径。若 Q2/Q3/Q4 要求把磁盘和层成员写入文档，就必须补模拟能力。
- 本机系统仍只读。拓扑可以显示。除非当前文档是模拟，拖动、执行和其他变更保持禁用。
- 除非后续被批准的回答证明必须改持久化或线路，否则不改 schema 14 和 IPC protocol 4。快照里已经有 `StorageTierInfo`。

## 4. 阻塞问题回答后的建议形态

本节是映射，不是额外产品范围。

### 4.1 页面骨架

用两行各 `Height="*"` 的网格替换当前整页 `ScrollViewer` + 带标题卡片。没有半区标题。每一半是左拓扑 / 右控件。

### 4.2 上区拓扑

新的 Application 投影，例如
`TopologyProjector.ProjectPartitionWorkspace(snapshot)`：

- 按 Q6 过滤后的操作系统磁盘，竖排（`TopologyChildrenLayout.Stack`）。
- 用户看不见系统 / 池 / 层 / 网络 / 其他组包装。
- 每个磁盘的子级是按偏移或分区号排列的分区，用 Flow 横排，必要时换行。
- 虚拟磁盘显示为一个磁盘节点（可分区的操作系统磁盘或虚拟磁盘本身），不是池内物理磁盘。

通过现有 `TopologyNodeControl` 绑定这棵树。

### 4.3 下区拓扑

新的 Application 投影，例如
`TopologyProjector.ProjectPoolWorkspace(snapshot)`：

- 只含内部池：原始池在前，然后是命名池，最后是假加号节点。无网络组。
- 池行用 Flow 或 WeightedFlow，让加号在所有池右边。
- 原始池：物理磁盘作为直接子级；`includeOsChildren: false`。
- 命名池子级从上到下：带分区的虚拟磁盘、性能层、容量层，若 Q8 让某些磁盘不进两层，再跟未分配成员。
- 假加号节点：仅编辑页展示用 id，不是快照里的 `StoragePoolInfo`。点击行为按 Q3。

新池一旦可见，显示：

- 虚拟磁盘节点，在真实虚拟磁盘出现前状态为“未建立”；
- 空的性能层；
- 空的容量层。

### 4.4 拖动与自动分层

下区编辑树中的物理磁盘节点成为拖动源。管理页节点不变。放置目标是池、加号/草稿池，以及（若 Q9 允许）层。

池成员变更成功后的自动分层：

- SSD → 性能层。
- HDD → 容量层。
- SCM / Unknown 按 Q8。

若文档是权威（Q2 立即提交，或稍后执行），必须扩展 `MovePhysicalDisk`：磁盘能离开源池的层，并进入目标池的匹配层。今天这种移动会被拒绝。

启动盘、系统盘、页面文件盘、崩溃转储盘保持不可移动，与当前模拟规则一致，除非开发者以后改口。

### 4.5 下区右侧表格

两列十一行，双语名称。值是 `TextBox` / `ComboBox` / 执行按钮。选中池或草稿时填充表格。若 Q4 包含修改，草稿/加号时按钮为“创建新池”，已有池时为“执行修改”；否则只启用创建。

执行仍只走模拟、有类型、有预览。不调用真实存储空间命令。

### 4.6 上区右侧

推迟到 Q1。在得到回答前不发明第二套命令面。在此之前，现有分区操作只是已知候选，不是已批准集合。
