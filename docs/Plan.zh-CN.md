## 1. 已确认决定

这些决定约束本阶段，优先于现有编辑页布局实现。

### 1.0 引擎不变量

这些不变量说明引擎为什么这样设计。它们是规范性的：满足其余全部章节但
违反其中任一条的实现，即视为不满足本计划。

1. **结构决策只存在于单位层。** 行成组、列预算、收缩决策、行高放宽、
   最小单位宽（含复杂池兄弟的 2 单位下限）全部在整数 Wunit/Hunit 空间
   决定。它们是布局计划中与分辨率无关的不变量。
2. **每个表面一次根级布局。** 每个表面（管理页、编辑上半区、编辑下半区）
   每轮布局只在自身的根适配器处以该表面自己的宿主宽度调用引擎一次。
   嵌套面板绝不调用引擎，也绝不重新规划任何祖先或兄弟的预算。
3. **面板是机械消费者。** 面板获取 WinUI 提供的宽度（WinUI 无限宽测量时
   使用各表面自己的回退值）；在根处把节点 ViewModel 树转换为引擎输入；
   按引擎分配的槽位宽度执行 Measure/Arrange。面板绝不决定放得下几个
   子项、等分还是加权、容量比例、行打包或收缩优先级。
4. **像素只做拉伸。** 像素值只把已完成的单位计划像素化。任何以像素量出
   的值不得回流进单位层决策。
5. **布局纯度与幂等。** 只有确定性输入数据——静态快照数据和 WinUI 提供
   的宽度——可以进入布局。任何由度量子元素得出的值不得影响布局决策
   （度量重入是已知 `LayoutCycleException` 的触发条件）。相同输入产生
   相同输出；小于 1 DIP 的宽度变化不重新规划。

### 1.1 唯一拓扑布局引擎

WinPool 只有一个拓扑布局引擎：

`TopologyLayoutEngine`

管理页、编辑上半区、编辑下半区都使用该引擎完成拓扑测量、行生成、最小
宽度计算、可用宽度处理、子项宽度分配和最终布局规划。

三个区域可以提供不同的拓扑树和少量布局或呈现选项，但不得拥有独立的布局
算法。

特别地：

- 管理页保持行为与视觉基准。
- 编辑上半区是受限的磁盘/分区投影。
- 编辑下半区是受限的池投影。
- `AdaptiveFlowPanel`、`WeightedPoolPanel` 或替代面板可作为 WinUI
  measure/arrange 适配器保留，但不得实现相互竞争的布局算法。
- 等分、加权、容量分配、换行与最小宽度规则属于 `TopologyLayoutEngine`。
- 面板只消费引擎结果，只做机械的 WinUI 度量与排列。
- 不得引入第二个编辑页专用布局引擎。
- 不得在核心算法中引入页面名判断（如 `if (Manage)`、`if (EditUpper)`）。
  所需差异一律以显式布局输入或策略数据表达。

实现必须保持所需的最小闭环。不得构建通用公共布局框架。

### 1.2 管理页是参照行为

管理页拓扑在功能与视觉上与当前管理页实现保持等价。

其投影继续按当前 `TopologyProjector` 展示完整逻辑拓扑。

管理页现有规则——系统根、池、层、物理盘、虚拟盘、分区、网络与其他
分组、Stack / Flow / WeightedFlow 关系、兄弟打包、行高放宽、拓扑选择、
展开、最小节点宽——均为参照行为。

本阶段可以重构产出该结果的内部实现，但不得有意重新设计管理页拓扑。

管理页布局回归测试因此是统一引擎的兼容性参照。

## 2. 分配模型

本节记录开发者确认的最终子项宽度分配设计。它取代任何把"容量分配"读作
新的通用或默认引擎模式的理解。

### 2.1 可选，而非默认

通过分配元数据实现的"同行不同宽度"是**可选的**。条带未声明分配选项时的
默认行为是当前管理页行为，对每种布局逐位保留：

- Flow 子项保持现有等分填充；最小子对象等宽（开发者 2026-09-05 所说的
  "等宽"正是指此，与当前引擎逻辑一致）。
- WeightedFlow 行保持现有的按单位比例拉伸（`WeightedPoolPanel.AllocateRows`
  算术，不变）。
- Stack 子项不受影响。
- 默认情况下字节容量权重不影响任何东西。

引擎只在该条带同时启用了分配并声明了权重（§2.2）、且仅限编辑上半区叶级
条带（§2.5）时，才执行声明权重分配。

### 2.2 显式启用，显式权重

- 布局输入可按条带携带：显式的**容量分配启用选项**，以及逐子项的
  **声明容量权重**（§2.3）。
- 只有启用选项**与**权重同时存在时分配才激活。仅有声明权重——或存储对象
  仅有容量数据——绝不激活分配。
- 两个字段都由投影层控制。引擎不含页面名逻辑、不含分配模式枚举、不从
  容量数据自动推断。
- 管理页兼容：管理页不声明任何内容；其行渲染与今天完全一致，现有回归
  期望继续有效。

### 2.3 容量权重换算

对已启用的编辑上半区分区条带：

```text
weight_i = 子项 i 的字节数，以 double 表示
```

- 权重不做归一化、不做舍入。`double` 在 2^53 以下精确表示整数，大于
  任何真实分区尺寸，因此权重比例精确等于字节比例。
- 若权重字段最终为整数类型，允许 GCD 约分；默认选择 `double`，完全
  不需要换算。
- 分区与可见未分配区都使用其实际字节数。
- 低于配置阈值的隐藏间隙不投影、不占布局槽、不带权重。

换算是快照数据的纯函数，运行在投影层、任何布局过程之外。

### 2.4 三段式条带分配

> **确认门槛：** 开发者尚未确认本节。开发者明确确认 §2.4 之前不得开始
> TL5。下方的"你看到什么"对照表即为确认用途。

白话行为（即开发者 2026-09-05 的描述，精确化）：

1. 窄的时候，每个子项都停在相同的最小宽度（112 DIP）；行可以溢出
   视口。
2. 变宽的过程中，**所有子项一起等量增长**，保持等宽，直到每个子项达到
   舒适宽度 `t`。
3. 再多的宽度才**按容量分配**：大分区开始比小分区长得快。

对一条已启用的条带行，`n` 个可见子项、间距 `s`（6 DIP）、叶子最小宽
`m`（112 DIP）、等宽增长阈值 `t`（§2.7）、声明权重 `w_i`：

```text
W1 = n × m + s × (n − 1)     行最小宽度
W2 = n × t + s × (n − 1)     行等宽增长边界
```

**第 1 段 —— `available ≤ W1`：** `width_i = m`。不做负向调整；条带
溢出视口（§4.4）。

**第 2 段 —— `W1 < available ≤ W2`：**

```text
g = (available − W1) / n
width_i = m + g
```

**第 3 段 —— `available > W2`：**

```text
width_i = t + (available − W2) × w_i / Σw        用于子项 1 … n−1
width_n = available − s × (n − 1) − Σ_{i<n} width_i，钳制 ≥ t
```

必需性质：

- **连续性：** `W1` 处第 1→2 段一致（`g = 0`）；`W2` 处第 2→3 段一致
  （每个子项恰为 `t`）。跨过边界不产生视觉跳变。
- 行内**最后一个子项确定性地吸收舍入残差**（第 2、3 段均适用）。
- 零权重子项停在第 1–2 段的 `m` 或第 3 段的 `t`。
- 若 `Σw ≤ 0`，第 3 段改为按子项数等分。
- `t` 是输入数据（命名常量，§2.7），绝不是布局期间量出的值。

**"你看到什么"对照表**（两个分区，100 GiB 与 200 GiB；`t = 200 DIP`
指示值；`W1 = 230`、`W2 = 406`）：

| 可用宽度 | 你看到的 | 阶段 |
| --- | --- | --- |
| 200 | `[112][112]`，行溢出 | 1 —— 等宽最小 |
| 320 | `[157][157]` —— 等宽 | 2 —— 等量增长 |
| 406 | `[200][200]` —— 等宽，到达 `t` | 2 → 3 边界 |
| 563 | `[252.33][304.67]` —— 大分区开始领先 | 3 —— 容量分配 |

### 2.5 围栏

已启用的容量分配只允许出现在编辑上半区的叶级分区/未分配条带上。引擎
不含字节或容量概念。本阶段不得把容量权重泛化到池、层或任何其他节点，
不得引入第二条分配公式，也不得让"同行不同宽度"在任何地方成为默认。

### 2.6 尺寸变化行为

调整尺寸是一串相互独立的单遍计算：宽度变化 → 引擎算一次 →
`ApplyLayout` → 面板按新槽位排列。引擎是"不可变输入记录 + 一个宽度"
上的纯函数；它不碰任何 UIElement，也绝不为决策去度量子项。`ApplyLayout`
回写只使排列失效，不得写任何影响宽度的属性。小于 1 DIP 的宽度变化不
重新规划（幂等保护，§1.0 第 5 条）。段间转换连续（§2.4），拖动跨过
`W1`/`W2` 不产生跳变。

### 2.7 常量，而非魔法数字

命名常量内硬编码取值是**允许的**。魔法数字不允许：每个参与布局的宽度
阈值必须以有唯一归属的命名常量出现；布局代码中禁止内联数字字面量。

| 常量 | 归属 | 取值 |
| --- | --- | --- |
| 叶子最小宽 `m` | `TopologyLayoutEngine` | 112 DIP（不变） |
| 兄弟间距 `s` | `TopologyLayoutEngine` | 6 DIP（不变） |
| 祖先边框宽 | `TopologyLayoutEngine` | 26 DIP（不变） |
| 等宽增长阈值 `t` | `TopologyLayoutEngine` | 实施时以截图确认；指示值 200 DIP |
| 单行头阈值 | `TopologyNodeControl` 呈现层 | 实施时以截图确认 |
| 各表面回退视口宽度 | 各表面自己的状态 | 按表面命名；取代内联的 1400 |

本阶段消除的现有内联魔法数字：`1400`（面板回退与 ViewModel 默认视口）、
`320` 与 `20`（页面 `SizeChanged` 处理器）、`150`
（`EqualFillFlowLayout` / `WeightedPoolLayout` 默认参数）。各改为命名
常量或随其宿主一起消失。

命名常量是代码常量，不是用户可见设置；设置仍属范围外（§13）。

## 3. 编辑下半区拓扑

### 3.1 结构

编辑下半区拓扑在下文未列出的方面使用与管理页相同的池导向结构与布局
行为。

它只显示内部池，包括原始池。

现有的编辑工作副本、拖拽、模拟 Execute、修改与解散行为保持不变，但本
计划明确修订处除外（§3.4 加号池规则；§7 可改性护栏）。

### 3.2 原始池

原始池显示其物理盘。

原始池内的物理盘在编辑下半区拓扑中**不**显示分区。

这是仅作用于编辑下半区的投影规则，不改变管理页投影。

概念上：

```text
Primordial
├─ Physical Disk
├─ Physical Disk
└─ Physical Disk
```

而不是：

```text
Primordial
└─ Physical Disk
   └─ Partition
```

### 3.3 现有池

非原始池渲染与管理页投影相同的逻辑内容，并受本计划的编辑下半区规则
约束。开发者于 2026-09-05 确认编辑下半区投影必须与管理页对齐：

- **层卡由快照驱动。** 池显示快照中**存在且至少有一个成员盘**的层，
  排序与管理页一致。没有固定的性能/容量占位卡；没有成员盘的层不渲染
  卡片。非 SSD/SCM/HDD 的媒体类型照常渲染。
- **草稿池行为相同。** `InsertDraftPool` 继续预建 SSD/HDD（及存在 SCM
  盘时的 SCM）层记录，作为池表单的参数载体；它们不是渲染占位。性能层
  或容量层卡片只在该媒体类型的第一块盘拖入草稿池后才出现——
  `MoveDiskToPool` 已经会把盘挂到（或创建）对应层，因此无需任何模拟
  语义变更。
- **层外成员可见。** 未被任何层覆盖的池成员，以与管理页完全相同的
  DirectDiskGroup"未分配"组渲染（同一种类、同样的 `group:direct:{pool}`
  稳定标识约定、组本身不可选、盘子女可选择可拖拽）。这恢复了旧编辑
  下半区投影静默丢弃的对象。
- 现有虚拟盘表示（含"Not created"占位）与虚拟盘分区条带保持可用。

除 §3.4 与 §7 外，本计划不改变池编辑语义或模拟操作；上述对齐只改变
投影。

### 3.4 合成加号池（单草稿）

合成加号池仍是编辑下半区添加池的入口，遵循单草稿规则（开发者 2026-09-05
决定）：

- 加号池**仅在不存在的草稿池时**出现；
- 点击它创建一个草稿池，加号池**消失**；
- 任意时刻至多存在一个草稿池——不允许同时多个新建池；
- 草稿执行或放弃后，加号池重新出现。

概念上：

```text
无草稿:   Primordial | Pool A | Pool B | +
草稿中:   Primordial | Pool A | Pool B | draft: Pool C   （没有 +）
```

加号池继续只创建现有的本地草稿池工作状态，不创建真实存储。

### 3.5 布局

编辑下半区使用与管理页相同的加权池布局规则，除非上文编辑下半区规则
改变了投影子项。

不存在单独的编辑下半区打包算法。

## 4. 编辑上半区拓扑

### 4.1 只有两级

编辑上半区拓扑只包含分区管理所需的磁盘/分区工作区。

可见逻辑层级为：

```text
Disk
└─ Partition / Unallocated
```

编辑上半区拓扑不显示系统、存储池、存储层、池分组、直连盘分组、虚拟盘
分组、网络分组或其他拓扑分组容器。

为喂给统一引擎所需的任何不可见根节点仅用于布局，不构成可见第三级。

### 4.2 只显示合格磁盘

只投影能通过现有分区管理策略管理的磁盘。

继续使用现有的可分区策略，不在页面里复制资格规则。

当前产品行为保持：

- 合格的系统/启动盘可以显示；
- 现有操作限制仍然适用；
- 可分区的虚拟盘可以显示；
- 被非原始池占用的物理盘不再单独作为可分区裸盘显示；
- 网络映射驱动器不显示。

本计划不扩大允许操作的磁盘集合。

### 4.3 磁盘排列

编辑上半区所有磁盘竖向排列。

概念上：

```text
Disk 0
Disk 1
Disk 2
Disk 3
```

一块磁盘不与其他磁盘共享水平行。

统一引擎应把这表达为竖向/Stack 关系，而不是依赖页面专用的布局算法
（现有 XAML `ItemsPanel` StackPanel 由引擎 Stack 通道取代）。

### 4.4 分区排列

一块磁盘内的分区与可见未分配区按磁盘偏移排成一条水平条带。

概念上：

```text
Disk 0
[Partition 1][Unallocated][Partition 2][Partition 3]
```

一块磁盘的子项不换到第二条逻辑分区行。

不换行规则（开发者 2026-09-05 确认）：

- 条带恒为单行；
- 每个可见子项至少保持其最小宽度；
- 可用宽度不大于行最小宽 `W1` 时，子项保持最小宽度，行横向宽于视口；
  由现有拓扑滚动面处理溢出（第 1 段，§2.4）；
- 条带的目标宽度只能是输入数据；布局期间量出的任何值不得成为目标宽度。

这使磁盘图保持空间连贯，而不是把后面的分区挪到无关的第二行。

### 4.5 未分配区

未分配区的现有编辑行为保持：前导、内部、尾部间隙是独立节点；顺序跟随
磁盘偏移；已配置的分区间隙忽略阈值仍决定哪些间隙可见。

可见未分配节点以该间隙的确切大小作为容量权重参与宽度分配（§2.3）。

低于配置阈值的隐藏间隙不获得可见布局槽。

## 5. 编辑上半区条带宽度分配

本计划中所有宽度均为 WinUI 设备无关单位（DIP），不是物理像素。

分配本身在 §2.4 中规范定义。本节记录其范围与验收用例。

### 5.1 最小宽度

每个可见分区或未分配子项以拓扑叶子最小宽度起步：`112 DIP`。

本计划不改变管理页最小宽度。

### 5.2 范围

三段式分配（§2.4）只作用于编辑上半区磁盘的分区/未分配条带，且仅因这些
条带同时启用分配并声明容量权重（§2.2）。

它不取代管理页现有布局规则（§2.1），也不改变编辑下半区池权重。

### 5.3 验收用例

以下数值假设指示值 `t = 200 DIP`；以确认值重算。`m = 112`，`s = 6`。

#### 用例 A1 —— 第 1 段（宽度不足）

```text
n = 2, available = 200（< W1 = 230）
期望：两个子项均为 112 DIP；行溢出视口
```

#### 用例 A2 —— 第 2 段（等量增长）

```text
n = 2, available = 320, W1 = 230, W2 = 406
期望：两个子项均为 112 + 45 = 157 DIP（等宽）
```

#### 用例 A3 —— 第 3 段（容量分配）

```text
n = 2, 权重 100 GiB : 200 GiB, available = 563, W2 = 406
期望：A = 200 + 157 × 100/300 = 252.33 DIP
      B = 563 − 6 − 252.33   = 304.67 DIP（吸收残差）
```

#### 用例 A4 —— 连续性

`available = W2` 处，第 2 段与第 3 段公式都给每个子项 `t`。

#### 用例 B —— 三个子项含未分配（第 3 段）

```text
100 GiB 分区、50 GiB 未分配、200 GiB 分区
```

超出 `t` 的宽度按 `100 : 50 : 200` 分配；最后一个子项吸收残差。

#### 用例 C —— 隐藏间隙

低于配置阈值的隐藏未分配间隙不获得布局槽，也不获得可见容量份额。

### 5.4 确定性

任何最终舍入都是确定性的；行内最后一个子项吸收残差，使规划的行宽保持
一致（§2.4）。

## 6. 宽度自适应节点呈现

单行合并是**所有层级存储对象节点的通用能力**，不是磁盘专属功能（开发者
2026-09-05 决定）：

- 共享的 `TopologyNodeControl` 支持一种呈现模式：当节点的引擎分配宽度
  达到命名单行阈值（§2.7）时，节点的多行头部合并为一行水平线；变窄时
  回到标准呈现；
- 该能力按节点（或按层级）通过显式呈现元数据启用——每个层级可开可关；
- 切换由引擎分配的槽位宽度驱动（确定性的渲染期输入），绝不是由量出的
  文字宽度驱动；
- 阈值是命名常量（§2.7）。

本阶段**仅对编辑上半区的磁盘层级**启用该能力。管理页与编辑下半区的所有
节点保持标准呈现。

概念上（宽的编辑上半区磁盘）：

```text
Disk 0    Samsung SSD ...    GPT    1.82 TiB
```

要求：

- 保留识别对象所需的信息；
- 保留无障碍名称；
- 保留选择与交互行为；
- 仍是共享 `TopologyNodeControl`；不得创建第二套控件树。

单行排布细节与阈值取值实施时以截图确认，与 `t` 一同确认。

## 7. 编辑下半区结构可改性指示与护栏

开发者 2026-09-05 决定。本节全部规则只作用于编辑下半区的模拟工作流。

### 7.1 指示

编辑下半区的存储对象卡片右上角显示一个图标，两种状态：**支持存储结构
修改** / **不支持**。图标带无障碍名称，由共享 `TopologyNodeControl`
呈现。

本阶段为编辑下半区显示的每一块物理盘定义该状态——原始池成员与存储池
成员（层卡与未分配组内的盘）一视同仁——以及存储池。其他对象种类（层、
虚拟盘、分组）不显示图标。

### 7.2 状态规则

- 物理盘（无论属于原始池还是存储池）：无分区，或其全部分区内已无数据 →
  **支持**；否则**不支持**。该规则只看盘自身内容，对原始池成员和存储池
  内的盘同等适用。
- 存储池（非原始）：其全部虚拟磁盘无分区，或分区内已无数据 →
  **支持**；否则**不支持**。
- 数据存在性来自只读清单快照。无法判定时按**不支持**处理（保守默认）。

### 7.3 行为

- **不支持的磁盘：** 仍可在工作副本中调整位置（在池间拖拽）；**禁止
  Execute**。
- **不支持的池：** 物理盘**可以拖入**，但**不可以拖出**；拖出被拒绝。
  Execute 同样被禁止。
- **被禁止的 Execute：** 涉及对象存在不支持状态时点击 Execute，弹出
  对话框，逐个列出问题对象、其问题（有分区 / 分区内有数据）以及应该
  怎么做（例如：先备份并清空卷，再重试）。WinPool 在此对话框中不执行
  任何清除，也不提供破坏性操作。

### 7.4 范围

指示与护栏只是模拟工作流的呈现与校验。不授权真实变更、真实数据清除或
任何新存储操作（§13、§14）。

## 8. 实施映射

### 8.1 应用层布局引擎

主要归属：

`src/WinPool.Application/TopologyLayoutEngine.cs`

重构现有引擎，使其结果足以让面板完成最终排列，而无需再发明宽度分配
算法。

引擎拥有：

- 自然子树测量；
- 叶子最小宽；
- 祖先边框宽；
- 兄弟间距；
- Stack 布局；
- Flow 布局；
- WeightedFlow 布局；
- 兄弟行成组；
- 收缩决策；
- 行高放宽；
- 最终子项宽度指派：默认行为逐位保留（§2.1），已启用条带实施三段式
  分配（§2.4）；
- 编辑上半区所需的不换行水平条带行为（§4.4）；
- 命名常量（§2.7）。

现有管理页计算保持基准；单位规划阶段不做重新设计，默认行的输出必须与

- 容量分配启用选项与权重（§2.2–§2.3）；
- 子行换行与否。

不得把页面名编入 `TopologyLayoutEngine`。

### 8.2 布局结果

引擎结果必须携带最终行成组与每个子项的最终分配宽度。

"最终分配宽度"指从该表面唯一一次根级布局结果像素化出的槽位宽度
（§1.0 第 2 条），**不是**各嵌套面板独立算出的宽度。

不得把最终加权或容量拉伸计算留在某个具体的 WinUI 面板里。

最终结果可以在现有 `TopologyLayoutResult` 上扩展显式行槽位宽度信息或
等价表示。

确切数据类型是实现选择；所有权边界不是。

### 8.3 WinUI 拓扑面板

当前相关控件包括：

- `AdaptiveFlowPanel`
- `WeightedPoolPanel`
- `TopologyNodeControl`

本阶段之后，任何保留的布局面板都是围绕 `TopologyLayoutEngine` 的薄
适配器。

每个表面有一个根适配器，以该表面的宿主宽度调用引擎一次。根适配器可以：

- 获取 WinUI 实际可用宽度；
- 在根处把节点 ViewModel 树转换为引擎输入；
- 调用引擎；
- 按引擎分配的宽度度量子项；
- 按引擎行与槽位排列子项。

根适配器之下的嵌套面板只消费已存储的槽位。

它们不得：

- 调用 `TopologyLayoutEngine`；
- 爬可视树寻找宿主并重新规划；
- 决定放得下几个子项；
- 选择等分还是加权；
- 选择容量比例；
- 选择行打包策略；
- 选择收缩优先级；
- 包含魔法数字（§2.7）。

若单个通用拓扑面板能干净地同时替代 `AdaptiveFlowPanel` 与
`WeightedPoolPanel`，允许该替代。

本计划授权移除的确切过时候选是：

- `src/WinPool.App/Controls/AdaptiveFlowPanel.cs`
- `src/WinPool.App/Controls/WeightedPoolPanel.cs`

仅当以下条件全部满足后才可删除：

1. 通用替代已存在；
2. 全部代码引用已迁移；
3. 全部 XAML 使用点（含 `MainPage.xaml` 与 `EditPage.xaml`）不再引用
   被移除的面板类型；
4. 管理页回归测试通过；
5. 编辑上半区与下半区定向布局测试通过。

仅为架构整洁而删除不是必需的。若保留薄适配器是更小的闭环变更，可以

宽度。

优先使用 `MeasureOverride` / `ArrangeOverride` 期间 WinUI 布局面板收
到的实际宽度。

在 WinUI 无限宽测量需要处可保留回退视口状态，但每个表面必须使用自己的
宿主宽度与自己的命名回退常量（§2.7）；内联的 `1400` 消失。

因此编辑上半区、下半区与管理页不得竞写同一个共享 `TopologyViewportWidth`；
移除该共享状态、替换为每表面状态，并配套自动视口隔离回归测试。

## 10. 必需的定向测试

这是普通功能/重构工作，不是自动全量质量门。

实施期间运行与改动直接相关的最小自动测试。

### 10.1 统一布局引擎

扩展现有 `TopologyLayoutEngineTests`。

必需用例包括：

- 现有管理页参照用例继续产出等价的行打包；
- 现有管理页加权兄弟保持其现有宽度行为（默认行与今天的面板算术逐位
  一致）；
- 未启用分配选项的行**不**产生任何基于权重的宽度差异，即使存在容量
  数据（§2.2）；
- Stack 子项保持竖向；
- Flow 行为仍符合现有管理页期望（等分填充）；
- WeightedFlow 行为仍符合当前管理页期望；
- 不换行水平条带不产生第二行；
- 可用宽度不大于 `W1` 时第 1 段保持最小宽度、不做负向调整；
- 第 2 段所有子项以相同绝对增量增长；
- 第 3 段超出 `t` 的宽度按声明权重分配，最后一个子项吸收舍入残差；
- 连续性：`available = W1` 与 `available = W2` 处相邻两段结果一致；
- 零权重子项停在第 1–2 段的 `m` 或第 3 段的 `t`；总权重非正时第 3 段
  回退等分；
- 进入或离开编辑页、调整任一编辑半区宽度，不改变管理页布局输入
  （共享视口隔离）。

### 10.2 分配验收用例

§5.3 的确定性用例（A1、A2、A3、A4、B、C），以确认后的 `t` 值重算。

### 10.3 编辑上半区投影

扩展 `EditWorkspaceTests`，证明：

- 只显示可分区磁盘；
- 非原始池的物理成员被排除在可分区裸盘列表之外；
- 合格虚拟盘保持可用；
- 网络驱动器不存在；
- 磁盘排序保持确定；
- 分区与间隙保持偏移顺序；
- 前导、内部、尾部可见间隙保持相互独立；
- 上半区拓扑只有可见的磁盘与分区/未分配两级；
- 条带携带分配启用与字节权重。

### 10.4 编辑下半区投影

测试必须证明：

- 原始池存在；
- 原始池物理盘在编辑下半区没有分区子项；
- 非原始池结构保持可用；
- 加号池：无草稿时恰好出现一次；有草稿时不存在；执行或放弃后重新出现；
  无法创建第二个草稿；
- 层卡跟随快照：有成员的层渲染；无成员的层不渲染卡片；非标准媒体类型
  照常渲染；
- 草稿池在拖入磁盘前不显示层卡；拖入后恰好显示获得成员的那些层；
- 未被层覆盖的池成员出现在未分配组中，可选择、可拖拽，并能拖到其他池；
- 可改性状态：无分区的盘 → 支持；分区全空的盘 → 支持；有数据的盘 →
  不支持——原始池的盘与存储池成员盘同等适用；虚拟盘无分区或无数据的池 →
  支持；否则不支持；数据存在性
  无法判定 → 不支持。

### 10.5 护栏

测试必须证明：

- 不支持的池拒绝成员拖出、接受拖入；
- 不支持的磁盘保持可拖拽；
- 涉及不支持对象的 Execute 被拒绝并产生说明对话框数据（对象、问题、
  建议做法）；
- 任何护栏路径都不执行真实存储变更或数据清除。

### 10.6 管理页非回归

现有管理页拓扑与布局测试必须通过，不得为配合重构而改写其期望行为。

管理页期望失败一律视为回归，除非开发者明确改变需求。

### 10.7 呈现结构

添加切实可行的最小架构/呈现测试：

- 编辑上半区在分配宽度达到命名阈值时选择单行呈现、不足时选择标准
  呈现；
- 本阶段自适应能力对编辑上半区磁盘以外的每个层级都是关闭的；
- 管理页与编辑下半区保持标准呈现模式；
- 所有层级仍使用共享 `TopologyNodeControl`；
- 编辑下半区磁盘与池节点暴露可改性图标状态。

不得以自动结构测试宣称视觉外观通过。

## 11. 实施后的人工验证

原生视觉证据与自动测试分离。

本地模拟-only 编辑点击走查应检查：

1. 进入编辑前后管理页拓扑打包等价。
2. 调整管理页尺寸，确认现有拓扑行为不变。
3. 调整编辑上半区尺寸，确认编辑下半区/管理页布局不因共享视口变量而
   改变。
4. 编辑上半区只显示合格磁盘。
5. 编辑上半区磁盘竖向堆叠。
6. 每块磁盘的分区图保持单条水平条带。
7. 把编辑上半区从窄拖宽，依次看到三个阶段：全部子项等宽最小、共同
   增长、容量比例差异，且跨越阶段边界无视觉跳变。
8. 未分配空间在第 3 段按比例参与。
9. 大量分区导致水平溢出而不是第二条分区行。
10. 编辑上半区磁盘头在足够宽时合并为一行，变窄时回到标准呈现；其他
    层级不合并。
11. 编辑下半区原始盘不暴露分区。
12. 编辑下半区加号池：点击后出现一个草稿、加号消失；执行或放弃后加号
    回来；无法同时建第二个草稿。
13. 编辑下半区可改性图标与 §7.2 一致（原始池有数据的盘；原始池无分区
    的盘；池内层卡或未分配组中的盘各备有无数据两种情形；虚拟盘有数据
    的池；虚拟盘为空的池）。
14. 不支持的磁盘：拖拽仍可用；Execute 被拦截，对话框点名磁盘、问题和
    建议做法。
15. 不支持的池：成员盘拖不出、拖得进；Execute 被拦截并弹对话框。
16. 对支持的对象，现有编辑拖拽、草稿、Execute、修改、解散模拟行为仍
    可用。
17. 连续拖动编辑分栏条不崩溃、无布局闪烁循环，释放后 CPU 稳定空闲
    （§2.6）。
18. 记录确认单行头、头部阈值与 `t` 的截图（TL8）。
19. 成员未被层完整覆盖的池，在编辑下半区显示承载这些盘的未分配组，与
    管理页一致，且这些盘可以拖出。
20. 草稿池与新建池只在对应媒体类型的盘拖入后才出现性能/容量层卡；
    任何地方都不出现空的"0 个物理盘"层卡。

真人/实机运行实际执行之前，此证据为 `unverified`。

除非开发者明确要求正式测试，本计划的普通实施不要求全量 Quality 门。

## 12. 执行与验证纪律

  下一项。实机验证指：启动应用、打开受影响页面、确认进程存活、确认

  优先插桩收集真实数据而不是猜；先报告根因、等批准再修。
- **脚本改代码**必须先确认编译成功，再用于验证的任何启动。

## 15. 验收门

仅当以下全部成立时实施才算完成：

- 三个拓扑区域均以 `TopologyLayoutEngine` 为唯一布局算法权威；
- 每个表面恰好运行一次根级引擎布局；没有任何嵌套面板调用引擎或重新

- 未启用分配选项的行渲染与今天完全一致；默认情况下任何地方都不出现
  基于权重的宽度差异；
