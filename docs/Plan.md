## 1. 已确认决定与完成范围

用户于 2026-09-27 确认以下四项，执行 Agent 不得自行更换：

1. **先完成单盘可验证的真实操作。** 多盘冗余、混合介质分层等列入后续阶段，真实入口保持禁用。本阶段不再要求把两个编辑页的全部模拟功能都变为已验证真实功能。
2. **显式删除重建纳入本阶段。** 每次列出受影响对象和数据损失，另行确认；不能把普通参数更新失败自动转换为删除重建。无成员池在真实模式只保留为草稿，加入合格成员后才能创建真实池。
3. **真实批量操作逐步执行。** 中途失败停止后续步骤，保留已经发生的结果并重新采集对账；修复、剩余步骤和重试另建计划并确认，不承诺整批回滚。
4. **首轮参数限于第 4.3 节的组合。** 数据分区格式化簇和单盘 VD 交错为 64 KiB；EFI/恢复分区簇为 4 KiB。其它组合保留模拟，真实写入暂不开放。

交付目标：在现有存储结构编辑页、磁盘分区编辑页接通第 4 节列入的本机真实操作，完成受控 Agent 执行、失败恢复、实机结果核对；模拟编辑继续工作。读取、草稿、预览、提交、执行和已验证成功分别表示。

| 分类 | 收口条件 |
| --- | --- |
| A：必做主路径 | 第 4 节 A 类全部实现并通过自动验证；第 10 节对应实机用例全部通过，否则阶段未完成 |
| C：现场条件分支 | 按第 4 节条件判定；满足条件须完成对应实测，不满足则保留禁用、记录能力证据及原因。不能把缺时间、实现失败算作不支持 |

A 类被设备、系统或提供程序阻断时，不得自行改为 C/D 或宣布完成；报告具体阻断并请用户调整范围。C 类支持性不明时保持 `unverified`，先补证据，不能猜测放行。

## 2. 授权、机器与文件边界

### 2.1 开发验证环境

- 机器限定为 `DESKTOP-BLE6H18`。
- 仅 `WDC WD40EZAZ-00SF3B0` 可作为真实修改的候选物理盘；每次仍须核对唯一身份。型号不能单独作为命令目标。
- `Samsung SSD 980 PRO 1TB`、`Samsung SSD 980 1TB` 禁止成为 WinPool 存储修改目标。涉及任一保护盘的池、层、VD、OS 磁盘、分区、卷及跨盘关联也禁止修改。
- 其它磁盘不因“空闲”“可入池”或“测试需要”自动加入许可范围。找不到 WDC、出现多个同型号对象、身份或关联不能唯一解析时停止设备写入。
- WDC 内容可在具体操作获准后清理；不表示已完成备份，也不允许执行 Agent 自选清盘、挂载或恢复命令。
- 机器名称和型号仅属于开发验收约束，不写入软件源码、产品通用规则或发布设备白名单。更多物理机留到后续阶段。

### 2.2 授权层次

| 授权 | 有效范围 | 不能替代 |
| --- | --- | --- |
| 后续“执行本 Plan”指令 | 代码、直接相关自动验证、文档及本地提交 | 准确真实操作及目标的开发者授权 |

| 产品内当次预览确认 | 当前会话、Agent 冻结的一个具体计划 | UAC、真实模式开关、旧确认或程序重启后的授权 |

遵守 [AGENTS](../AGENTS.md)：“开发 Agent 每次实际创建、删除、初始化、格式化、调整、修复真实存储对象前，必须取得该操作和准确目标的明确授权。”一次询问可逐项列出一个具体计划的全部子操作，由用户明确批准这些子操作；不得只问“是否可以测试这块盘”。新对象尚无 Windows ID 时，授权绑定创建步骤、精确父对象和参数；创建后用返回身份和实时关联定位，不能改用名称搜索。

实机授权请求固定包含：机器绑定；物理盘型号、序列号、UniqueId 及当前定位；完整关联对象；操作编号和顺序；参数和预计末态；不可逆影响；计划摘要/哈希；证据位置。缺项先补齐。未获答复不执行对应写入。

### 2.3 运行与证据不得依赖待破坏对象

实机前解析 App/Agent 运行目录、当前数据根、仓库、证据目录所在卷及底层物理盘。若清盘、删除、格式化、脱机或池操作会影响这些路径、Windows 系统、分页/转储或当前启动链，停止并报告具体路径与关联。不能自行搬迁整个仓库、运行树或数据根来绕过；位置调整按用户决定完成后重新预检。

文件处置继续遵守 AGENTS：文档归档用 `docs/Archive`，可清理生成物移至项目根 `Rubbish`，不直接删除文件，不清理既有测试证据。获准的磁盘删除/格式化本身不通过“移到 Rubbish”实现，也不产生可恢复数据承诺。

## 4. 操作矩阵与真实含义

### 4.1 磁盘分区页

| 编号/类 | 现有动作 | 固定真实行为与边界 | 成功后必须核对 |
| --- | --- | --- | --- |
| A01 | 联机/脱机 | 精确 OS 磁盘的 `Set-Disk`；脱机拒绝 Boot/System/PageFile/CrashDump 及运行依赖盘；脱机盘其它修改禁用，上线保留入口；不顺带改只读属性 | 同一硬件身份、在线状态、无额外结构变化 |
| A02 | RAW 初始化 GPT | 确定 RAW、无有效分区的目标执行 `Initialize-Disk`，不先 `Clear-Disk`；可选 MSR 为独立步骤，1 MiB 起点、16 MiB 长度 | GPT、身份映射、可用区域；勾 MSR 时类型/偏移/长度正确 |
| A03 | 新建 BasicData | 在线 GPT 的指定空隙，明确 Offset/Size、正整数 MiB，保留 GPT 首尾保留区；格式化、FS/簇/标签/盘符各自进入计划 | GUID、几何、关联卷；不格式化时可为 RAW 或尚无卷对象，不能要求一定出现 RAW 卷，也不能自动格式化 |
| A04 | 新建 EFI/MSR/Recovery | 固定 GPT GUID；EFI 只 FAT32，Recovery 只 NTFS，MSR 无文件系统/盘符；非数据分区不自动分配盘符 | 类型/几何/选定文件系统；不宣称已安装引导器、注册 WinRE 或形成启动系统 |
| A05 | 删除分区 | 目标自身非 Boot/System，且无本操作保护角色/运行依赖；不因同盘其它分区角色无区别套用全盘禁令；预览卷和数据损失 | 指定分区/附属卷消失，相邻分区身份/几何不变 |
| A06 | NTFS 格式化 | 仅普通 Primary/BasicData、非 Boot/System；快速/完整互斥，默认快速；不强制卸载、解锁 BitLocker 或自动换文件系统 | FS、实际簇、标签及关联；记录方式和数据损失 |
| A07 | exFAT 格式化 | 同 A06 资格；使用已验证参数，不回退 NTFS | 同 A06；原文件系统替换结果 |
| C01 | ReFS 格式化 | OS/SKU/提供程序明确支持且 WDC 获准实测后启用；否则禁用并说明原因；保留研究风险提示 | 同 A06，不能从枚举/命令存在推断支持 |
| A08 | 盘符设置/更换/清空 | 重核分区/卷关联及本地卷、网络映射占用；只改选定盘符路径，不删其它挂载路径，不执行全机 automount | 新旧盘符、关联卷和保留挂载路径 |
| A09 | 卷标 Enter 改名 | 精确关联卷的 `Set-Volume`；独立即时计划；失焦不提交，非法值按 FS 规则验证 | 原身份保持、标签正确，结构草稿不回滚名称 |
| A10 | 普通 NTFS/RAW 数据分区扩展/压缩 | 对精确目标查询 `Get-PartitionSupportedSize`，取实际 SizeMin/SizeMax 与几何交集；目标总 bytes 按 1 MiB；执行前重查。启动/系统卷真实扩缩本阶段不启用 | 起点不变、实际分区/卷容量、相邻分区及原测试文件哈希 |
| C02 | ReFS 扩展 | C01 已验证且提供程序对当前卷返回可用范围；ReFS 压缩、exFAT 扩缩本阶段不开放 | 真实容量变化及内容保留 |
| C03 | MBR 清盘转 GPT | WDC 原有合法 MBR 测试状态时纳入；明示清除数据后初始化，不宣传无损；不调用 MBR2GPT 或为造夹具新增 MBR 创建入口 | 原分区按批准清除、GPT及指定后续结构；无既有夹具则禁用/未验证 |

- 四类 GPT GUID 沿用当前 `SimulationCommandPreview.PartitionTypeId` 对应定义并核对官方参数，不开放自定义 GUID。EFI/Recovery 不引入未计划的属性修改、引导修复或 WinRE 配置。
- 完整格式化实际写入目标卷，显示耗时和不可逆影响；测试用小分区，不对整个 4 TB 盘擅自做全盘格式化/擦除。
- 格式化未填写新卷标时，Windows `Format-Volume` 的示例结果为空卷标；真实预览与后置核验均以空卷标为预期，不描述为“保留原卷标”。
- BitLocker 锁定/加密状态不明、动态盘、集群/远程对象、未覆盖提供程序明确拒绝；解锁、解密、强制卸载、改只读、自动修复不作为隐含前置操作。
- 已有分区不为匹配新建网格重新对齐。原始磁盘容量不等于 GPT 可用末端，须核对扇区保留区和真实可用范围。

| C05 | 已有 Simple/Fixed VD 或层 MAX 扩展 | 只在取得适用于该已有对象、布局及 provider 的可靠扩展上限/粒度时启用；VD 与层分别判定。不把新建上限当扩展上限，不改创建参数，不隐式扩分区 | 对象 ID 保持、VD/层/OS 磁盘容量正确、未声明的分区保持原状 |
| D01 | 多盘成员增减/跨池移动 | 禁用；单盘入新池由 A11 覆盖，整池释放由 A15 覆盖，不宣称通用迁移/移除成员已支持 | 回归证明无写副作用 |
| D02 | Mirror/Parity、多介质/SCM 分层 | 禁用真实提交，保留模拟和只读展示 | 同上 |
| D03 | 热备/退役/层成员驱逐 | 单盘无条件验证；不得改 MediaType/Usage/显示关系冒充完成 | 同上 |
| D04 | 已有多 VD 池修改 | 本阶段只读，不归一化、合并或删去额外 VD 来凑条件 | 真实拒绝，不改变已有模拟规则 |
| D05 | 其它未列动作 | 优化仍属模拟 no-op，不接真正优化；Repair、RawDeviceWrite、远程、VHD/VHDX、动态盘、新建 MBR、Thin、第二块 VD、自定义命令均拒绝 | 未知 Intent/参数不落入通用执行 |

已有层事实不是 C04 支持证据。不支持单层创建时 A12 走明确的非分层 Simple/Fixed 路径；HDD 显示分组不报告为真实层。已有层不支持本阶段原地改参时可提供 A16；不把“当前版本未开放”写成“Windows 永远不支持”。

C05 的特别条件：`Get-VirtualDiskSupportedSize` 文档描述的是池中新建 VD 的尺寸，不能直接作为已有 VD 的最大总容量，也不能未经证明用“当前容量 + 新建最大值”相加。P0/P3 必须记录用于扩展上限的具体 API、适用条件及计算依据；没有可靠依据就保留禁用/未验证并列后续，不写试探性 Resize 循环。现有层的扩展范围同样区分模板新建容量和已有层实例能力。

### 4.3 本阶段写入参数组合

本节参数范围已由用户确认。首次交付按下表开放创建/格式化参数；其它既有模拟选项继续保留，真实模式明确显示“本阶段未验证”。这是阶段交付范围，不宣称 Windows 不支持其它值。容量是经过实时范围与粒度检查的变量，不限于验收的几个容量点；身份、边界和整数溢出由自动测试覆盖。

| 用途 | 已确认的首轮参数 |
| --- | --- |
| 新建 Simple/Fixed VD | 1 列，Interleave 65536 bytes；不开放其它交错或冗余组合 |
| 普通 BasicData 格式化 | NTFS / exFAT，簇 65536 bytes，快速/完整分别实测 |
| 条件 ReFS 格式化 | 簇 65536 bytes，先仅快速，须 C01 通过；完整方式留后续 |
| 创建 EFI / Recovery | 分别 FAT32 / NTFS，簇 4096 bytes，快速；不开放现有此类分区的格式化 |
| 不格式化 BasicData / MSR | 无 Format 步骤，不发送 FS/簇/标签等无效格式化参数 |

已有真实对象的其它参数仍如实采集显示，不自动改为上述值。A10 对已有普通数据分区采用真实 supported-size，不为匹配新建默认值重新格式化。若用户要求扩大真实参数组合，先将准确组合及验收用例加入 Plan，不能由执行 Agent 只因控件原来可选而放行。

## 5. 固定交互与删除重建

### 5.1 交互流程

1. 保留本机/模拟选择和真实编辑开关；普通启动开关关闭，同意不持久化，提权沿用 App + Agent 整套交接。
2. 本机选择、真实模式、管理员 Agent、操作能力、可靠目标全部满足才可提交。模拟系统即使真实开关打开，仍只能模拟；不因模式切换把草稿发往另一系统。
3. 结构页保留净差异面板与一次应用；分区页逐动作及时提交。已有名称 Enter 独立提交，真实改名也须确认本次准确目标/新值，不参与结构撤销。
4. App 送意图，Agent 准备并返回不可变计划、步骤、目标、影响、后置条件与拒绝原因；UI 用返回计划显示最终确认，不重拼另一份计划。
5. 确认显示目标链/关键身份、参数、每步动作、数据损失、中途失败可能留下的结果；取消不执行、确认不默认选中。内部协议字段留在详情，不堆进普通说明。
6. 执行中禁用所有真实修改入口，允许查看/查询当前操作；切系统、关窗口不能改变已接受目标；App 退出后 Agent 保留执行与查询能力。
7. 分别显示成功并已核对、未执行/拒绝、失败、部分完成、结果待核对；提交回执、退出码 0、通知消失不等于成功。

480 DIP 下预览、损失说明、确认/取消、状态及剩余步骤均可达，中英含义一致。复用对话框/通知服务，不新增通用操作中心或改造开发页为历史审计工作区。

为落实 A03/A10，在 BasicData 新建的文件系统选择补一个最小的“不格式化”选项（当前控件尚无此选项，模型已有对应语义）；选择后禁用簇/标签/格式化方式等不适用输入，计划不含 Format-Volume。保留格式化 NTFS 的原默认。EFI/Recovery/MSR 按固定类型规则处理，不用此选项绕过。RAW 扩缩与 NTFS 扩缩分别验收，不用只创建/删除 RAW 代替扩缩证据。

### 5.2 显式删除重建

- 原地支持动作走普通操作；本阶段不能原地修改的参数明确提供“删除并重建”，不继续标作普通保存。
- 选择重建后 Agent 新建包含全部删除和创建的计划，列池/层/VD/OS 磁盘/分区/卷/盘符及损失；旧普通更新授权无效，重建单独确认。
- 删除前尽可能只读验证新布局/容量；删除后创建仍可能失败，不能承诺原子替换。
- 只操作列明对象；其它成员、多 VD、不明关联/角色或不支持结构时拒绝；不删整个上级池来规避子对象限制。
- 失败保留现场，不自动重建旧结构、回滚或借“恢复”再删除。撤销不能恢复已格式化/清盘的数据。
- RAW 初始化与清盘分开；`ClearDisk` 仅作为已确认转换/重建/测试准备的精确子步骤，不提供任意清盘命令框或按盘号批处理。`RemoveOEM` 默认不用；确需移除的恢复/OEM 分区必须逐项列入具体计划并获准。

## 6. 类型化计划、实时校验与适配器

### 6.1 模块职责与实现方向

- Application 管意图、共用规则和展示契约；Execution 管不可变计划、策略、授权和状态；Infrastructure.Windows 管能力查询、精确定位及 Windows 适配；Agent 协调和持久化。App 不直接调用写命令或写执行表。
- 在现有项目内实现，不新增服务、DSL、插件体系、远程执行器或第二套完整对象模型。可按职责增加小文件/接口。模拟 DTO 可在 UI 边界转换，但不能默认当作获准真实请求。
- 固定后端采用 Windows 自带 Windows PowerShell 5.1 的 Storage 模块及封闭步骤，命令模板内嵌 Infrastructure.Windows，由 Agent 调用。名称、标签、ID 通过数据序列化传入，严禁拼成代码、`Invoke-Expression` 或接受任意脚本。写适配器与只读采集的策略及取消机制分离。
- 每步有确定操作种类、强类型参数、适配器版本。若复用既有计划字典，也须先转为封闭 DTO，拒绝未知/重复/多余参数；不把任意字典直接 splatting 给命令。
- 创建沿独立步骤调用，不能以 `New-Volume` 等组合命令隐藏建 VD、初始化、建分区及格式化的副作用。固定适配器的错误输出按结构化结果解析，不按本地化成功文字或输出行数判断。
- 仅本机 Microsoft Storage Spaces/基本磁盘路径；不接受远程 CimSession、机器名、任意可执行程序路径或其它 provider 的近似回退。

### 6.2 计划与身份

计划至少包含：Agent 分配的 `OperationId`、计划格式/适配器版本、Agent 生成的 `PlanHash`、系统/机器绑定、发起会话身份、实时事实版本、受影响目标指纹、规范化意图/参数、有序步骤/依赖、各步前置/后置条件、破坏性影响、支持证据、授权截止时间。CorrelationId 只作传输追踪，不代替 OperationId。

目标指纹包含适用的硬件唯一标识/序列信息、提供程序身份、父子/成员集合、分区 GUID/几何、卷身份、安全角色。DiskNumber/PartitionNumber 只能在实时精确解析后作调用参数，每步复核，不能独立持久定位。型号、名称、盘符、数组顺序都不是主身份。

哈希覆盖真正执行的参数、顺序、依赖、目标和影响，不只哈希显示文字。新对象以步骤输出引用，绑定返回 ID 并复采关联；重建产生新 GUID 是预期变化，显式记录旧→新关联，不要求新旧 GUID 相同，也不放宽物理盘身份。

### 6.3 实时前置条件与容量

1. 准备从 Windows 取得当前相关事实，不能取 SQLite 历史、UI 草稿或上一次报告充当实时依据。`AgentInventoryCoordinator` 的展示合并会保留失败来源的旧值；执行预检必须使用本次成功读取的原始事实与明确读取状态，不能使用合并后的旧成功字段填补安全条件。
2. Agent 取得唯一真实修改门后重新采集，每步调用前重核目标/角色/能力/条件。固定锁序为修改门→采集协调器内部采集门→短数据库事务；执行内复采不能再等待自己持有的修改门。自动/手动展示采集由同一协调器排到步骤核对边界，长操作中返回忙/延后，不作为新授权基线；状态查询不等采集门。不能把变更中的快照发布为已验证终态。WinPool 的锁不阻止外部工具，发现外部改变立即停。
3. 指纹比较相关身份、拓扑和安全字段；采集时间、性能计数、无关硬件变化不使确认永远失效。容量/范围执行前重查；前步计划内变化用已验证结果推进基线，不能误判为外部冲突。
4. 修改池/VD/卷前遍历全部底层成员及上级关联；未知成员、保护盘或范围扩大均拒绝。显示假池/假层、导入模拟来源不能作真实目标。
5. 分区范围用 Windows 能力与可靠几何；新建 VD/层与已有对象扩展采用各自适用的能力证据，后者按 C05，不用模拟 4 GiB 取整、1% 余量、成员合计或历史示例替代。
6. `UseMaximum` 意图准备时解析确定 bytes 并进入预览/哈希；执行时范围变化导致参数不同就重新准备确认，不静默缩小/增大。允许的提供程序容量偏差必须在计划中事先定义，否则视为后置不符。
7. 分别反馈 Windows 不支持、产品本阶段禁用、事实不足；不改模拟事实、丢未知对象或自动改参数来修正真实设备。

### 6.4 策略与授权

- Agent 自行核对管理员令牌、机器、当前会话模式和 IPC 对端，不信请求中的管理员/已确认/环境标志。
- 真实模式由已验证 App 进程显式请求进入/退出当前 Agent 会话，Agent 只保存内存态，同时绑定经 OS 核实的 PID/启动时间/映像身份和协议 ProcessInstanceId、AgentSessionId、产品会话；客户端声明的实例 ID 不能替代 OS 证据。App 退出/换代、用户关闭真实模式、Agent 重启后禁止接受新写入；已持久接受计划按第 7 节处理。25/30 秒正常管道更新或同一 App 短暂重连不等于退出真实模式，重连必须重新验证同一进程实例；模式本身仍不授权任何具体操作。
- 保留 SID、进程实例、路径、实际令牌完整性、严格版本、4 MiB 帧限制和 25/30 秒传输边界。真实功能增加明确本机会话能力，不能把整机标成 `UserProvidedDisposableMachine`，也不能借 Simulation/Replay 绕过。
- 增补普通本机真实执行环境语义，同时保留 `ProtectedDevelopmentMachine` 的拒绝含义；不简单删旧保护测试。开发设备限制由本计划及实机授权落实，不硬编码机器名。
- 全部真实写入至少 R4；清盘、移除池及破坏性重建维持 R5。R5 仅放行本阶段封闭且获准步骤；Repair/RawDeviceWrite 等仍拒绝，不能整体开放 R5 或降低风险。
- 保留既有 **2 分钟一次性授权**期限，绑定计划、会话、机器、目标指纹，由 Agent 签发和消费；确认须对应当前会话的已准备计划/哈希，不能只接受 `userConfirmed=true`。令牌不持久化；重启、模式撤销、计划改变或过期后，未开始计划重新确认。
- 已存在同 OperationId/同哈希的已接受请求先返回持久状态，不重新消费令牌或因该操作自己的结果改变而拒绝查询；同 ID 异哈希拒绝。新接受顺序固定为：持有修改门重验→消费内存一次性令牌→事务写入 Accepted/步骤初态/授权摘要和事件→允许 Windows 调用。消费后落库失败证明尚未写盘，返回需重新确认，不能复用令牌；落库后回执丢失只查询原 ID。已接受长操作不因 2 分钟到期中断，新增/重试/修复需新计划。

## 7. 状态、持久化与失败恢复

### 7.1 状态含义

实现可沿用现有枚举名称，但 IPC、数据库、UI 必须一致表达下表。

| 状态 | 判断依据 | 下一步 |
| --- | --- | --- |
| 已准备/等待确认 | 已生成计划，无 Windows 副作用 | 确认、取消或重新准备 |
| 已接受/执行中 | 授权和持久化完成，步骤推进中 | 查询 OperationId，禁止重复启动 |
| 已成功并验证 | 步骤及最终复采通过，结果落库 | 显示真实新事实，结束 |
| 已拒绝/取消且未执行 | 证明没有步骤进入 Windows 调用 | 按原因重新准备 |
| 失败且无已完成步骤 | 已证明失败及无成功步骤；不能只靠异常判断没写入 | 记录事实，不明确则转待核对 |
| 部分完成 | 部分步骤已成功，后续失败/停止且影响已查明 | 列完成/失败/未执行步骤，另建恢复计划 |
| 结果待核对 | 调用可能发生，副作用或作业状态不明 | 阻止新的真实写入，只读查询/采集/人工核对 |

步骤至少表达：未开始、准备调用、调用已发出、等待提供程序、验证中、已验证、失败、结果未知、因前步停止而未执行。继续用 `ApplicationStatus.OutcomeUnknown` 表示不确定结果，不能被普通失败覆盖。

### 7.2 持久化、防重复及恢复

1. 准备阶段在 Agent 写租约下持久化不可变计划/参数/影响及 Prepared 状态，此时无有效执行授权。确认启动时按 6.4 消费令牌，再在短事务中写授权摘要、Accepted、执行步骤初态及事件，提交后才能调用 Windows。同 OperationId 不对应另一哈希；转移用带预期旧状态的原子更新，并将对应事件一起提交。
2. 调用前落库“准备调用”和精确目标；失败则不调用。SQLite 与 Windows 无共同事务，崩溃恢复遇此状态也须当作可能已调用。
3. 返回对象、作业 ID、错误、后置事实、状态转移以事务保存；不持有 SQLite 长事务等待格式化。
4. 同 ID/同哈希重复请求返回已有状态，不重写；不同哈希拒绝。请求可能送达后客户端不自动重发写命令，重连只查状态；仅未发任何字节时可按现有连接规则更新连接。
5. 扩展现有 `operation_plans`、`operation_steps`、`execution_events`，生产写入口须有租约。消息列表继续只存内存；持久执行记录承担恢复，不新增通用审计页面。
6. Agent 开放真实启动请求前先读未终结记录、建立恢复禁写状态。数据库不可读/schema 不支持也禁写，不能重建绕过；过期授权不恢复执行。只读对账，不重放/续跑/回滚。对象不存在不能单独证明从未执行，尤其删除、格式化、清盘及同名重建。
7. 不确定操作保持全局真实写入锁，只读/模拟可继续；已证明完整后态、相关成员和运行依赖后才可解除。即使有部分成功，只要其它影响/关联不明仍为待核对。已查明的部分完成可记终态并解除锁，但余步绝不自动恢复，须另计划确认。

### 7.3 并发、长操作和取消

- Agent 最多一个真实修改计划；另一启动返回忙，不排未经重新确认的写队列。事件是提示，持久状态查询是权威。
- 提交短请求返回持久操作 ID，随后事件/查询跟踪；完整格式化不占唯一控制通道，查询及请求停止后续步骤仍能响应。
- 取消表示停止尚未开始的步骤；当前 Windows 调用/作业开始后不承诺撤销，不因关对话框、App 断连或 CancellationToken 杀写进程。
- 用提供程序明确返回的作业 ID 跟踪；无可靠关联不按全机作业名猜测。进度未知显示等待/已用时间，不伪造百分比。
- 传输超时不是执行超时。可查询作业每 **2 秒**查询一次，单次只读查询最多 **30 秒**；异常保留状态并提示。命令仍运行时无固定总时长强杀。命令结束后每 2 秒复采、最多 **60 秒**；仍不能确认则待核对，可继续人工触发只读对账。
- 有执行中/待核对操作时，托盘退出、Agent shutdown、提权交接和数据迁移读取同一持久状态并拒绝；App 关闭说明 Agent 是否仍工作。系统注销、断电、外部强杀不能保证拦住，靠预写状态及重启对账处理。日常可停止进程授权不用于中断写盘。
- 构建脚本不受 Agent 内存锁控制。停进程/替换运行树前须按 App/Agent 同一数据位置规则（含标准根外指针和便携 Data）解析活动 `winpool.db`，只读核对状态；未终结、指针歧义、已有活动根却缺库或不可读均拒绝。可证明尚未初始化且无活动指针/WinPool 进程的首次构建可进行。检查落实到 Clean/Rebuild/运行树合并入口，不能只查默认 AppData 或只写人工提示。
- 写后结果落库失败：停后续、保留记录/现场，不为补记录重发命令；重启按未终结状态对账，不能核实就继续禁写。
- 断线/崩溃窗口用替身和临时数据库注入。本阶段不在真实写入中拔盘、断电、强杀 Agent 或重启 Windows 来造故障。

- 单盘 Simple/Fixed VD 初始 **16 GiB、1 列、65536 bytes Interleave**；新建 MAX 查适用的创建能力，已有对象 MAX 仅按 C05。单盘 Simple 验证不叫分层研究验证。
- 只在获准新建测试卷写一个 **16 MiB 固定种子文件**，关闭/flush 后记 SHA-256；改名/盘符/扩缩/脱机再联机后重读比对。文件写入也列入测试批准；不扩成压力测试。文件清理遵守 AGENTS；获准格式化/清盘的损失另按该操作确认。
- C 类单独计划：ReFS 候选 **1024 MiB/65536 bytes/快速**，官方适用性与现场支持核实后才提交，不支持不自动换参。C04 先查单 HDD 层最小值/粒度/关联，按证据确定精确参数，不随机试错。

### 10.3 固定顺序

这是验收安排，尚未填写唯一身份，不是执行授权。每行实际子操作均按 2.2 取得批准，条件不满足停在该行。

| 编号 | 前置及操作顺序 | 通过条件 |
| --- | --- | --- |
| H00 | 准入表、完整前态/保护盘拓扑/运行依赖，确认测试末态 | 身份/成员/路径完整，工程门通过，无待核对操作 |
| H01 | WDC 有结构则单独预览并批准清理/解散；原为 MBR 时先验证 C03 到 GPT，再另经准确批准清理至 RAW；其它 GPT 状态也需独立清理计划；原本 RAW 不清理 | 仅清批准对象、中间结果核对，H02 前态明确为 RAW，不造 MBR |
| H02 | RAW→GPT+MSR，创建主 NTFS 分区；另一不格式化 BasicData 执行 1024→2048→1536 MiB 后删除；H04 中删除现有 MSR 后再验其独立创建 | 初始化、RAW 扩缩、NTFS 分别有证据，无隐含格式化；可选 MSR 关闭分支在 H07 验证 |
| H03 | 文件哈希；卷标 Enter、盘符更换/清空/恢复；8192→12288→10240 MiB；脱机/联机 | 每次独立核对，关联/哈希保持，刷新/关窗不产生额外修改 |
| H04 | 独立小分区完成完整 NTFS、快速/完整 exFAT、EFI/MSR/Recovery 创建/删除；几何先入计划。每次创建后复采角色，仅仍非 Boot/System 且无其它保护条件才执行获准删除 | 类型及快速/完整证据齐全；出现保护角色则停并报告，不为清理用整盘 Clear-Disk 绕过，不声称部署引导/恢复环境 |
| H05 | 满足条件则 C01/C02；C03 已在 H01 处理，缺条件验证禁用 | 可用分支有实测，不可用有依据，不回退 FS |
| H06 | 单独批准清理直接分区，使 CanPool；创建单成员池，先关自动 VD/分区 | 池真实存在、唯一 WDC、无 VD；无成员草稿不能算此项 |
| H07 | 建无分区 Simple/Fixed VD；在其 RAW OS 盘初始化 GPT且关闭 MSR，验证无 MSR；获准删除后再建带自动 GPT/MSR/BasicData 的 VD。自动分区大小和是否格式化在确认前显示；不为留扩容空间偷偷改 MAX 默认 | 自动开/关影响步骤，一池最多一块新 VD，身份链明确；MSR 开/关分别验证 |
| H08 | 池/VD/卷标签改名；满足 C05 才做既有 VD MAX 并记录原 ID 保持，分区扩展另列计划；若当前分区无增长空间先显示拒绝，不暗删重建；核文件哈希 | 参数真实改变、无隐式扩分区；C05 不满足则禁用证据，H03 已独立覆盖分区扩缩 |
| H09 | 若 C05 已执行，以 H08 相同 VD 身份作为原地修改对照；否则用自动 T13 证明普通布局修改拒绝且无删除调用。另确认完整池重建到 **32 GiB VD/同一合法 Simple/Fixed 布局**，打开自动建 VD/分区，逐项列旧池及子对象删除、新池→自动 VD→初始化/分区/格式化 | 自动建池分支也实测，仍逐步记账；真实目标确定、旧→新 ID 可追踪；不以 Enter 改名冒充布局修改；无自动重试 |
| H10 | C04 满足时先另行批准删除 H09 的非分层 VD及其子对象，保留单成员池；再创建 HDD 层模板、以该层新建 VD，验关联/改名/删除重建；层 MAX 另按 C05 | 不对原非分层 VD凭显示分组挂层；真实层/关系有证据；不支持保留禁用 |
| H11 | 独立批准最终清理或用户末态；完整复采、普通 App 重启重读 | 无未终结操作，末态正确，无 WinPool 导致的 Samsung 结构改变 |

H00 的测试末态已由用户确定：WDC **在线 GPT、16 MiB MSR + 剩余可用范围一个 NTFS/64 KiB 数据分区、卷标 `WinPool_Test`、盘符 `E:`**。H11 前重核 `E:` 占用；若已被其它卷占用，停止并重新确认，不自动换字母。末态选择不代替各次清盘、删池、分区和格式化的精确授权。“恢复”不表示恢复已销毁原数据。

测试前保存界面及偏好基线，结束后恢复语言、主题、开发者模式、自动建 VD/分区、MSR、监控等本轮临时改变的偏好。恢复偏好不触发真实结构变更，不能自动恢复真实编辑同意；普通重启后开关仍关闭。若中途受阻，记录当前偏好与设备末态，不用未经批准的写入来凑“恢复原状”。
