# 提权重启与 Agent 连接复发修复 Plan

状态：待执行；仅完成计划编制。日期：2026-09-16；代码基线：`ed688d6`（V0.53）。本计划不代表已修复，也不授权真实存储写操作。

## 目标与范围

修复用户报告的“打开本机真实操作 → 以管理员身份重启不完全 → Agent 弃连/握手异常”。成功标准不是新窗口出现或警告消失，而是旧 App 完整退出、新管理员 App 接管、Agent 连接和工作区恢复均可验证。

只处理提权交接、相关 App 生命周期、单实例和 Agent 控制/事件连接；不新增真实存储操作、不扩大 Agent 默认权限、不重构无关模块。提权不等于存储操作授权；Real 同意不持久化。执行采用独立运行树和隔离数据，保留用户正在使用的实例与数据。

## 已知事实与待核实原因

| 位置 | 静态核对结果 |
| --- | --- |
| `WindowsElevationRestartService.RestartElevatedAsync` | `runas` 返回进程即报告 Started，只传旧 PID；不代表新实例已就绪。 |
| `MainWindow.RequestExecutionModeAsync` / `MainWindow_Closed` | Started 后调用 `Close()`；保存与监控脱离位于 `async void Closed`。此链路未显式等待共享 Agent 连接释放，不能把关窗等同于清理完成。 |
| `Program.WaitForProcessHandoff` | 最多等旧 PID 10 秒，但忽略 `WaitForExit` 返回值，随后仍进入单实例重定向；没有核对旧进程启动时间。 |
| `App.ConnectAgentAsync` / `NamedPipeAgentConnection` | 存在启动重试；连接包含控制握手、事件握手、恢复快照多个阶段，不能只检查控制管道接通。 |
| `AgentControlServer.RunAsync` | 控制连接串行服务，已有握手期限；已连接后的 `IOException` 被整体静默处理，需区分正常退出与真正错误。 |

`116ac08` 已处理关闭窗口后继续更新控件、跨完整性进程身份读取及正常弃连提示；其验收保留原 Agent。此次用户报告说明不能复用旧验收结论。上述代码风险尚不是本次现场根因：先排除运行旧二进制/混合运行树，再核实残留窗口或进程、连接未释放、单实例重定向、身份拒绝与事件订阅失败之间的实际顺序。

## 执行步骤

| 阶段 | 工作与交付 | 状态 |
| --- | --- | --- |
| P1 复现定位 | 记录 App/Agent 路径、文件版本或哈希、PID、启动时间、权限、数据根、Agent session；关联 `app-crash.jsonl`、`agent-control.jsonl` 与连接结果。复现一次正常交接及当前失败，标明最早偏离预期的阶段。必要时加最少量阶段日志，不凭“弃连”字样认定根因。 | 未开始 |
| P2 收口交接 | 在现有生命周期入口实现可等待的交接：防重复触发 → 确认 UAC 启动 → 有界保存/停止旧 App 本地任务与连接 → 关闭所有所属窗口并退出 → 新进程核验旧实例退出后接管。处理欢迎窗口、后台连接重试和关闭回调，避免多个入口各加一套补丁。 | 未开始 |
| P3 修复连接 | 根据 P1 修复控制/事件握手、取消/释放及恢复快照的具体缺口；旧连接不再占住监听，新客户端可以完成全部连接流程。正常退出不误报，拒绝/超时/持久化失败仍可追溯；不以扩大超时、吞异常或清除 endpoint 代替修复。 | 未开始 |
| P4 验证收口 | 用失败用例验证修复，再执行下表及相关项目测试和 Release 构建；记录实际命令、运行树及结果。更新受影响的 Development/CHANGELOG，完成后归档本 Plan。 | 未开始 |

P2 的具体清理顺序以 P1 为依据：UAC 取消或启动失败时，旧实例仍可用且保持原模式；超时必须明确失败，不能继续重定向到未退出的旧窗口并冒充成功。涉及进程等待/清理时同时验证 PID、启动时间和路径，不按进程名批量结束程序。新实例尚未就绪时不宣布“重启成功”，旧实例已退出后若启动失败，给出可见诊断和重新打开路径。

Agent 是否需要替换由权限职责和现场证据决定，不能预设“不重启就是正常”，也不能为完整重启而无条件结束监控。复用时验证原 Agent 健康且新 App 可完整接入；若确需替换，使用既有有界关闭、监控收口、写租约释放及 endpoint 重建流程，验证只有一个写入者。若需要改变产品权限模型，先说明依据与影响，不借本修复引入后台常驻提权。

## 回归与验收

| 场景 | 必须观察的结果 |
| --- | --- |
| 普通 App 开启本机真实操作，接受 UAC | 旧 App PID 消失；仅一个目标管理员 App；同一数据根，模式及工作区正确；控制握手、事件订阅、快照和一个只读请求成功。不是只看标题“管理员”。 |
| 同时打开欢迎窗口；连接/采集尚在进行；监控开启 | 旧 App 所属窗口和任务全部收口，无关闭后访问控件；Agent 监控按既有语义保持，若受控替换则明确收口/恢复，不产生双会话或双写入者。 |
| 取消 UAC、启动失败、重复点击 | 原窗口、模式和连接可用；无重复提权和遗留新实例。 |
| 旧进程退出慢/超时、PID 失效或复用 | 有界失败且身份核验正确；不误等/误杀其他进程，不回到旧窗口后误报成功。 |
| 已提权 App 再开启选项；正常关窗后重开；数据位置交接 | 不无故再提权；普通重开不继承真实操作同意；不破坏共用的等待和启动参数语义。 |
| 零字节/半帧弃连、旧客户端仍连接、事件握手中取消 | 连接释放后健康客户端可接入；不静默挂起、不使 Agent 监听退出；正常断开与超时/协议/身份错误分开记录。 |
| Agent 未启动、endpoint 陈旧、权限/身份核验失败 | 成功恢复或明确失败；不得绕过 SID、nonce、协议、进程身份和单写入者校验。 |

自动测试优先覆盖生产交接逻辑和真实命名管道，允许注入进程/UAC结果与时钟；保留已有弃连、半帧超时、跨权限身份及参数测试，补上其未覆盖的完整顺序。新增回归须能在修复前暴露对应缺陷，不能只断言源码含某个字符串。

原生验收从设置页和主窗口实际入口执行；在隔离运行树中连续完成至少三轮“普通启动 → 提权交接 → 连接恢复”，同时覆盖取消及退出超时。UAC 安全桌面由用户交互，不绕过系统确认。验证期间仅使用只读请求，不执行磁盘修改。缺少实际跨权限验证时标记 `unverified`，不得以自动测试通过宣告本问题已修复。
