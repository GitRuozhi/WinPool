## 1. 目标与范围

**以“来源事实、WinPool 统一模型、应用数据”贯通采集、硬件查看、真实只读管理、现有模拟存储编辑与逐步 PowerShell 命令预览。** 完善现有能力，不重新设计全部产品。

| 本版交付 | 边界 |
| --- | --- |
| 统一数据链路 | 来源保留、可靠关联、统一选值/派生、持久化与消费者一起切换，退出重复权威 |
| 采集与硬件页 | 完善限定来源中的存储属性；硬件页只读，展示多设备、字段、来源与失败原因 |
| 管理与模拟编辑 | 保持现有有效操作及交互，升级底层模型、编辑状态、规则和计划 |
| 命令预览 | 与步骤对应的命令和说明，不是完整可独立运行脚本 |

明确不做：真实存储写入或隐藏写入执行器；任何新增存储编辑功能；CPU/内存/GPU 等非存储硬件模拟或编辑；全量原生 API 重写；厂商私有/远程/集群等新采集体系；完整终端、通用规则框架、数据库全面重写、拓扑布局重写、运行时/平台升级、签名发布。

**“采集升级”不等于“全部从 PowerShell 改为原生 API”。** 本版复用并修正现有 PowerShell、CIM/WMI 和已实现原生读取；有效备用来源可以保留。退出的是旧数据兼容和重复解释路径，不是有价值的备用采集。

## 3. 数据契约

### 3.1 三类职责与更新

| 类别 | 内容与权威 |
| --- | --- |
| 来源事实 | 真实采集、导入或模拟产生的对象、属性、关联、读取状态、来源及时间；模拟值明确标记来源 |
| WinPool 统一模型 | 面向软件的统一对象、统合字段、派生属性和显示分组；按事实与规则生成，可缓存，不独立修改 |
| 应用数据 | 内部身份对应、修订、设置、选择、草稿意图、操作计划和提交记录；不要求都能从 Windows 推导 |

正式更新：采集/模拟结果 → 来源事实 → 统一模型 → UI。编辑输入先成为应用意图，生成隔离的候选事实与预览；不能在提交前改当前事实，更不能直接改统一模型再反向同步。模拟提交成功后才切换当前事实。候选事实仍使用同一套字段定义，不建立另一套业务模型。

前端、报告和必要的监控接线引用统一对象及统一服务提供的来源详情，不各自做多接口匹配、选值、容量计算或假层归组。

### 3.2 对象、分组与身份

统一业务对象用 `WinPool` 前缀，例如 `WinPoolDisk`、`WinPoolStoragePool`、`WinPoolStorageTier`、`WinPoolPartition`、`WinPoolVolume`、`WinPoolProcessor`。属性不重复加前缀。序列化显式保存对象类型与格式版本，不依赖任意 CLR 类型动态加载；不同职责可以共用数据库/文档，不强制拆文件。

来源中保留 PhysicalDisk、VirtualDisk、Disk 的独立类型。统一磁盘视图可组合已确认的 PhysicalDisk＋OS Disk，或 VirtualDisk＋OS Disk；不能把支撑同一虚拟磁盘的多块物理盘合为一个身份。仅发现 OS Disk 时照常保留，“其他磁盘”是归类结果。保留全部可靠关联和特有字段归属，避免重复计数；操作按种类定位正确来源对象。

Partition 与 Volume 保留独立身份、容量、类型与关系，前端可以组合。StoragePool 与实际 StorageTier 独立；层模板、真实层和界面分组不能混为一谈。

**`WinPoolDisplayGroup` 仅指统一模型中的“显示分组”**，用于热备、退役、未划层等现有框。不是新存储实体、真实层或额外分组引擎；可复用现有分组实现。成员由 Usage 和可靠关联统一派生，页面直接显示。`IsHotSpare` 同样派生；Usage 未知不能当 false，关联失败不能当未划层或未分配。拖入热备分组提交设置用途意图，不保存第二份可写成员清单；折叠/可见性属于应用偏好。

软件用一个内部对象引用，关联多个来源身份。内部身份对应记录要保存，重建缓存不重新随机分配；改名/枚举顺序不改可靠身份，不靠名称、盘符或编号猜测关联。普通 UI 不展示内部 ID。复制系统有独立身份和引用，不可能路由回原系统。

### 3.3 字段与来源规则

原始字段保留“来源类＋属性”、类型语义、单位、数组、枚举代码和精度。不同语义的容量或状态不得因同名而统合；只对需要选源/计算的字段派生 WinPool 结果，单一明确来源直接引用。

读取字段采用公共的 `Value`、`ReadState`、可选 `ReasonCode`、`SourceRef`。`Returned` 包括实际返回的 0、false、空集合及 null；`NotCollected` 表示未查询；`Unavailable` 表示有依据的不提供/不适用；`Failed` 表示查询失败。成功返回 Unknown 枚举仍保留原码。脱敏、来源冲突分别标明，不伪装成未采集；不把冲突值简单取最大、平均或最后值。

来源选择、备用条件、对象匹配和单位换算集中维护并复用现有有效规则；保留原始证据及采用依据，不能把已格式化的最终结果再标作原始返回值。UInt64 等跨 JSON/IPC/数据库无损承载，不经浮点丢精度；运算超出支持范围时只读保留并拒绝相应编辑。

## 4. 采集范围与刷新

本版来源限现有本地 Storage Management CIM/Storage cmdlet、Win32/WMI 补充接口及已实现的原生只读路径；允许在这些来源补固定只读属性查询。对象包括 Computer/OS 必要上下文、StorageSubsystem/Pool/Tier、PhysicalDisk/VirtualDisk/Disk、Partition/Volume、既有网络映射及硬件报告来源。

存储对象尽量保留可读标准属性，包括当前未编辑的低成本信息；其他硬件保留有效采集能力。不得以“完善”为由无限加入新接口、权限、提供程序或编辑功能。分类和项目数量不限于旧 13 类、154 项；拆分/合并旧项目需保留有效信息或说明纠错理由。

必须重新核对并贯通以下已发现风险；本地已修好的项目转为回归：

| 风险 | 目标 |
| --- | --- |
| 分区类型与卷容量 | 分区自身 Guid、GptType、MbrType 分开保留；卷 Size/SizeRemaining 独立采集，不用分区 Size 代填；原生卷不得仍分类为 Partition |
| 身份与状态 | DeviceId 保留来源字符串含义；状态/原因数组、身份稳定性和未知值不丢；补可获得的只读、脱机及原因 |
| 布局与占用 | 已采到的虚拟磁盘副本/冗余/分配参数进入统一链路；Size、AllocatedSize、FootprintOnPool、SizeRemaining 分清 |
| 关联与报告 | 无卷、卷读取失败、无盘符、目录挂载分别表达；多设备按对象匹配，不按不同字段数组的相同下标配对 |

新增/修正字段完成采集、状态、关联/统合、持久化/IPC、消费者及往返测试整条链路。集合查询失败或部分失败不能被当成“全部对象消失”。

分开存储刷新与完整硬件刷新：启动先显示缓存，管理普通刷新不强制采 CPU/GPU/显示器等；完整硬件按需读取。Agent 协调两类动作、取消/超时及重复请求，保留各自时间与完整性。较旧结果不覆盖较新事实，迟到结果不更新错系统，不回退草稿或模拟副本。默认使用受控串行调度，进一步并行要有测量依据，不新建通用调度平台。

现有 Windows PowerShell 5.1 采集基线、固定只读脚本、程序集内嵌、stdin 和安全检查继续保留；不发布外置 inventory 脚本，不接受自由 PowerShell/WQL。全面原生化及 PowerShell 7 迁移不属于本版目标。

## 5. 硬件页与属性展示

新增只读 WinUI 硬件页，沿用导航、系统选择、语言与主题，按分类/对象展示统一模型。池与层分开组织；多设备明确对应；字段状态、来源、失败原因和采集时间可见。仅有存储数据的模拟系统可以没有 CPU/内存信息；已有复制硬件信息只读展示，不参与模拟运算，也不能用本机刷新覆盖它。

**不为展示标准字段名而改坏现有界面：**

- 管理/编辑页的卡片、表单和操作区保留当前主体布局、友好名称与格式化值；不强制给每个控件增加常驻技术行或大幅加宽。
- 选中属性或展开详情后，可以查看标准项名、原值及单位、来源、读取状态；悬浮提示可辅助，但不能是唯一入口，键盘也应可访问。
- 新硬件页可在属性列表提供标准项名，原始多来源内容放在详情。统合字段同时说明 WinPool 字段及对应来源，不冒充某一 Windows 原始属性。
- 示例：主界面仍显示“容量 931.32 GiB”；来源详情显示 `MSFT_PhysicalDisk.Size`、`1000000000000 bytes` 和读取状态。`Value/ReadState` 是内部表达，不直接铺成普通页面控件。

来源详情由统一服务提供，前端只负责展现。具体详情控件可复用已有结构，不增加独立诊断工作区。必要模型接线不能变成拓扑布局或整体视觉重写。

## 6. 模拟编辑与命令预览

真实→模拟、模拟→模拟复制均为独立系统，不共享可变对象、缓存、计划或写目标；原系统刷新、删除、编辑不影响副本。模拟操作只更新当前副本事实，新值标为模拟；旧来源证据不能覆盖新值。管理/硬件/编辑页均读取当前统一结果，不保留另一份当前报告正文。既有创建、重置、复制、导入导出和内置样例适配新格式，不新增历史报告或非存储硬件模拟功能。

将页面中的基线、草稿、MAX、各池创建意图、撤销/重做、计划及提交状态集中到可测试的编辑会话。MAX 是意图，显示舍入、延迟事件和选择切换不能改变它；即时改名按 ID 更新基线与相关草稿/历史；删除覆盖无意义修改，成员目标和新建身份不得丢失。保持原来页面切换行为，不新增跨重启草稿恢复功能。

继续使用一个规则入口，返回允许/拒绝/信息不足并解释依据；不引入多个规则引擎。表单可用性、按钮/拖放、预检查共用相关规则。候选结果统一验证身份引用、分区几何、盘符、介质与容量。保留基线 MAX 向下 4 GiB 对齐等模拟策略，不宣称是 Windows 通用保证。拒绝保留草稿，冲突不覆盖，结果未知先按 CommitId 对账；后续步骤失败不部分持久化。

结构批量、分区即时操作和改名都使用类型化计划；单项可以只有一步。步骤至少含种类、内部目标、明确参数、顺序/依赖、基线修订和风险原因。预览、模拟执行和命令生成消费同一份计划；收紧混用名称/目标池/用途等含义的参数，不另造通用命令系统。

命令预览位于既有待办/结果详情，可逐步查看、复制；一步允许多条对应命令。使用正确 cmdlet/参数名并处理转义。目标未绑定时明确占位，不把模拟 ID/脱敏哈希填入 Windows ID 参数；无对应命令、内部动作、no-op 或空池前提不足时说明，不编造命令。只校验对应关系与语法，不执行生成文本，不保证独立可运行，不新增终端、脚本执行按钮、真实目标绑定和恢复后端。

## 7. 数据与旧路径退出

保留 SQLite＋带版本 JSON 文档，不建立外部 JSON 文件与数据库的双向同步，不要求全部字段拆 SQL 列。来源事实与必要应用数据持久化；统一缓存/查询索引可重建且不能独立业务写入。内部身份记录必须保留；缓存过期按事实修订及投影规则版本重建。

按实际不兼容变化确定并记录 schema、IPC、文档/事实版本。新格式完整往返；旧格式明确拒绝，不保留产品内兼容/迁移代码，不静默删除或覆盖旧数据。必要的一次性人工转换只针对选定开发数据，工具不进入运行、构建依赖或发布；内置样例可重建。

保留 App＋托盘 Agent、类型化 IPC、Agent 单写入方、租约、事务、哈希、修订冲突及 CommitId 对账。真实写入在应用/IPC/Agent 均不可达，不只禁用按钮；模拟可跳过 Windows 状态检查，但不能跳过文档和提交保护。来源事实、详情、日志、导出、复制和命令预览均遵守同一脱敏边界。

新模型优先进入既有项目。迁移完成的旧模型、重复规则、报告选源及假层写入路径退出构建/运行；按 AGENTS 移到 Old/Archive，不直接删除、不成为运行依赖。有效多来源备用读取保留，不能与旧格式兼容代码一起误删。数据位置、设置所有权、监控和便携运行结构只做必要适配。
