## 1. 即时改名与身份：固定决定

### N1 改名单独提交

- 已保存对象的 FriendlyName，以及卷的 FileSystemLabel，属于命名修改，不属于结构修改。沿用现有合法可编辑范围，不因为某对象有名称就虚构 Windows 可写能力；物理盘/池/层/VD/OS 盘/分区/卷需逐类检查现有入口与支持范围。
- 名称输入框按回车（Enter）即时提交改名，不增加“保存名称”按钮，不等待结构应用。普通输入和失焦不提交；名称未变化或提交尚在进行时不重复写入。中文输入法确认候选的回车不误触发提交。复用现有反馈，不增加二次确认对话框。
- 每次仅发送目标 ID 与新名称，通过现有类型化 Rename 单独提交，不能携带结构草稿、文件系统、簇大小或容量。字段输入未提交时只是文本缓冲，不增加结构动作、不启用结构应用/放弃、不进入结构撤销/重做。
- 改名成功即更新已保存文档和界面；失败保留原已保存名称，给出原因与可重试输入。保留现有名称合法性限制，不擅自增加名称唯一性要求。池名、VD 名、卷标互不连带改名；OS 盘若是同一 VD 的派生展示，仅遵守既有投影关系。
- 有未应用结构草稿时仍允许对已保存对象改名，包括草稿中待删除的对象；不得因此阻止改名，也不能提前应用结构修改。实际提交中串行化写请求，保留冲突/未知结果处理。
- 成功后按 ID 将名称更新同步到最新基线、当前草稿、撤销和重做状态；保留成员、容量、MAX、分区参数等结构意图。随后重建待办显示及预检查，结构动作不得夹带旧名称把新名称改回去。
- 结构撤销、重做、放弃均不能撤回成功改名；应用结构也不能覆盖它。已有确认窗口若基线或草稿变化，旧确认失效。非本次改名导致的并发修订变化仍按既有冲突处理，不盲目覆盖。
- 尚未创建的草稿对象没有可持久化目标：名称作为创建参数留在草稿，界面说明“创建时生效”，不提前创建对象、不生成额外 Rename 动作。创建动作可显示名称；撤销/放弃创建自然撤销该对象及其创建名称。

### N2 对象以 ID 追踪

- 复用现有 `SystemId + 对象类型 + StableId` 身份及关系键；UniqueId/ObjectId 是提供程序身份来源或定位信息，不另造一套并行身份模型。名称仅用于显示、搜索与名称字段修改。
- 模拟对象和草稿对象在创建时分配稳定 ID；改名、同名、切换选择、保存加载不得改变它。草稿转正式对象使用确定映射并更新所有引用，不通过名称找回对象。
- 检查 `StorageModels.cs`、`RawSnapshot.cs`、StableId 工具、采集映射、关系投影、页面选择、草稿字典、计划目标及仓库存取。重点排查以 FriendlyName/FileSystemLabel 构造持久 ID、关联或定位目标的路径；不要把正常文案/搜索匹配当成身份匹配批量替换。
- 真实采集优先使用当前对象类型适用的 UniqueId/ObjectId 或已存在的稳定标识。不得将名称、盘符、列表序号、DiskNumber 单独作为持久身份，也不能假定所有 Windows 对象都有同一种 UniqueId。
- 缺少可靠标识时保留“不稳定/未知”状态和只读展示，不以名称猜测跨采集身份，不允许据此选定写目标。不稳定对象也不应在改名后误关联其他对象。保持现有脱敏边界。
- 验收：两个同名对象只改中选目标；改名后 ID、成员/父子关系、选择与待办目标不变；保存再加载不丢关联。身份不足明确可见，不误匹配。

以下是后续获准验证时的验收清单；无需扩大成全量回放系统测试：

1. 有数据的池/VD/卷分别在名称输入框按回车改名（普通失焦不提交、输入法确认不误提交）：仅名称改变，ID、容量、文件系统、簇、已用量、路径与关系保持；无结构动作。
2. 待移动磁盘/修改容量 → 即时改名 → 结构撤销/重做/放弃或应用：名称始终为保存后的值，结构意图各自正确。改名失败/修订冲突不修改基线，不丢草稿；提交中重复 Enter 不重复写入。
3. 两个同名池/磁盘精确选择；名称改变并重新采集/加载后按可靠 ID 关联。缺 ID 不用名称猜测。草稿对象改名只影响创建参数，放弃后无持久化对象。
4. 池 A 只改文件系统/簇后切换 B 或原始池，仍可应用/放弃；再切回 A 参数保持。仅已有对象名称文本编辑不会触发结构待办。
5. 改分区参数 → 解散池/删除 VD → 撤销删除：删除时无尾随属性动作，撤销后恢复此前参数意图。
6. 新池/已有空池分别设置独立池名、VD 名、卷标及自动分区；切换对象后创建值正确。手动容量和 MAX 下尺寸、分区边界一致。
7. 文件系统/簇 A→B 确认→撤销→重做；手动 80 GiB→MAX→手动 60 GiB，以及 MAX 后增减成员撤销：值、模式、动作和原因一致。
8. 一个解散操作中两个不同磁盘有独立阻塞条件，父项折叠时仍能看到两种原因；依赖动作说明准确。无错误的步骤不被误标成独立错误；中文/英文原因与对象信息可读。
