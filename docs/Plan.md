### 1.2 以模拟操作为基准的接线表

| 原操作 | 真实模式必须沿用的逻辑 | 必要的真实差异 |
| --- | --- | --- |
| 新建池、拓扑拖入/移出成员 | 进入本地草稿；属性和净差异同步；撤销/重做/放弃仍操作草稿 | 无成员不可 Apply；已在池成员的迁移/移除等未支持动作不能借拖拽放行 |
| 保存属性、自动创建偏好 | 保存属性只更新同一草稿；偏好独立保存；Apply 消费当前表单与净差异 | 真实容量和能力以 Agent 的实时依据冻结，不把候选拓扑作为 Windows 事实 |
| 已有池创建首块 VD、删除池/VD/层 | 结构变更加入待应用动作，由原 Apply 提交；新增对象名是创建参数 | 清单列出准确删除对象和损失；单独清空磁盘仍是磁盘页即时动作，不能混作拖拽副作用 |
| 已有对象名按 Enter | 独立改名；失焦不提交；不进入结构撤销栈 | 保留准确计划确认；核对成功后把新名称同步到当前草稿及撤销历史，不丢其他未提交修改 |
| Apply | 原位置发起，沿用原净差异呈现和操作反馈；不再要求另填建池表单 | 先确认准确冻结计划；必须复采新身份的下一段仍有其准确确认，不能用最初确认代替未来身份核验 |
| 失败或冲突 | 保留未完成的输入与目标，沿用现有消息和净差异区说明原因 | 已完成写入不可撤销；按已核对事实标明剩余项，Unknown 时禁写，只读对账 |

模拟原子提交继续保持。真实额外确认是执行安全要求，不是新参数编辑流程；不新建步骤中心、任务工作区或独立向导，不以“回归模拟”为由移除真实确认。显式重建采用模拟已有操作：在同一草稿中解散旧池、新建池、拖入释放成员并编辑目标，最后 Apply；解散尚未执行时的“释放成员”只是草稿预期，不能当作真实 RAW 证据。直接成员迁移仍禁用；仅当同一草稿已显式解散旧池时，才允许把该 WDC 指派给替换池草稿，此拖拽只表达目标成员关系，不生成独立真实 `MovePhysicalDisk` 调用。旧真实专用重建按钮/参数向导退出日常入口，复用其必要后端能力。删除前显示损失，不能由普通 Apply 失败自动触发。

## 2. 范围与保持有效的边界

### 2.1 纳入本阶段

1. 存储结构页的新建池、池内首块虚拟磁盘、已支持的单 HDD 分层创建，以及普通和单 HDD 分层结构的显式删除重建，均为必交付。
2. 原拓扑、右侧属性、软件自动创建偏好、净差异面板、撤销/重做/放弃和应用入口在真实模式下的正确连接。
3. 用户参数从草稿到真实计划、分段执行及结果呈现的完整传递；新建容量输入与 MAX 意图的正确处理。
4. 对已有池的编辑：已支持动作进入正确流程；不可原地修改的结构参数明确区分拒绝与显式重建，不能以新表单掩盖缺失能力。
5. 两个编辑页的页面外边距；磁盘分区页的联机/脱机、初始化/GPT 转换合并入口、独立清空磁盘、扩缩公式及起点/终点显示。
6. 未勾选创建 MSR 时的初始化最终结果；真实执行持续反馈、写后图形遮罩、相关对象采集、预期改动与本软件监控联动及性能定位/优化。
7. 分区页按本次明确要求调整，不扩展文件系统组合、既有 VD/层扩缩或完整测试工作区。清空磁盘复用已支持的准确清盘能力，不绕过真实操作安全校验。

### 2.2 不扩大真实能力范围

- 本机写入仅限已授权 WDC 及完全由该盘承载的对象；真实布局沿用已核验的 `Simple`、`Fixed`、1 列、64 KiB interleave。
- 单 HDD 分层沿用已有能力核验，不推导出多盘冗余、混合介质性能/容量分层或任意层组合可用。
- 多成员加入/移除/迁移、Mirror/Parity、Manual、Journal、第二块虚拟磁盘、既有虚拟磁盘/层的扩缩及 MAX 扩展、C03/C05/D 类等未支持真实能力继续禁用。
- 新建容量 MAX 与既有对象 MAX 扩展是不同能力。前者冻结原生最大容量意图，由 Windows 决定实际容量；明确容量仍须通过适用的 provider 范围核验。后者不因界面恢复而开放。
- 建池自动数据分区默认 NTFS、64 KiB、快速格式化；其他文件系统和格式化方式仅在既有准确能力及本次计划校验均满足时可用。本阶段不新增参数组合。
- 不新增服务、通用向导、独立操作中心、自由形式命令、第二套完整对象模型或数据库历史补填。

### 2.3 已有授权与实机末态

沿用 [AGENTS 的 WDC 持续授权](../AGENTS.md)：`DESKTOP-BLE6H18`，`WDC WD40EZAZ-00SF3B0`，稳定身份 `physical:uid:6ceea032f3fb375a61cd27bd`。用户已确认 E: 无有效数据，覆盖该盘及仅由它承载的存储对象的全部操作、数据损失、修复和验收准备。激活后不再逐操作、新计划 ID 或数据损失说明重复索取聊天批准。

每次仍核实实时硬件身份、完整成员、对象关联、系统角色和运行依赖；两块 Samsung 及其关联对象不得成为写入目标。全部写入通过 App → Agent 的类型化受控路径，保留产品内准确预览、当次确认、短时令牌和结果未知屏障。

实机验收结束恢复 WDC 在线 GPT、1 MiB 起点的 16 MiB MSR、其余可用范围一个 NTFS/64 KiB 数据分区、卷标 `WinPool_Test`、盘符 `E:`。若 E: 被其他对象占用或身份/依赖不明确，停止相关写入并报告，不自行改写其他磁盘。

## 4. 目标产品流程

### 4.1 新建存储池

1. 在原结构页进入空池草稿，拓扑显示草稿状态；尚未应用时真实采集事实不变。
2. 将合格 WDC 成员拖入目标池或适用介质分组；仅凭 `CanPool=true`、盘号或型号不能认定可创建。需要清理的准确对象和影响必须列入受控流程。
3. 在原属性区填写池名、层规格、虚拟磁盘名和容量。新虚拟磁盘名称沿用原名称联动规则；用户改过的名称不被后续默认值覆盖。
4. 自动创建虚拟磁盘、自动创建分区是独立软件偏好，保存在 App 的 `UserPreferences`，不从现有拓扑反推。开关变更保存偏好，新建意图读取偏好，不反向增删已有存储结构。关闭自动虚拟磁盘时允许仅创建有成员的池；关闭自动分区时不初始化、分区或格式化新虚拟磁盘。
5. 属性保存、拖拽和结构参数只更新草稿；待应用动作显示合并后的净差异及阻止原因。撤销/放弃结构草稿不回滚已保存的软件偏好。真实无成员空池只能保留草稿；模拟空池维持现行产品规则。
6. 点击 Apply 后，向 Agent 申请准确计划；最终产品确认必须展示 Agent 返回的目标、参数、损失和步骤。确认前不写入，取消不产生已接受计划。
7. 按冻结计划逐步执行、核对后态；因新对象身份需分段时，保留原输入并说明下一段。结果满足后置条件才显示成功。

复用原确认样式；数据损失汇入准确冻结确认，不先后弹内容重复的通用“是否继续”窗口。净差异是操作前说明，确认框是对当前准确计划的确认，正常完成使用现有通知/结果反馈，不阻塞刷新。

### 4.2 修改已有池

1. 从真实采集基线建立草稿；展示池规格与虚拟磁盘用量，缺失、冲突和未知数据保持可辨认，不用成员容量伪造层容量。
2. 成员和非名称结构参数只在支持范围内进入同一净差异草稿。修改层用量不等于修改池级规格；模板与实际层关联不唯一时拒绝相关写入。
3. 已有池、层、虚拟磁盘名称按 Enter 独立提交准确改名计划；失焦不提交，结构撤销/放弃不回滚已完成改名。新对象名称仍属于创建参数。
4. 可原地执行的动作正常准备计划；必须删除重建的参数明确引导至显式重建；当前能力不支持的动作说明原因并全链路拒绝。不能提交后再擅自把失败转成重建。
5. 不适用的自动创建偏好不改变已有对象。已有第二块虚拟磁盘或复杂分区仍如实展示，不因进入编辑器而自动归一化。

### 4.3 显式删除重建

1. 用户在原结构页显式解散旧池，再新建目标池、拖入同一 WDC 成员并填写原属性，形成包含删除与创建的净差异；该草稿组合定义显式重建。新草稿按现有命名与已确认的新建默认值建立，不另造一套自动继承向导；已经输入的目标参数在 Apply 后各段完整保留。不承诺保留旧 GUID 或数据。
2. 删除前列出准确旧对象、完整数据损失和目标结构，并尽可能只读验证成员、布局与容量。目标结构已知不支持时禁止进入删除阶段。
3. 删除旧虚拟磁盘/相关模板/池 → 复采核实释放成员 → 必要时独立准确清盘并复采证明 RAW/零分区 → 创建目标池/模板/虚拟磁盘 → 复采并完成可选布局。释放成员已有可靠 RAW/零分区事实时跳过清盘；每段仅在前段核对成功后准备。
4. 各段用真实身份冻结并保留当段产品确认；池名、虚拟磁盘名、布局种类、容量意图和自动分区等稳定参数持续传递，不让用户从头填写。
5. 分层重建必须按所选层规格创建模板和分层虚拟磁盘，不能调用普通虚拟磁盘路径替代。实现尚未通过前保持删除前拒绝；拒绝只是安全负例，不能算作本阶段分层重建验收通过。
6. 取消、失败、部分完成或结果未知停止后续写入；只读采集对账。修复/继续从已核实现场另建计划，不自动重放原计划，不自动重建旧结构。

### 4.4 草稿、实时采集与执行状态

- 撤销、重做、放弃只处理未执行草稿，不表示可以撤销磁盘写入。
- 本机/模拟切换、真实开关和提权不改变草稿的系统归属；模拟意图不能发往真实目标。
- 外部变化或无法解释的新采集与草稿基线冲突时，明确提示并停止提交，不静默覆盖用户输入或把旧目标套用到新对象。本流程前段已核对成功所产生的新池、模板、提供程序 MSR 等预期变化，应复采核实并成为下一段基线，不能仅因修订变化误判为冲突。具体草稿保留方式见第 9 节。
- 执行中禁用会造成重复或冲突写入的入口；同一意图不会因重复点击、窗口重连或通知丢失再次 Accept。
- 成功已核对、拒绝/未执行、失败、部分完成、结果待核对分别呈现。最后一类保持写入屏障，不能凭退出码 0 或页面刷新解除。

### 4.5 两编辑页留白与位置显示（用户已确定）

- 存储结构页、磁盘分区页补齐页面内容与显示边界的间距，采用管理/开发页已有的页面级留白方式；以开发页现有四周 24 DIP 为实现基准，避免与宿主已有边距重复叠加。不改管理、开发、设置页来迁就编辑页。
- 留白覆盖拓扑、操作区和属性区组成的整页内容；内部卡片 Padding 不能代替外边距。分隔条仍可拖动，窄窗口仍可切换目标/属性，底部按钮和滚动区域不被裁切。
- 起点、终点分别保留各自字段；每个字段的 MiB 值与自适应单位值上下两行显示，样式和其他容量项一致。移除当前同一行的 `MiB (...)` 拼接。
- 两行都由同一原始偏移值生成，保持既有起点/终点定义；非整数 MiB 不丢失精度，未知值显示未知，不改写真实分区几何。

### 4.6 磁盘按钮合并与清空（用户已确定）

| 入口 | 状态、动作和完成后结果 |
| --- | --- |
| 联机/脱机合并按钮 | 当前在线显示“脱机”，当前脱机显示“联机”；根据新采集的准确状态更新文字/图标。未知、保护对象或执行中禁用并给出原因；点击后不能先把界面状态翻转冒充成功 |
| 初始化/GPT 转换合并按钮 | RAW 显示“初始化磁盘”，目标 GPT；MBR 显示“转换为 GPT”，沿用该动作实际能力与数据损失规则；已为 GPT 时显示已初始化/禁用原因，不再变成“完成布局”入口 |
| 清空磁盘 | 独立按钮，对应 `clean` 的结构清除语义：清除选中磁盘的分区/卷结构至 RAW，不做 `clean all` 全盘清零，不自动建池、初始化或格式化 |

合并只改变入口组织，不开放真实 MBR 转换 C03：真实 MBR 显示“转换为 GPT”但禁用并说明未支持；模拟沿用现有转换规则。不能把“转换为 GPT”偷偷实现成先清盘，也不把禁用当作本阶段缺陷再询问扩大范围。清空是用户显式选择的独立破坏动作，须显示准确磁盘、关联分区/卷、盘符和损失，并走类型化冻结计划确认。

真实清空复用现有 `ClearDiskCommand` 等受控能力；不提供 diskpart 文本框、任意脚本或按盘号直接执行。 现有真实安全前态限普通 GPT Data/MSR 或完整证据证明的零分区 GPT；真实 MBR 清空在 UI 同样禁用并解释，模拟 MBR 保持既有规则。本阶段不扩充 MBR 角色识别与清盘能力。池中物理成员、系统/启动/分页/转储盘、运行/证据依赖及关联不完整目标继续按现有规则拒绝。清空完成须核对同一磁盘 RAW/零分区、原分区和卷关联已移除；已经 RAW/零分区时不产生无意义重复写入。初始化无 MSR 后的 GPT/零分区也是应支持的清空前态：现 planner 对零分区的拒绝应做精确修复，只有本次完整采集证明空且安全检查全部通过才允许；不能由缓存的空集合推出允许。模拟仅更新模拟事实。

### 4.7 扩展/压缩的两行公式（用户已确定）

扩展显示：

```text
AA MiB + BB MiB = CC MiB
A.A TiB + B GiB = C.C TiB
```

压缩使用同样布局，两个加号均改为减号。AA 为操作前当前容量，只读；BB 为正的扩展/压缩量，CC 为操作后目标总容量。修改 BB 联动 CC，修改 CC 反算 BB；扩展满足 `C=A+B`，压缩满足 `C=A-B`。输入不直接触发磁盘操作，确认仍只提交准确目标总 bytes。

- 第一行使用整数 MiB；第二行由同一组容量转换为自适应单位，各项可采用不同单位以便阅读，不将例子中的 TiB/GiB 固定套用到所有容量。
- 用户已确认：第一行 BB/CC 可编辑并双向联动，AA 只读；第二行全部只读展示，不能增加第二套可编辑单位输入。
- 使用一份权威容量状态，避免双向事件递归或重复舍入。空输入/输入中间态可以暂留，但暂停另一项的有效联动并禁用确认；非整数、负数、溢出、零改变量、方向错误、超界或不符合对齐规则时给出具体原因，不静默夹紧到边界。
- 真实范围由准确目标的 provider supported-size 查询给出；模拟使用现有建模规则。CC 和 BB 的允许范围按同一当前 A 推导，提交前重新校验真实上限/下限；能力过期不能沿用旧范围写入。
- 当前 bytes 不是整 MiB 的已有布局不能先四舍五入再当作准确 A 计算。保留原始 bytes、明确显示精度差异；整数公式无法准确表达时停止确认并给出原因，不擅自改动已有容量。该边界作为直接回归，不把易读显示值作为执行输入。

### 4.8 创建 MSR 选项与初始化末态（用户已确定）

未勾选“创建微软保留分区”时，初始化最终结果必须是 GPT 且没有 MSR；仅初始化不附带创建 BasicData 或格式化。勾选时按既有规格最终只有一个 16 MiB MSR，起点 1 MiB。设置仍作为软件偏好保存，不从已有结构反推。

Windows 在 GPT 初始化时可能自动生成 MSR，现有 H07 证据记录过此情况。产品须把初始化、复采识别自动 MSR、按用户选择准确处理、复采核对末态连接为同一次用户操作；不能只修改请求参数、把中间 GPT 成功当作最终成功，或要求用户另找“完成布局”。必要的准确分段冻结与产品确认仍保留。

若取消后续确认、删除 MSR 被拒绝、采集失败或结果未知，显示“GPT 已初始化，MSR 选项尚未完成/待核对”等实际部分结果，停止后续写入；不承诺初始化会自动回滚。建虚拟磁盘时的自动分区流程也必须沿用同一 MSR 选项，不能被默认布局覆盖。

部分初始化的恢复复用该操作结果/查询对话框：先只读对账，已确认前段结果且原目标仍唯一时，提供“重新准备剩余操作”，从当前事实重新冻结并确认所需 MSR 处理；不再初始化 GPT，不重放旧计划。Unknown 未解时只有查询/对账。不得通过让 GPT 主按钮重新变成“完成布局”补回这一能力，也不新增独立恢复工作区。

### 4.9 执行反馈、拓扑遮罩与相关范围刷新（用户已确定）

- 真实操作准备/执行至核对和反馈期间，右下角显示带转圈的常驻工作消息；按“正在准备/执行/核对/刷新”更新同一条，不按普通消息超时消失、不每次轮询追加一条。不伪造百分比，等待用户确认时明确显示等待确认。
- 实际写入开始后将受影响的编辑页图形盖上黑色半透明遮罩并转圈，持续到相关事实采集、验证和新视图更新完成；准备期间的右下角提示与写后的遮罩各自有明确阶段，不让旧图形继续可编辑。
- 遮罩只覆盖图形区域，不挡住准确目标确认、停止后续、取消未接受计划、结果详情或必要导航。新视图就绪后解除遮罩，恢复仍存在的选中对象；被删除对象清除选择，不误选另一个同名对象。
- 写后正常刷新只采当前操作涉及的相关范围，不自动启动整机硬件采集或每步完整 UI 刷新。范围至少包含受影响对象、完整物理成员、父子关系、模板/实际层、同盘兄弟分区和卷，以及本次核验必需的角色/依赖；盘符占用等仍取得适用全局证据。
- 局部结果带系统、准确范围、时间与完整性；范围内缺席须有本次完整采集证明，未采的非目标对象保留，不当作删除。旧缓存不能补充成真实执行的新证据，不能把局部文档标为整机已全部刷新。
- 不能证明局部闭包完整时，只补取必要证据；仍不足则停下并说明原因。必要全量存储兜底须记录原因，不能成为每次写后的默认路径；手动全量刷新仍可使用。
- 刷新失败时解除无限转圈，保留旧视图并明确标为未刷新，显示重试/详情及适用屏障；结果未知用待核对状态保留写入阻断，不能因停止动画而当作成功。切页/重连后工作状态能从同一操作恢复，不会重复提交。

### 4.10 性能排查与优化（用户已确定）

先测量后定位，不预先把慢归因于 PowerShell、SQLite、UI 或单个安全检查。每种代表操作记录点击→准备、确认后→接受、逐步预检、Windows 写调用、后态采集/核验、终态传回、写后刷新、UI 投影/重绘的耗时，以及采集范围/次数、轮询次数；记录准确目标和 OperationId/StepId，排除用户停留在确认/消息窗的时间。

已确认的代码排查入口：`WindowsRealStorageBackend` 的 Prepare、Preflight、Execute 前采集与后态轮询，`EditorPageBase` 的 2 秒状态查询、完成消息窗之后才启动 `ScanAsync`，以及 `WorkspaceViewModel`/`AgentInventoryCoordinator` 的存档、警告、投影和刷新。当前拓扑采集已是 Storage 用途，但仍不是按目标范围采集；不能把它描述成每次都采完整硬件。以上只是静态路径，尚未有本阶段耗时测量或根因结论。

优先消除无必要串行等待、同一阶段重复采集/投影、可避免的轮询延迟及与本次操作无关的采集；完成提示不应阻塞结果刷新。需要复用事实时证明其范围、时效和阶段一致，执行前实时目标/角色/依赖验证与后态核验不能靠缓存省略。多个操作只合并可合并的显示刷新，不吞掉逐步执行证据。

以改名前后、联机/脱机、小分区创建/扩缩和建池/VD 为代表记录修改前后同条件耗时；低破坏操作优先多次取样并报告中位数/范围，不为了性能数字反复清盘。分别报告 Windows 自身耗时与 WinPool 额外等待，用户对系统磁盘管理器的观察作为对照问题，不能未经同条件测量声称已追平。

性能验收至少证明写后默认刷新已变为相关范围，结果刷新不等待用户关闭完成窗，已定位的额外等待有量化减少且没有安全回归。低破坏路线在同条件前后各取 3 个有效样本，报告中位数和范围；池/VD 路线复用功能验收实际样本，不为凑样本额外重建。不设无依据的总秒数承诺；至少一个已定位 WinPool 额外等待项须有前后量化下降，且其他阶段无未解释的明显退化。未解释慢点继续定位和修复，不通过临时询问用户性能阈值退出本阶段；若确认只能新增范围才能解决，记录具体瓶颈及证据，按第 6.5 节处理。

### 4.11 磁盘编辑与本软件监控联动（用户已确定）

用户已明确：问题来自 WinPool 自己的监控模块，例如修改池后磁盘状态/对象发生变化，监控丢失原目标并持续报告错误。本阶段必须把真实编辑与监控任务、目标集合及告警状态接通；不建设新的测试工作区。

- 以准确系统、目标、OperationId/StepId、冻结计划及 before/verified-after 关联编辑与监控影响。计划已接受且将影响目标可用性时，监控进入“磁盘编辑中，目标预期变化/暂不可采样”的信息状态；准备草稿、尚未接受或已拒绝的计划不能开启此状态。
- 编辑中只将冻结步骤明确预期的目标移除、身份替换、联机状态等变化标记为“编辑相关，待核对”；不提前声称操作成功。目标之外的丢失、无对应步骤的变化及真实健康错误继续告警，不按时间窗口笼统静默整盘。
- 后态核对后，物理盘监控沿用核实后的同一硬件身份；池/VD/OS 磁盘的删除或替换按已执行步骤输出和完整关联更新监控目标。确已删除的旧对象显示“已按编辑操作移除”，有唯一、已核对后继对象时恢复其采样；不能按同名、盘号或盘符猜测新目标。
- 后继对象不唯一、尚未创建或监控未能恢复时，明确显示待核对/需要重新选择目标及实际原因，不无限转圈、不伪造恢复。结构变化已 Verified 不代表重建后所有阶段成功，重建失败仍如实报告。
- 部分完成只认可已 Verified 步骤。取消、失败或结果未知时结束笼统的“编辑中”状态，转为准确的部分完成/待核对；未发生变化的旧目标继续监控，已删除目标不继续按普通丢盘循环告警，未知结果保留适用屏障。
- 同一操作/同一预期变化用信息级结果说明一次，重复轮询不持续弹警告；已有告警仅在对应原因确实消除时解除。完成后继续监控未受影响目标，不重启或重置整场监控来掩盖问题。
- 编辑期间不可采样的区间仍记录真实起止、原因和数据缺口，不伪造样本、不把缺口标作已补齐。与独立故障同时发生时分别呈现，预期结构变化不覆盖真正的数据丢失或设备故障。

现监控主要以 PhysicalDisk/VirtualDisk 的 PDH 通配实例采样，实例名不等同于 Storage 稳定身份。本阶段只接通现有物理/虚拟磁盘指标的准确对应与恢复；池、OS 盘、模板和实际层用于关联核对，不新增独立池/层指标、图表或监控种类。不能仅过滤消息；须核准采样实例与本次准确硬件/VD 的关系，不能用同名/相同PDH实例文本冒充同一对象。无法唯一对应时只暂停该对象的恢复判断，不影响无关采样。

编辑缺口以最小区间记录写入现有监控持久化链：SessionId、系统、准确目标/采样对应、OperationId/StepId、起止、原因和待核对/已核对状态。必要时对现有 monitoring.db 做受检迁移并验证轮换，旧样本不回填；不新增历史查看产品。重启不能凭当前时刻虚构旧缺口结束；端点未知如实留空并说明。未发生采样缺口不创建虚假缺口行。多计划流程按已接受的子计划分别关联，尚未接受的下一段不能开启新静默窗口；已核对删除的旧对象保持“按编辑移除”，不在两段确认间反复报丢盘。

### 6.3 真实编排的固定顺序

1. **新建普通：** 原草稿 → Agent核对当前可证明的条件 → 必要的准确清盘（须在净差异/确认列出）并复采 RAW/零分区 → 创建池并核对唯一输出 → 明确容量查询范围，MAX保持原生意图 → 新计划创建普通 VD → 按偏好执行 GPT及分区布局。自动 VD关闭在池完成即结束；自动分区关闭不得初始化 VD。
2. **新建单 HDD 分层：** 创建池并核对 → 创建准确 HDD 模板并核对 → 明确容量只查询准确未用HDD模板范围，MAX保持原生意图 → 新计划创建分层 VD → 核对实际层关联/用量和规格 → 按偏好布局。池级规格与 VD 层用量在原属性区分开；不能用模板 ID 冒充实际层 ID。
3. **已有池首 VD：** 从准确单成员且无 VD 的池继续上述普通或分层后半段，缺模板时先创建并核验；不能因执行已有池流程自动重写偏好或创建第二块 VD。
4. **显式重建：** 原“解散旧池+新建目标”草稿 → 删除前校验所有已知能力、损失和目标参数 → 删除旧 VD（其实际层随之消失）→ 删除准确旧模板 → 删除旧池 → 复采释放盘 → 必要时独立准确清盘 → 上述普通/分层创建。禁止把模拟逐条分区删除/成员移动机械翻译成额外破坏动作；真实删除依赖按所属对象和完整影响去重。明确容量所需的新池/模板范围只能创建后查询，MAX不查询尺寸范围；最终确认须说明后续仍可能失败，不能宣称删除前已保证完整重建成功。
5. **容量执行：** 明确普通容量读取准确池范围，明确分层容量读取准确未用HDD模板范围，冻结具体 bytes，写前复核范围，不默改已确认值。普通 MAX 保留类型化 `UseMaximumSize=true` 与规范 `SizeBytes=0`，冻结目标、成员、布局和最大容量意图，调用 `New-VirtualDisk -UseMaximumSize`，不查询并解析数值上限、不附 `Size`、不扣减容量或试写搜索。单 HDD 原生 MAX 的两条候选均已实测失败：准确模板与该参数互斥；`WindowsAutomaticHdd` 候选仅生成普通 VD。该候选不是已验证产品能力，保型原生分层 MAX 路径继续按 §10.3 技术调查，不等待用户选择估算策略，不自动重试或改成估算。明确容量继续 `ExactTemplate` 机制。MAX 后态要求 Windows 返回的正容量及准确 VD/OS 磁盘关联一致；分层另须实际 HDD 层、Simple/Fixed/1列/64KiB，不接受普通 VD。核对成功后，自动布局使用实际 OS 磁盘容量形成下一准确计划。新建 MAX 不开放既有对象扩展。
6. **MSR：** 冻结本次选择 → GPT初始化 → 复采 → 识别准确 provider 自动 MSR → 规范化续段 → 复采验证完整末态。false最终无MSR；true最终只有1 MiB起点/16 MiB MSR；独立初始化不追加数据分区。既有严格自动MSR识别、native GPT角色补充核验保留，不能让任意MSR或缺失安全字段进入删除许可。
7. **续段：** 只有前段后态 Verified且关联完整，才将其真实输出作为下一段目标；稳定输入不重填。保留每段 Agent冻结计划的现有确认框；Agent可依据持续WDC授权操作这些确认，不逐段问聊天批准。部分/失败/取消/Unknown停止，不自动执行余步或重放原调用；只读对账后，执行Agent可依据现有授权从已核实现场重新建立准确计划。
8. **草稿与外部变化：** 已Verified的计划内变化可更新基线并保留剩余意图，不能直接 Bind 清空全部草稿；失败时保留输入，原净差异区区分已完成和未执行。与计划无关的基线冲突按模拟现行行为拒绝Apply、保留草稿供查看，放弃后再按新事实编辑，不做自动合并。本阶段不新增跨重启草稿存储；已有持久操作恢复只负责查询/对账，不恢复令牌或自动续写。

### 6.4 范围刷新与监控的固定契约

- 范围由准确系统、OperationId/StepId、before目标和verified-after输出确定，至少含同盘兄弟对象、完整池成员/模板/实际层、OS盘/分区/卷和核验所需依赖；盘符占用、系统角色等必要全局证据单独取得。不能先全量采集再过滤返回值却声称“只采相关范围”。
- 局部批次携带采集时间、范围、每类完整/失败状态、来源身份及关系闭包；局部缺席只有在对应范围完整时才可删除旧事实。保留范围外对象、来源和跨边界关系；失败保留旧事实及时间并标记未刷新。merge不是新的实时安全证据。
- 手动全量、启动采集和写后局部刷新经现有协调门序列化/校验代次，晚到旧结果不能覆盖新事实；当前系统切至模拟时只更新本机后台事实，不能改当前模拟草稿。范围不足先补必要证据，仅记录原因后允许全量存储兜底，不能改成常态全量。
- 页面写后刷新必须真实按范围采集；Prepare/Preflight/写后安全核验另按其证明需要采集，不能为达到性能指标删减完整成员/角色证据。诊断分别统计安全采集与显示刷新，避免把二者混写为一次刷新或宣称完全消除了全量存储核验。
- 监控影响来源必须由Agent已接受计划及步骤状态导出，不能仅由App乐观事件驱动。真正重绑实际采样器/计数器选择与活动目标集合；展示层同样按准确关系更新。旧样本保持旧身份，新对象获得新身份，并保留替换关联；不通过改写历史让曲线假装连续。
- 监控不可采样信息只适用于冻结步骤预期的对象/变化，不能压掉同对象的独立健康故障或未涉及的其他盘告警。确认后继不唯一则标记需重新选择并保留其余监控，不猜测盘号/盘符/名称。Agent重连后从持久步骤复建必要影响状态，无未结束的永久“编辑中”。
- App首次连接/重连以Agent持久记录取得本机未终结/需对账操作，再按准确ID查询并恢复工作状态。现有内存 `RealOperationSubmissionState` 不足时，仅扩充受控只读枚举接口和既有恢复记录；不要求用户重新手输丢失的OperationId，不新增通用历史操作中心。已终结结果与显示刷新失败分开记录，不能因为App尚未刷新就重复执行已成功写入。

### 6.5 连续执行、调度与异常处理

1. 首轮：主代理P3，6.1-Sol负责P2，6-Luna max负责P5；契约冻结后空余槽位可交P6。第二轮：主代理P4/P7，6.1-Sol负责P6/P8（有共享文件则顺序做），6-Luna max负责已完成模块直接回归/文档核对。最多使用实际可用槽位；测试、构建运行树及桌面操作各由唯一执行方串行持有。
2. 工作包下发必须包含本计划节号、固定决定、文件所有权、公共契约、非目标、对应T/H编号和证据要求。子代理不得自行扩大产品范围、降级必交付或跑实盘；默认由主代理或其明确指定的唯一设备负责人操作WDC。
3. 范围内编译/测试/绑定错误、参数传递、超时诊断、只读对账、WDC重试及末态恢复由Agent连续调查修复。令牌过期/UAC/产品确认不是新增聊天授权。测试值按第7.2节确定，不问用户临时起名或挑容量。
4. 同一失败以同一办法重试两次仍无进展，停止盲重跑，读取证据改用诊断/夹具/责任包修复；Unknown期间只读对账，不能把这一规则理解为允许重试不确定写调用。外部工具/UAC权限障碍仅阻断依赖它的验收，其余代码/测试/文档继续，记录精确恢复点；不在后台无限等待人工。
5. 只有扩大到其他磁盘/机器、改变已定产品语义、撤销既有保护，或唯一目标/依赖不能核实且无法安全继续时，才集中询问。问题必须带具体冲突、已完成调查和建议；等待时继续无关工作，不靠等待超时视作同意。没有答案的必交付不能标完成；若所有可独立工作已做完，报告具体阻塞和恢复命令/入口并结束，不挂着反复轮询几小时。
6. 每个完整包更新状态、只提交本任务文件；主代理审阅完整证据，不重复已通过且未受后续修改影响的测试。累计5个未推送提交提醒；不自行推送、打tag、发布，也不升级到迭代10。

### 10.4 用户指定的内置整数 GiB MAX 算法（已验证）

2026-10-09 最新明确决定：真实和模拟共用以下算法；普通真实 MAX 也改用该算法。多层是同一 VD，各层先按自己 0.5×C 创建，C 为奇数时允许临时半 GiB；最终每层整数 GiB。此决定（W09）取代 W08 及前文禁止自动试探／分层 MAX 拒绝门，不改写历史失败与微软侧归因。

固定规则：G=1,073,741,824 bytes，R=4,000,000 bytes（十进制，不是 4 MiB）。A 为准确 provider 上界；模拟无 provider 时先按数据成员、布局／副本／列数／校验列与已知占用折算逻辑上界。C GiB 的严格字节公式为 `(A-R-1)/G`（非负整数除法）；A 不足以得到正 C 时拒绝，不造最小值。模拟直接用 C×G，不试探。真实先尝试 C×G：首次容量失败后每次减 G，首个成功值为 WinPool MAX；首次成功后每次加 G，首个容量失败前的成功值为 WinPool MAX。起点不是硬上限，不能换成二分或旧固定扣减。默认创建最终整数 GiB；显式输入保留原适用 provider 网格校验。

多层严格按冻结层顺序：一次创建全部 0.5×C 的实际层；成功后逐层从该层 C 开始相同步长搜索，已完成的其它层保持原值。Windows actual tier 只支持 grow，因此失败降候选时不得小于已成功 seed，不能执行缩层；不能用 pool template 代替 actual tier。最终 VD 是各层最终容量之和，分区布局仅在搜索核验完成后基于 fresh OS 容量创建。

实施顺序与文件所有权：

1. Domain 共享公式／状态机；移除模拟旧 4 GiB 对齐，统一所有 MAX／建议容量调用，补漏排 HotSpare／Retired／Journal 的路径。覆盖严格边界、布局折算、剩余容量、奇数 seed 与上下方向。
2. Execution 为现有创建合同添加可省略的搜索策略／有序层输入，不改变旧 JSON／hash；Agent 从 fresh 来源冻结 A、C、来源／身份／时间、固定规格、尝试预算、方向及停止策略，原 Apply 的一次产品确认覆盖当前算法搜索，不逐 GiB 再确认。
3. SQLite 事务 CAS 尝试日志保存 op／parent step／ordinal、候选、last success、准确目标、before proof、Preparing／CallIssued、provider receipt 与后态。Agent 持原 mutation gate；CAS 拒绝或未知立即停止。父宏步骤只在最大边界已证明后 Verified；容量拒绝作为 attempt 边界，不是夹带 Failed 的成功 operation。
4. Windows 固定 adapter 每次只调用一次准确 create／grow；每次重采同一身份、完整成员集合、布局与安全角色。成功严格检查 VD／actual tiers／OS、其余层与模板、成员、容量和 RAW 零分区。容量拒绝须有明确 provider 返回、可适用容量错误分类、两轮完整 fresh unchanged 和终态 jobs；参数冲突、权限、超时、transport、部分变化与证据不全不能当容量边界。
5. Query／重启恢复只读，不自动续写或重放 attempt。缺边界时不称已找到 MAX；保留准确残留与未完成草稿。已有对象的任意 MAX 编辑／缩层不因新建搜索而放开。
