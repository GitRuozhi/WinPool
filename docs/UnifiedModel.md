# 统一对象、显示对象与派生属性

状态：2026-09-16 用户已确认的产品设计；模拟层、模拟池改动待代码实施与验证。本文是 Product 的专项设计，适用于本机、导入和模拟系统的统一呈现；不是未排期设计储备。

## 事实与统一呈现

来源事实保存 Windows 或导入文档实际提供的对象、字段、关联、来源、时间及读取状态。统一层根据这些事实合并对象，并生成呈现所需的对象和属性。生成的显示对象不反写来源事实，不伪造 CIM 类、提供程序路径、原始字段或 Windows 关联，不作为真实存储操作目标。

“模拟层”“模拟池”表示没有独立 Windows 对象的假层、假池；“模拟系统”表示可编辑的仿真系统。两者是不同维度。真实本机也可显示模拟层和模拟池；模拟系统中有来源事实的存储层也不因此变成显示用假层。程序内部宜用 Synthetic 等可区分的标识表示假对象，避免与系统来源 Simulation 混淆。

## 模拟层

层类型包含性能层、容量层、模拟层等当前适用类别。热备、退役和未划层是模拟层的名称及成员划分，不能把名称当成层类型，也不能当成 MSFT_StorageTier 对象。

| 名称 | 类型 | 成员含义 |
| --- | --- | --- |
| 热备层 | 模拟层 | 当前池内用途为 HotSpare 的物理磁盘 |
| 退役层 | 模拟层 | 当前池内用途为 Retired 的物理磁盘 |
| 未划层 | 模拟层 | 当前池内未归入已知实际层、且不属于热备或退役的成员 |

层成员关系未采集清楚时，成员仍在未划层显示，并另标明“归属未知”。未划层仅说明当前统一投影不能将其放进已知层，不证明 Windows 中没有层归属，也不证明物理容量尚未分配。

模拟层与实际存储层使用尽量相同的属性结构、属性名称和显示顺序。显示名称、类型、所属池、成员数量等有定义的派生属性；没有来源的容量、物理占用、可用容量、冗余、列数、交错、预配等字段留空，不补零或猜测值。

模拟层不计算层容量。成员磁盘容量之和不是层容量，不用于填充模拟层的容量字段、卡片摘要或导出字段。实际层容量使用该层自己的来源值；缺失时留空，真实零值保留，不以成员容量合计兜底。

管理页中模拟层是正常的层条目：可显示、选中、查看属性，拓扑选择与层属性列表指向同一对象。原始字段区域显示“无原始来源”，不借用成员磁盘或父池的原始字段冒充层来源。成员本身仍可查看各自来源。

显示对象只在统一投影中生成。现有编辑器中的热备、退役用途操作仍针对成员磁盘；创建模拟层显示容器不创建 Windows 层，也不增加新的层结构修改能力。

## 模拟池

| 名称 | 类型 | 成员含义 |
| --- | --- | --- |
| 其它磁盘池 | 模拟池 | 未关联到已知物理或虚拟磁盘的 OS 磁盘，以及没有可靠磁盘归属的分区联合体 |
| 网络磁盘池 | 模拟池 | 当前已采集的网络映射对象 |

本轮仅将现有“其它”和“网络”分组规范为模拟池，不额外创造其他池类别。模拟池使用尽量与真实池一致的属性结构，在管理页可显示、选中；名称、类型和适用成员数量有值，无来源字段留空，原始字段显示“无原始来源”。

模拟池容量不汇总成员容量，容量及可用容量均留空；网络映射可能指向同一后端，合计更不能作为唯一物理存储容量。模拟池不进入实际 StoragePool 来源集合，不具备创建虚拟磁盘、解散真实池等操作能力。

## 联合体与其他软件对象

| 对象或属性 | 软件定义及边界 |
| --- | --- |
| 统一磁盘 | 按明确关联组合 PhysicalDisk、VirtualDisk、OS Disk 和补充来源的视图；不增加物理设备 |
| 分区联合体 | 将具有唯一明确关联的 Partition、Volume、LogicalDisk 组合为一个业务对象；保留来源身份。孤立卷、逻辑盘和网络映射可以在这一层显示，但不能因此获得不存在的分区几何 |
| 虚拟磁盘显示容器 | 为同一池下多块 VD 组织布局，不是额外磁盘，也不是模拟池 |
| 未分配空间节点 | 按磁盘大小与分区范围计算间隙，属于几何派生节点，不是分区表中的分区；与“未划层”不同 |
| 系统占位 | 没有 Computer 来源时供界面保存上下文的占位，不能算作新采集的计算机 |
| 内部身份与元数据 | 内部 ID、系统 ID、来源映射、采集修订、冲突、保留旧事实状态等由软件管理，不是设备原始属性 |
| 含有数据 | 现有判定要求文件系统非空且不是 RAW，并且报告剩余容量小于分区容量；据此作保护性判断，不表示已经遍历文件或实测用户数据字节数 |
| 主网络 | 根据默认路由接口计算的标记，不是原样读取的通用 Primary 属性 |
| 汇总与友好值 | 名称组合、容量单位换算、枚举翻译、计数和内存合计等均为派生表达，保留各自的来源和含义 |

WinPool.GraphicsAdapter、WinPool.GraphicsOutput、WinPool.NetworkAdapter 和 WinPool.Platform 是采集适配器定义的来源名称；其数据来自实际 Windows API/CIM。自定义来源名称不代表设备虚构，亦不能与无原始来源的模拟池、模拟层混为一谈。

来源中已存在的原始池（IsPrimordial）仍是 Windows 提供程序对象，不因为它用于组织未入普通池的磁盘就归为模拟池。性能层、容量层是 WinPool 对适用真实层的友好分类，不能依据名称或介质分组自行补造 MSFT_StorageTier。

## 设备计数与容量统计

明确区分三种数量：来源对象条数、统一业务对象数、显示容器数。同一硬件可能对应多个来源对象；多个来源组合的联合体按统一身份算一次；模拟池、模拟层和布局容器不增加真实设备数。

现有管理页与硬件页的存储摘要共用一套口径，本轮不重新定义统计指标：

| 当前指标 | 统计口径 |
| --- | --- |
| 存储池 | 来源投影中的 StoragePool 数量，包含已采集的原始池；不包含显示用模拟池 |
| 物理磁盘 | 按稳定 ID 去重后的 PhysicalDisk 数量，不额外计入同设备的 OS Disk 视图 |
| 虚拟磁盘 | 已采集 VirtualDisk 数量，不含虚拟磁盘布局容器 |
| 分区 | 当前分区联合体数量，可能包括孤立卷、逻辑盘、网络映射；不是 MSFT_Partition 原始条数 |
| 可访问卷 | 联合体中具有访问路径或盘符的对象数；这是来源属性判断，不保证当前路径实际可访问 |
| 本地存储 | 去重物理磁盘的标称字节数合计；不是池可用容量或冗余后的逻辑容量 |
| 外部存储 | 网络映射的报告容量合计；可能重复同一远端后端，不代表去重后的远端物理容量 |

计数所需来源未采集或失败时，沿用未知状态；成功空集合才显示零。保留历史事实不应被解释成新采集成功。真实层计数若需要呈现，按实际层来源统计；界面层条目数可以包含模拟层，但必须与实际层数区别。

## 验证要求

- 生成、刷新、选择假对象前后，来源事实的对象、字段、关联和序列化内容保持不变；假对象不进入持久化来源或真实命令目标。
- 热备、退役、未划层以及两个模拟池在管理列表、拓扑、属性、导航和来源详情中一致。
- 缺失层归属继续显示归属未知；孤立联合体没有伪造磁盘、偏移或容量。
- 使用层容量与成员总容量明显不同的样例验证真实层显示；模拟层、模拟池容量始终为空，缺失与零不混淆。
- 假对象不增加真实设备计数，选择和刷新不导致同一设备重复；中英文均保持名称与类型的区别。
