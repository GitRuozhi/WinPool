# WinPool 产品方向

**本轮目标为 V0.61。** 第一目标是减少冗余、防御性重复和代码之外的工作，第二目标是性能；本轮已实现采集、Agent 作业、模拟提交和监控链的简化。首稿公开测试版在 V0.70 之前交给不同环境的专门测试人员，当前工作均在开发者环境。执行与候选包状态以[Plan](Plan.md)为准，实测覆盖只看[Quality](Quality.md)。

本文件维护产品语义和范围；模块实现归[Development](Development.md)，逐日结果已原样[归档](Archive/20261017-v061-document-baseline/Product-before.md)。

## 定位与呈现

WinPool 是 Windows 存储拓扑、管理编辑和监控桌面软件。保留 WinUI App＋用户托盘 Agent，不引入 Windows 服务。只读发现真实结构时保留原貌；编辑器只支持部分结构不意味着可以隐藏、合并或改写其它真实对象。

- 管理、拓扑与属性共享池／层／磁盘／分区等对象语义；来源事实与显示派生对象的关系由[UnifiedModel](Reference/UnifiedModel.md)定义。
- 分区、卷与逻辑磁盘在业务呈现中组成同一分区联合体，来源详情仍保留区别。关系不唯一时保留未知，网络映射保持其能力限制。
- 模拟只生成规则范围内的合法配置；未完成输入可留草稿，不能提交为有效系统。模拟估算不冒充 Windows 实测值，不通过旧样例恢复非法组合。
- 中文、英文、主题、键盘操作及响应式布局继续支持。主窗目标最小宽480 DIP，窄窗导航改为菜单；语言和尺寸不改变存储权限。
- 开发者模式默认关闭，启用后显示硬件、测试、开发，硬件在管理之前。隐藏页不可经记忆、快捷键或启动参数绕过；通知和错误处理仍正常工作。
- 硬件页为只读十段报告：Computer、System、Mainboard、CPU、Memory、VirtualMemory、Storage、GPU、Monitor、Network。使用统一对象集合和原值，不额外隐藏软件／间接 GPU，不做隐私裁剪；完整 JSON 可导出。

管理／硬件启动可先显示保存的事实，后台采集后更新；失败保留旧事实和时间。自动／手动采集分别显示进度与结果，历史加载或重连不冒充新采集成功，后台更新不切走用户当前模拟系统。

启动先显示模拟系统目录，按所选系统读取正文；切换过程中迟到的加载结果不会切回旧系统。App 与托盘 Agent 配套运行，连接失败明确呈现，不另启本地写入或采集替代路径。

| Mirror默认列数 | 合格数据成员数除以副本数向下取整、至少1；排除热备／退役。自动建议随成员变化，用户显式输入后不覆盖；既有对象复原到实际值 |
| 层和成员角色 | 同介质有actual层则使用actual，否则选择唯一template；多个无法唯一表达的对象拒绝歧义修改。热备／退役／未划层为派生显示，不伪造Windows来源或容量；角色作用于准确成员，热备／退役不计入数据容量 |
| 动作与表单 | 无具体池时显示新建池入口，有池时解散所选池；按钮与菜单同源。待实施数量打开只读展开明细，预览和Apply同一净差异。结构属性卡可独立折叠，分区卡始终展开；精确尺寸直接读共享代码，见[源码入口](Reference/README.md)，不维护额外尺寸副本 |
| 拖放 | 仅合法目标高亮并接收；Escape／捕获丢失／无效释放不改变草稿。真实执行中及未同步的未知结果保留对应阻止状态 |
| 真实确认 | 一次结构Apply确认完整目标、参数及数据损失；内部阶段按当前事实解析，不逐底层步骤弹新确认。独立磁盘操作仍确认当次业务动作，单名称／盘符Check不另叠确认。取消、失败或Unknown停止后续写入，恢复／重试另建确认计划 |
| 真实作业生命周期 | Agent 接受整批结构目标并记录已完成／剩余阶段。关闭 App 而 Agent 仍运行时，可继续原确认范围内的已接受作业；取消只阻止尚未发出的步骤，已发出调用继续观察。Agent 重启只读核对，不自动续写；重新 Apply 须确认剩余目标。完成才清草稿，中止／未知保留结果与剩余目标 |
| 结构重建 | 删除旧池后不能凭CanPool断言RAW；核实直接OS关联和GPT/MSR，按已确认目标清至零分区RAW后再建池、VD和布局。已有数据的锁定字段不能因草稿显示而绕过 |
| 条带 | 显示条带单元；完整条带为数据KiB＋额外写入KiB。Simple额外为0，Parity为校验量，Mirror标明物理副本量；不明布局留空 |

### 磁盘、分区与文件系统

- 联机／脱机只依据准确来源 `IsOffline`；未知时禁用。RAW可初始化GPT；真实MBR→GPT及真实MBR清空不支持，不以清盘变相绕过。
- 独立清空至RAW不做整盘写零、格式化、初始化或建池。真实目标限未受保护在线GPT普通数据／MSR，或完整成功来源证明的零分区GPT；模拟GPT／MBR按现有规则清除。
- 模拟分区创建使用1 MiB网格，起点向上、长度向下对齐；不足1 MiB拒绝。真实几何与自动新VD布局保留磁盘尾1 MiB，导入已有分区不自动重排。起止位置以整数MiB及自适应单位显示。
- 分区页创建固定GPT BasicData、EFI、MSR、Windows恢复类型，不开放自定义GUID或新建MBR。禁止删除／格式化系统分区；不是对同盘其它对象的一刀切禁用。
- 默认NTFS／64 KiB／快速格式化。快速／完整互斥；真实BasicData可明确不格式化，EFI固定FAT32／4 KiB／快速，Recovery固定NTFS／4 KiB／快速。模拟完整格式不模拟真实介质扫描。
- 模拟NTFS／ReFS／exFAT按规则支持；真实簇大小核对准确卷及所选文件系统的provider能力，默认值不限制其它合法输入。ReFS保留SKU／provider要求，支持合法4 KiB或64 KiB格式选择，扩容另行核验，不开放收缩／完整格式化。研究结论不增加界面警告或额外确认。
- 模拟普通数据分区可扩缩，含模拟系统／启动数据分区，保留分区不扩缩。真实RAW／NTFS普通数据分区在live range内扩缩，NTFS可在线；ReFS仅适用SKU与探针允许的扩容，真实系统／启动卷和exFAT扩缩不支持。
- 扩缩以目标总量 `C×MiB` 为准，扩展显示 `A+B=C`、收缩 `A−B=C`；当前bytes非整MiB不额外前端拒绝，展示余数，Agent核对准确范围。Delete／Format／Offline仍保留运行依赖保护。
- 格式化后以真实文件系统更新当前值和Undo基线，不虚构NTFS回退。资源管理器只打开真实本机、有盘符且存在的路径，模拟禁用。

未支持范围还包括C05与D类真实操作、动态磁盘及其跨区／带区／镜像／RAID-5卷、VHD／VHDX、Manual分配、Journal独立设计路径和自由形式存储命令。操作类别的原范围见[单盘阶段归档](Archive/20261007-real-edit-stage1/Plan.md)，不由本次重构扩大。

## MAX 与真实操作边界

新建使用用户确认的 `WINPOOL-MAX-GIB-1`。设 `G=1,073,741,824`、`R=4,000,000` bytes，`C=floor((A−R−1)/G)`；真实A来自fresh provider上界与物理预算的较小值，模拟A来自按布局折算并扣已知占用后的逻辑余量。C是起点，不是物理最大值保证。

模拟直接采用各层C。真实首次明确容量拒绝且证明无变化时逐次减1 GiB至成功；首次成功则逐次加1 GiB至容量拒绝，保留上次成功值。多层同一VD先按各层0.5×C建立，再按冻结顺序搜索，临时seed可半GiB、最终各层整数GiB；具体调度及已核验边界沿用[算法原决定](Archive/20261012-editor-ui-baseline/Plan.md#104-用户指定的内置整数-gib-max-算法已验证)。不改成二分、固定扣2 GiB、旧4 GiB对齐或原生 `UseMaximumSize`。既有VD／层扩展到MAX仍禁用。

准确模板的离散值或minimum／origin／divisor范围用于明确容量，不套用池的其它网格。容量拒绝需准确后态与storage jobs等证据；普通错误、超时、残留和Unknown不能冒充无变化来推进下一候选。真实分层结果须有actual tier与父链，普通VD不能替代。

本机原生分层MAX接口失败的既定微软侧归因及WDC授权在[AGENTS](../AGENTS.md)维护；这是本机已测路径，不声称所有Windows版本相同。历史实验数值不是产品fallback。

真实写入通过Agent冻结计划、准确成员身份、系统／运行角色、BitLocker和能力核验。写前CallIssued耐久，写后核对实际结果；调用出错不等于未改变。严格只读恢复可关闭已证明无效果或准确识别异常残留的失败，残留保留并另行确认清理；Unknown仍保留写屏障，不重放或重启续写。

查看当前状态不会触发 Windows 重查；需要重新核对未知结果时使用明确的只读重查入口。App 重连读取耐久状态，保留原 operation／job 身份，不通过换 ID 重发写入。

产品确认与开发Agent授权分开：真实模式默认关闭、不持久化同意；UAC或模式开关本身不确认某个操作。开发任务使用已有准确目标授权，WDC不逐项重新询问，两块Samsung禁止成为写目标。V0.61复用有效临写事实与已验证后态，保留上述边界。

## 通知与监控

业务反馈为右下角消息卡，普通消息点击消失，错误点击打开详情；独立重复消息不合并，持续异常只在状态改变时通知。Unknown明确显示未确定，结果与原因在消息及开发页详情查看。进度按同一操作更新，结束后发布结果；关闭消息不解除未知结果屏障。用途／单位／禁用原因使用原生提示。精确触发与参数见[源码入口](Reference/README.md)，不另维护通知表。

开发页仅保留本次App运行最近200条内存消息，双击可复制详情，退出清空；不读取日志文件、不做完整操作审计。测试页仍为路线说明，完整测试／开发／AI工作区留到2.0。

监控记录独立写入 `monitoring.db`，固定1 GiB轮换并用随附7z归档；完成包不自动淘汰，无历史读取／回放。CSV只含活动库。轮换落盘可短暂停顿，崩溃／缓冲耗尽的缺口如实显示，不承诺零丢失。

监控时长使用单调计时，轮换不重置。真实编辑的未知端点、历史缺口保留；fresh身份绑定和所需实际计数器样本恢复后才能标记恢复，未知操作不自动解锁。监控关闭时特定历史pending不作为当前告警，但诊断不删除。没有独立OS计数器的池成员不能借用VD计数器伪造独立数据。

采样率仍可选择 0.2–20 Hz；样本以有界批次推送，图表与告警使用同一 App 缓存。重复批次不重复应用；断流或序列缺口后重同步最新窗口，已知缺失区段断开显示。实时显示缺口与持久化未保存样本分别报告，池成员缺独立计数器显示为不支持该角色的采样。

7Z设置只提供默认／自定义路径，默认随包，取消选择保留原值；不检测能力、不下载／安装工具，自定义失败不静默回退。数据位置与7Z项的“打开路径”只打开目录。
