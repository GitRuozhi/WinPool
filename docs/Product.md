## 定位

WinPool 是 Windows 存储结构管理软件，以统一桌面界面呈现存储拓扑、监控、管理和可审阅的编辑。它不创造 Windows 无法实现的存储结构，不以界面能画出来作为配置合法性的依据。

- 清楚表达池、层、物理磁盘、虚拟磁盘、OS 磁盘、分区、卷和网络存储之间的关系。
- 同时提供完整拓扑和聚焦的操作工作区；操作必须明确、类型化、可预览、可验证。
- 保留真实只读采集、模拟编辑和受控真实编辑；模拟只允许已知合法且在支持范围内的配置，真实写入必须经过准确目标核验和 Agent 冻结计划确认；信息不足或规则未覆盖时不默认放行。
- 容量采用有依据的简化估算，以适用的真实采集值为准；估算和推导信息必须可辨认，不能伪装成 Windows 实测值。
- 保持软件中英双语、主题、键盘操作、高对比度和响应式布局。开发文档取消双语不改变软件功能。
- 当前不承诺公共 SDK、插件 API、数据库或 IPC 对外兼容契约。

当前产品版本为 V0.58；公开能力见 [简体中文用户说明](../README.zh-CN.md)。结构页提供净差异动作面板、MAX 容量意图和整批预检查；分区页仍及时提交。已完成的单盘真实修改第一阶段通过了 H01–H11 场景、最终 GPT/NTFS MAX 布局和工程门。该历史阶段收口时 WDC 布局为 GPT、1 MiB 起点/16 MiB MSR、其后 BasicData；E: 为 64 KiB NTFS 卷 `WinPool_Test`。H10 验证了 HDD 模板选择及由其创建实际分层虚拟磁盘；H11 验证了 ReFS 扩容后的内容哈希并确认收缩入口禁用。

V0.59 阶段已将新的单盘真实操作接回现有结构页和分区页，范围包括普通或明确容量的单 HDD 分层 VD 创建、明确发起的删除重建、独立清空至 RAW、RAW 初始化 GPT，以及按 Agent 实时范围扩缩 RAW/NTFS 数据分区。本轮普通原生 MAX 以 `SizeBytes=0`／`UseMaximumSize=true` 冻结并完成创建，Windows 实际返回 VD 与 OS 磁盘均为 3,999,688,294,400 bytes，随后完成 GPT、规范 16 MiB MSR、NTFS／64 KiB 数据分区与 `WinPool_V059_Data`／`W:`，见[原生布局证据](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Ordinary/native-maximum-layout-readonly-proof.json)和[断言](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Ordinary/native-maximum-layout-assertion.json)。[原 Agent 托盘正常退出](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Final/ordinary-native-max-observed-exit-result.json)确认 App／Agent 均 exit 0。已有空池首块普通 32 GiB、普通 MAX 意图重建与单 HDD 分层明确 32 GiB 创建、布局、重建的历史证据仍有效，不能外推分层 MAX。修正前 B5 曾通过物理 WDC 联机 GPT、规范 MSR、NTFS／64 KiB 最大整 MiB 数据分区、`WinPool_Test`／`E:` 且无 concrete pool／VD，以及 Samsung 限定范围 0 变化、监控 0 缺口；4 项共享 Primordial 调整另存。本轮新写入后的[独立原生／full对账](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Engineering/final-protected-comparison-review.json)也已通过：WDC物理盘在线GPT、1 MiB起点／16 MiB MSR、17 MiB起点／4,000,767,279,104-byte最大整MiB数据分区、NTFS／64 KiB／`WinPool_Test`／`E:`，无concrete pool或VD；Samsung限定结构范围0变化／0证据缺口，4项共享Primordial调整单独保留。准确成员返回的[原UI局部刷新复验](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Engineering/scoped-release-original-ui-review.json)通过，未扩查Samsung兄弟盘。[普通重启及托盘退出](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Final/normal-restart-exit-exit-result.json)两进程exit 0，[审计](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Final/after-normal-restart-readonly-audit.json)确认偏好与B0一致、RealOff／MonitorOff、监控设置20 Hz、Accepted 214／CallIssued 271不变、无未终结操作。

2026-09-27 用户正式进入本机真实磁盘修改第一阶段；该阶段已完成并归档。真实池创建须证明当前池成员和磁盘角色拓扑完整且目标唯一；已知布局能力在删除旧对象或清盘前预检，计划准备与每步写入时还要实时复核目标身份、系统角色、BitLocker、运行依赖及适用能力。需要改变既有池/虚拟磁盘布局时，用户须在现有结构页明确提出删除重建；计划列出准确对象与数据损失，并由产品逐项确认，不会因普通更新失败自动转入重建。真实批量中途失败或结果未知时停止后续写入，只读对账，不重放不确定调用，后续恢复或重试须另建计划。现有虚拟磁盘或层的 MAX 扩展没有可靠 provider 上限依据，保持禁用。真实 MBR→GPT 转换 C03、C05 与 D 类操作仍禁用；多盘 Mirror/Parity、混合介质分层和新建 MBR 不在当前支持范围。

真实普通布局新建 `MAX` 保留 Windows 原生 `UseMaximumSize` 意图到冻结计划和固定调用，由 Windows 决定实际容量；不预先解析、取整或扣减为 bytes。明确 GiB 才读取准确池的 provider 范围，单 HDD 分层还须满足与尚未用于 VD 的 HDD 模板范围的交集。两种模式都须 fresh 核对准确目标、布局能力、成员及安全角色；普通 MAX 成功后核验本次输出对应的 VD／唯一 OS 磁盘及一致容量，再据此准备自动分区几何。分层目标额外要求唯一 actual tier、完整规格与准确父链，不能把普通 VD 当作分层成功。本机准确 `StorageTiers` + `UseMaximumSize` 被以 48010 拒绝；另一次 `MediaType HDD` + `UseMaximumSize` 虽返回 VD，却没有 actual tier，故不满足分层目标。不能再声称 WindowsAutomaticHdd 保证自动创建实际层。新分层 MAX 已在草稿生成任何删除或创建动作前拒绝，Prepare／Preflight、适配器及固定脚本也在调用前拒绝；明确容量分层与普通原生 MAX 保持可用。实际 API 冲突的最终处理仍待用户答复，不泛化为所有 Windows 的永久边界。先前显式 bytes 失败不证明原生开关不可用。不静默改小容量、改布局、失败后切换调用路线或通过试写探测；默认普通／MAX 保持不变。

真实调用出错或后置条件未核验时不能直接认定无变化。严格只读对账可在准确冻结身份、两轮 fresh 完整证据和终态 storage jobs 等守卫下，将已证明无创建残留的结果收口为 Failed／ObservedNoEffect；准确识别到不符目标的真实残留时，则只能记录 Failed／ObservedUnexpectedEffect，保留残留及已调用证据，不能标为 NoEffect 或 Verified。本轮后一条[独立对账审核](../artifacts/test-results/20261009-v059-native-maximum-81428d1f9c2249bfbeb4d30c21b08219/Engineering/closed-query-recovery-host/root-verification-independent.md)已通过，随后由原界面查询该终态并另行确认清理。失败不是创建成功，恢复、清理或改变目标仍须准确的新计划。

V0.5x 按具体计划逐项引入经验证的真实创建、修改、删除、格式化、扩缩容等操作。只读采集可继续改进。真实操作不要求在一个版本中覆盖所有 Windows 存储功能。

真实操作须保留准确目标校验、类型化预览、审计及执行后重新采集验证；自由形式存储命令不进入产品。授权区分：

- 开发 Agent：核对已有用户授权是否覆盖准确目标和操作范围。2026-10-07 用户明确批准本机 WDC 全部操作并确认 E: 无有效数据，持续授权记录见 [AGENTS](../AGENTS.md)；范围内不再逐操作向用户聊天索批，仍须走产品内当次计划确认。其它磁盘，包括本机两块 Samsung，仍禁止成为写入目标。
- 产品用户：当前会话显式选择本机真实修改选项，授权当时产品已支持的受控操作。不得预选或持久化同意；UAC 和 Real 模式本身不是授权。

## 分区联合体与采集边界

统一层中的模拟池、模拟层、联合体、显示容器和设备计数按 [统一对象与派生属性](UnifiedModel.md) 维护。2026-09-16 已确认模拟层（热备层、退役层、未划层）及模拟池（其它磁盘池、网络磁盘池）为纯显示派生对象；无来源字段和容量留空，管理页可选且原始字段显示无原始来源。实施与验证见[统一对象阶段归档](Archive/20260916-unified-synthetic/README.md)。

自动采集的存储、完整硬件两个阶段，以及两页手动刷新，都在窗口内显示“采集中”和最终的“采集成功”或“采集失败”通知；不是阻塞确认对话框。完成或失败后移除对应的采集中提示。自动和手动进度互不覆盖，同一次手动刷新不因 Agent 事件重复弹出。加载历史或重连补读不冒充新的采集成功。

管理页与硬件页启动先显示上次保存的本机事实，不等待 Agent 连接。每次 Agent 启动自动依次执行一次存储采集和一次完整硬件采集，每阶段保存后主动回报 App；历史存在也不跳过。App 晚连接或重连时补读最新结果，采集失败保留历史。管理页刷新手动触发存储采集，硬件页刷新手动触发完整采集，两者更新同一本机事实文档，后台回报不切走用户选中的模拟系统。

分区、卷和逻辑磁盘在产品中是同一层联合体。管理属性只有“分区”分类；拓扑、属性、选择和导航都使用联合体身份。原始来源事实保留 Partition / Volume / LogicalDisk 的区别，来源详情用于追溯字段，不生成额外业务层。网络映射也在此层显示，保留网络访问能力限制。物理磁盘与 OS 磁盘的来源组合仍属于磁盘层，不并入分区。

只按明确且唯一的关联组合来源。缺少关联的文件系统或逻辑盘继续显示在“其它”下，未知所属磁盘、偏移和分区容量保持未知，不创建占位磁盘。分区范围容量与文件系统容量不相等时分别展示。字段按语义选择来源，正常补充值不再被旧缺失标记遮盖；冲突保留来源证据，显示优先来源值。

存储刷新包含 Win32_DiskDrive、分页/转储角色和 Windows 版本补充，不依赖完整硬件刷新。管理页系统信息只保留存储上下文，CPU 和内存留在硬件页。不支持的可选电池类显示不可用；实际查询失败仍如实保留。失败刷新保留旧事实及其时间，重复刷新不累积失效状态行。

## 存储编辑边界

这些是产品创建范围，不是对 Windows 对象模型的重新定义。发现已有系统时保留其真实结构；不因编辑器只支持一种结构就丢弃其他对象、强行合并或修改采集结果。

| 项目 | 当前有效决定 |
| --- | --- |
| 编辑页面 | 保留存储结构编辑和磁盘分区编辑两页；管理页负责完整检查，结构编辑页不扩成第二个检查器 |
| 建池与虚拟磁盘 | 一个池最多新建一块虚拟磁盘；模拟可提交没有成员和虚拟磁盘的空池，真实无成员池只保留草稿，有合格的单盘成员才可创建。现有结构页可选择普通或单 HDD 分层布局；单盘 HDD 模板用于创建对应的分层虚拟磁盘。池、虚拟磁盘和分区布局分别进入类型化计划；模拟整批原子保存，真实按确认后的计划逐步执行，中途失败保留部分结果并对账，不承诺整批回滚 |
| 已有多虚拟磁盘 | 如实读取与展示；支持范围内可减少，不创建第二块，不因读取而自动“归一化” |
| 自动创建 | 自动创建虚拟磁盘（AutoVD）与自动创建分区（AutoPart）是独立、已保存的软件偏好，不从当前所选对象结构反推，也不因切换偏好而改动已有对象或草稿。AutoVD 控制新池是否自动创建虚拟磁盘；AutoPart 控制新虚拟磁盘是否继续 GPT 自动布局，单独开启 AutoPart 不会代替创建虚拟磁盘。默认两项开启。分区页可创建 BasicData、EFI、MSR、Windows 恢复四种固定 GPT 类型，不开放自定义 GUID 或 MBR 创建 |
| MSR 与自动布局 | “创建 Microsoft Reserved Partition”是独立的已保存偏好，默认开启。开启时新 GPT 布局在 1 MiB 起点放置规范 16 MiB MSR；关闭时不创建 MSR，自动 BasicData 从 1 MiB 起点布局。RAW 初始化、提供程序自动创建 MSR 后的规范化及新虚拟磁盘自动布局都按该偏好核对；初始化 GPT 本身不等同于自动格式化或建池 |
| 磁盘状态与分区表 | 分区页用一个联机/脱机状态按钮显示并切换磁盘状态；只有准确来源事实返回 `IsOffline` 时才允许操作，未知或缺失状态禁用。分区表按钮按状态提供动作：RAW 可初始化为 GPT，GPT 显示已初始化，MBR 在模拟中可转换；真实 MBR→GPT 转换 C03 明确拒绝，不通过清盘绕过 |
| 清空至 RAW | 与初始化和分区表转换分开的单独操作。模拟 GPT/MBR 按原规则清除分区及关联卷至 RAW；真实清空仅支持准确在线、未受保护的 GPT 普通数据/MSR 分区，或完整、成功的来源事实明确证明零分区的 GPT。真实 MBR 清空不支持；未知或失败事实不能当作空盘。它不做整盘写零、初始化、格式化或建池；真实操作的数据损失进入 Agent 冻结计划确认 |
| 单盘真实结构与池重建 | WDC 实测确认 `CanPool=true` 不代表磁盘为 RAW：删除旧池后 Windows 曾保留 GPT 和自动 MSR。若改动要求重建，须在现有结构草稿中明确移除旧池/虚拟磁盘/模板；先预检当前已知布局支持，再按冻结计划逐项删除，复核物理盘/OS 磁盘身份并独立清盘至零分区 RAW，然后创建新池/虚拟磁盘并配置所选 GPT 布局。取消、失败或结果未知会停止后续步骤；只读对账，不自动确认或重放 |
| 模拟分区网格 | 新建分区起点上取整到 1 MiB 网格，长度取整到正整数 MiB；输入默认占满选中空隙的对齐上限，容量不足时说明原因并拒绝。空盘初始化勾选 MSR 时在 1 MiB 起点放置 16 MiB MSR，终点为 17 MiB；已有导入分区不为匹配网格而改写。界面起止位置固定以 MiB 显示并附自适应单位，具体判定见[模拟规则表](DesignTables/SimulationRules.md) |
| 系统分区保护 | 禁止删除、格式化系统分区；不因磁盘包含系统分区，就禁用整块磁盘及其他分区的所有操作。改名、容量等已支持操作仍按各自适用规则判断；真实写入还须经过本阶段的目标、关联和安全核验 |
| 分层 | 以性能层和容量层为主要路径，按介质提供分组和编辑；模板对象与其创建出的实际分层虚拟磁盘分别核对。当前原界面已验证单 HDD 模板派生的 32 GiB 实际 tier／VD、自动布局及重建；实际 tier 与模板身份分开，顶层 VD 不返回普通布局字段时须核对实际 tier 的准确父链和完整规格。分层原生 MAX 两条候选均未满足目标，新请求已在删除或创建前拒绝；实际 API 冲突的最终处理待用户答复。现有虚拟磁盘或层的 MAX 扩展仍因缺少可靠 provider 上限而禁用 |
| 备用与退役 | 以模拟层类型显示，名称为热备层、退役层；未归入已知层的成员显示在未划层。仅为统一投影，管理页可选，不生成 Windows 来源层，不以成员容量充当层容量；详细语义见 UnifiedModel |
| 提交方式 | 结构页：成员和非名称参数属于同一次草稿；已有对象改名按 Enter 独立及时提交，不受结构撤销/放弃影响；只读“待应用动作”显示合并后的净差异和规则原因，预览与应用使用同一计划。分区页：格式化与卷属性及时生效，每次动作单独提交并弹出成功或失败 |
| 真实确认与重建 | 每项操作以类型化冻结计划预览，并由产品用户当次确认；已有名称 Enter 发起独立计划，失焦不提交。不能原地修改的布局须在原页同一草稿显式删除并重新创建，按净差异分别确认类型化计划，列全对象和数据损失；不增加独立重建入口，不能由普通更新失败自动转入重建。部分完成或结果未知时停止后续写入，只读重新采集对账且不重放不确定调用；恢复或重试另建计划 |
| 参数 | 提供适用的交错、列数、冗余、容量等参数；已核验的单盘真实路径为 `SimpleFixed`、1 列、64 KiB interleave。新虚拟磁盘容量可输入 GiB 或选择 `MAX`；默认普通布局／MAX。普通原生 MAX 已保留 `UseMaximumSize` 并通过实际容量核验；分层 MAX 策略待定，不能以普通成功替代。明确 GiB 读取准确池范围，单 HDD 分层再与尚未用于 VD 的 HDD 模板范围取精确交集，冻结明确 bytes 并在写前重核。共同范围不保证最终 provider 调用成功。既有虚拟磁盘或层的 MAX 扩展仍禁用。模拟层容量可按适用路径输入 GiB 或选择 MAX，预配类型当前仅支持 Fixed；不能依据控件选项判定所有组合都受 Windows 支持 |
| 文件系统 | 模拟格式化支持 NTFS、ReFS、exFAT；NTFS 为默认。真实创建/格式化默认走 NTFS、64 KiB 簇、快速格式化；其他 NTFS/exFAT 与格式化方式组合只有在当前 provider 能力和准确计划都允许时才可用。ReFS 仅在明确适用的 Workstations/SKU 与现场 provider 探针通过后支持 64 KiB 快速格式化和扩容，不开放收缩或完整格式化。H11 已核对指定卷扩容前后内容哈希一致 |
| 格式化方式 | 分区页的快速与完整格式化开关互斥且始终选中一项，默认快速；方式进入模拟操作计划和预览。真实 BasicData 新建另有“不格式化”选项，计划不含格式化步骤；EFI 固定 FAT32/4 KiB/快速，Recovery 固定 NTFS/4 KiB/快速，数据分区参数按本阶段组合放行。模拟完整方式不代表真实介质扫描或真实格式化，阻止条件见[模拟规则表](DesignTables/SimulationRules.md) |
| 资源管理器 | 只对本机真实卷、有盘符且路径存在时打开；仿真禁用 |
| 扩缩容 | 已实现普通数据分区的模拟扩展/压缩，包括系统/启动数据分区；不开放保留分区扩缩。模拟估算不冒充 Windows supported-size。真实 RAW 分区和 NTFS 普通数据分区按 Agent 实时 provider 范围扩缩，NTFS 可在线操作；界面用两行公式 `A + B = C` 扩展、`A − B = C` 压缩，A 为当前容量，B 为变化量，C 为目标总容量，两行分别显示 MiB 和自适应单位，计算保留一个精确 bytes 目标值。Agent 在准备和执行前重读准确目标范围；没有整 MiB 目标或实时范围失效时拒绝。ReFS 仅在明确适用的 Workstations/SKU 与现场能力探针通过后开放 64 KiB 快速格式卷扩容，不开放收缩。启动/系统卷及 exFAT 真实扩缩不在当前支持范围 |
| 排除项 | C03、C05 与 D 类真实操作、多盘 Mirror/Parity 等冗余、混合介质分层、直接成员迁移、既有虚拟磁盘/层的 MAX 扩展（缺少可靠 provider 上限）、新建 MBR、不推荐的 256 KiB interleave 组合、动态磁盘及其跨区/带区/镜像/RAID-5 卷、VHD/VHDX 功能、Manual 分配、Journal 作为独立设计路径、第二块虚拟磁盘、自由形式命令 |

历史设计中的“单盘 Mirror 仅警告仍放行”等例外不再生效。每种配置必须有可适用的 Windows 规则依据；不能以旧方案或旧测试要求恢复非法结构。未完成的表单可暂留界面，不得提交成有效模拟系统。

结构合法性和经验风险是两类规则：合法不等于推荐；有风险的受支持配置仍需明确警告或既定限制。研究结论必须保持：

```text
64K interleave + 64K NTFS cluster = current tested recommendation.
Windows 11 has not yet received equivalent testing because current storage hardware prices and the author's practical budget do not allow a second full test platform.
```

64K+64K 在当前测试中稳定；64K+256K 出现两阶段 NTFS 损坏；256K+64K 已发生失败，当前不推荐，不承诺未来复测；256K+256K 出现直接 NTFS 损坏、Event 55。256K interleave 不作为静默默认值。这些证据不等于其他文件系统或平台已受同等验证。

## 1.x 范围与架构约束

主窗口继续支持 480 DIP。宽度不足时导航收为带本地化名称的菜单，列出当前模式允许访问的页面；标题栏保留本机/模拟系统选择和真实编辑开关，不因隐藏标签改变执行权限。

1.x 聚焦拓扑、管理编辑、监控、设置、数据安全和交付质量。“测试”页保持路线说明；开发页当前只显示轻量的“消息列表”，已移除故障日志路径和操作按钮，既有验证范围见 [Quality](Quality.md)。完整测试工作区、外部基准执行、开发者和 AI 工作区留到 2.0。开发者模式默认关闭；启用后才显示硬件、测试、开发三页，硬件在管理之前。关闭后不能通过导航、快捷键、记忆页面或启动参数进入隐藏页；正常通知、异常处理和上下文帮助仍可使用。

保留 WinUI App + 每用户可见托盘 Agent 两进程，类型化命名管道和 Agent 单 SQLite 写入方；不引入 Windows 服务。详细技术所有权归 [Development](Development.md)。标题栏以存储系统下拉框显示和切换当前本机或模拟系统。保留现有拓扑布局。只读硬件页不显示重复页标题，以 Computer、System、Mainboard、CPU、Memory、VirtualMemory、Storage、GPU、Monitor、Network 十段纵向报告显示友好值，Memory 总体与模组分段，每段可横向查看多设备。刷新和导出按钮左对齐，不显示采集完成时间。管理页和硬件页的项名列均按内容自动宽度并设比项值更窄的上限；硬件页项名保持在横向滚动区外。设备列按内容自动宽度并设上限；单击项值选中同一设备组并将该组滚动到值区中央，组内文本可选择复制，不弹出原始字段对话框。两页属性表的缺失字段显示空白，不以破折号占位；未知、失败和真实零值继续按各自既有口径呈现。页面操作、即时反馈和各报告段使用同一纵向滚动。设备列与统一模型中的同类对象保持一致，界面只决定显示哪些字段，不按来源或设备属性隐藏对象；不隐藏软件 GPU、间接显示适配器或 Monitor。间接显示适配器在统一层按 D3DKMT 类型标志识别并使用显示侧名称，不冒充其关联的物理渲染 GPU。网络对象在统一层采用 `MSFT_NetAdapter` 的 `ConnectorPresent -or InterfaceType -ne 0` 条件，Storage 按 WinPool 管理页口径且不增加硬件页专用过滤。本机可独立刷新，当前系统可导出完整 JSON。模拟系统的非存储硬件只读。Storage 与管理页共用摘要及未知/失败/零值口径。采集、显示、缓存与导出保持原值，不做脱敏或隐私裁剪。

## 通知、上下文帮助与消息列表

业务提醒统一使用右下角固定宽度、高度随内容变化的单层消息卡片，不另设通知横幅，不显示“详情”或“关闭”按钮。普通消息短时间自动消失，点击后向右退出；错误消息较长时间自动消失，点击后向右退出并打开错误消息对话框，提示进入开发页消息列表查看详情。独立重复消息不合并。持续异常只在状态变化时通知，正常轮询不重复提醒；消息消失不代表问题解决。进度结束后清除，提交结果未知必须明确说明，不能当作失败或成功；模拟结果注明所属模拟系统。触发与记录条件见[消息卡与消息列表触发表](DesignTables/Notifications.md)，验证范围见 [Quality](Quality.md)。

控件用途、参数含义、单位、快捷键和禁用原因使用简短原生悬停提示；灰色禁用控件仍须能显示原因，不在控件外堆放灰色解释文字。对象及来源详情保留显式查看与复制入口，不自动弹出整份硬件报告。说明复用统一模型的来源、未知、失败和估算口径，不重新计算事实。

开发页没有页面大标题，左上消息列表仅展示最近 200 条本次运行内存消息；不显示表头，单行条目按时间、级别、来源、信息标题四列排列，标题列只取消息标题。紧凑消息行的文字垂直居中，悬停和选中状态提示可操作；双击条目在界面中央打开只含可复制文本框的详情，详情有不透明背景而周围界面变暗，点击对话框外关闭。三个子区域可拖拽调整，右上和下方功能区暂留空，下方小字提示人工智能入口正在开发。页面不显示列表区域标题、Diagnostics 路径、旧说明或清空/复制按钮，不读取故障日志文件；“消息列表”仅用于控件自动化名称及文档称呼。消息只存内存，退出 App 后清空。关闭即时通知不删除记录，开发者模式不影响 App 运行期间的消息缓存；不补采 App 关闭期间事件，不新增日志文件读取、事件数据库、搜索、文件导出或完整用户操作审计。悬停、选择和普通进度变化不进入消息历史。

## 监控记录与状态提示

监控原始记录独立写入 `monitoring.db`，达到 1 GiB 后轮换；旧库后台以 7z 高压缩归档，完整性与内容哈希验证通过后不保留原始封存库。历史不自动删除，空间不足不得靠淘汰旧归档继续记录。软件不提供监控历史读取或回放。正常轮换保持采样连续，异常需如实显示记录延迟、暂停或缺口。

监控页左上角运行时持续显示本次运行时长，未运行显示“已停止”；正常诊断隐藏，异常进入右下角消息卡和本次运行记录，不再占据左上角横幅。轮换不重置时长，正常缓存淘汰不作为丢样警告；状态恢复记入记录，真实记录缺口不标作自动恢复。

历史编辑缺口的未知端点保留，不因停止或重启补写结束时间。对于已核验、未调用或历史端点未知的受支持物理盘／VD，开启监控时须由 fresh 完整来源唯一绑定当前设备，随后以各请求计数器家族的真实样本确认恢复；操作结果未知或当前调用中的目标仍暂停。监控未运行时，仅 `PendingVerification` 且原因为 `monitor.edit.recovered_endpoint_unknown` 的历史状态不作为当前告警；其他 Pending／NeedsSelection 和活动监控异常仍报告，诊断目标与历史缺口不删除。

设置页不提供“数据容量限制”，轮换阈值固定为 1 GiB。无标题的工具卡放在通用卡之后，当前只有 7Z 一行，按“默认/自定义”下拉选单、“打开路径”、路径文字顺序排列；下拉框与其它设置项同宽并对齐，不提供单独浏览按钮。默认使用便携包随附组件，选择自定义即打开文件选择器，已有自定义也可重新选择；取消不改变原配置。数据存储位置下拉选单后也提供“打开路径”和路径文字，打开当前实际数据目录；7Z 的按钮打开当前所选工具的所在目录，不启动工具。设置项简称“创建微软保留分区”，行为不变。设置页点击按钮配有图标。只检查工具文件存在，实际调用错误如实报告，不进行独立可执行性或能力探测，不静默回退自定义路径。采用最小进程调用器与 7z 适配器，不恢复旧工具管理系统，不提供安装、更新、下载或搜索。

监控轮换已在 V0.53 实现，执行与证据见[监控轮换阶段归档](Archive/20260921-monitoring-rotation/README.md)；后续设置页调整及验证见 [CHANGELOG](CHANGELOG.md) 和 [Quality](Quality.md)。CSV 仅覆盖当前活动库，不跨归档补齐会话；轮换期间落盘可短暂停顿，崩溃或缓冲耗尽不承诺零丢失。异常关闭只影响呈现，不删除数据或取消后台恢复。

## Windows 与交付

2026-09-16 确认：只提供便携版与安装版两种交付方式，两者使用同一产品版本并具有相同功能。相关页面统一由软件内置开发者模式控制，不再划分 Standard、Preview 等功能版本，不建立按发行版本区分的功能或数据模型。交付储备及实施前待核对项见[便携版与安装版交付方案](Design/WinPool-Distribution-Plan.md)。

最低受支持系统为 Windows 10 22H2 x64，主要平台为 Windows 11 24H2 / 25H2 x64；这是软件支持范围，不意味着所有 SKU/提供程序均可创建同一存储配置，也不意味着研究已经完成 Windows 11 等价测试。编译 TFM 不等于最低支持系统。ARM64、x86 和更早系统不属于公开保证。

当前只交付完整目录形式的无打包、自包含 x64 便携版。数据默认位于 `%LocalAppData%/WinPool`，可显式选择可写的程序旁 `Data`。签名 MSIX 在 V0.8–V0.9，Store 在 V1.0 完成之后；目前没有已发布的 MSIX 或 Store 页面。安装方式不增加存储权限，不改变进程架构；账号、包上传和正式发布另行授权。
