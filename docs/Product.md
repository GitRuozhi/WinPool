# WinPool 产品方向

本文件是当前产品行为、边界和路线的中文权威。2026-09-10 用户决定已覆盖相冲突的历史设计。当前实现为 V0.55；统一事实、硬件页与模拟编辑升级见 [V0.52 归档](Archive/V0.52/README.md)，十段硬件报告与 KS 能力接线见[硬件报告执行归档](Archive/20260915-hardware-report/README.md)。已知限制见 [CHANGELOG](CHANGELOG.md)。

已有对象在名称输入框按 Enter 独立提交改名并即时生效；普通失焦不提交，不增加保存名称按钮。改名不参与结构撤销或放弃；名称只用于显示，身份与关联使用可靠 ID。尚未创建对象的名称属于创建参数。历史修复与验证范围见 [CHANGELOG](CHANGELOG.md) 的 2026-09-11 记录。

## 定位

WinPool 是 Windows 存储结构管理软件，以统一桌面界面呈现存储拓扑、监控、管理和可审阅的编辑。它不创造 Windows 无法实现的存储结构，不以界面能画出来作为配置合法性的依据。

- 清楚表达池、层、物理磁盘、虚拟磁盘、OS 磁盘、分区、卷和网络存储之间的关系。
- 同时提供完整拓扑和聚焦的操作工作区；操作必须明确、类型化、可预览、可验证。
- 保留真实只读采集和模拟编辑，模拟只允许已知合法且在支持范围内的配置；信息不足或规则未覆盖时不默认放行。
- 容量采用有依据的简化估算，以适用的真实采集值为准；估算和推导信息必须可辨认，不能伪装成 Windows 实测值。
- 保持软件中英双语、主题、键盘操作、高对比度和响应式布局。开发文档取消双语不改变软件功能。
- 当前不承诺公共 SDK、插件 API、数据库或 IPC 对外兼容契约。

## 当前能力与真实操作边界

当前实现版本为 V0.55；公开能力见根目录 [README](../README.zh-CN.md)。结构页提供净差异动作面板、MAX 容量意图和整批预检查；分区页仍及时提交。不包含任何真实存储写操作。

V0.5x 才可按具体计划引入选定的真实创建、修改、删除、格式化、扩缩容等操作。只读采集可继续改进。真实操作不要求在一个版本中覆盖所有 Windows 存储功能。

未来真实操作保留准确目标校验、类型化预览、审计及执行后重新采集验证；自由形式存储命令不进入产品。授权区分：

- 开发 Agent：每次实际变更前取得开发者对准确操作和目标的明确批准。
- 产品用户：当前会话显式选择本机真实修改选项，授权当时产品已支持的受控操作。不得预选或持久化同意；UAC 和 Real 模式本身不是授权。

## 分区联合体与采集边界

统一层中的模拟池、模拟层、联合体、显示容器和设备计数按 [统一对象与派生属性](UnifiedModel.md) 维护。2026-09-16 已确认模拟层（热备层、退役层、未划层）及模拟池（其它磁盘池、网络磁盘池）为纯显示派生对象；无来源字段和容量留空，管理页可选且原始字段显示无原始来源。实施与验证见[统一对象阶段归档](Archive/20260916-unified-synthetic/README.md)。

自动采集的存储、完整硬件两个阶段，以及两页手动刷新，都在窗口内显示“采集中”和最终的“采集成功”或“采集失败”通知；不是阻塞确认对话框。完成或失败后移除对应的采集中提示。自动和手动进度互不覆盖，同一次手动刷新不因 Agent 事件重复弹出。加载历史或重连补读不冒充新的采集成功。

管理页与硬件页启动先显示上次保存的本机事实，不等待 Agent 连接。每次 Agent 启动自动依次执行一次存储采集和一次完整硬件采集，每阶段保存后主动回报 App；历史存在也不跳过。App 晚连接或重连时补读最新结果，采集失败保留历史。管理页刷新手动触发存储采集，硬件页刷新手动触发完整采集，两者更新同一本机事实文档，后台回报不切走用户选中的模拟系统。

分区、卷和逻辑磁盘在产品中是同一层联合体。管理属性只有“分区”分类；拓扑、属性、选择和导航都使用联合体身份。原始来源事实保留 Partition / Volume / LogicalDisk 的区别，来源详情用于追溯字段，不生成额外业务层。网络映射也在此层显示，保留网络访问能力限制。物理磁盘与 OS 磁盘的来源组合仍属于磁盘层，不并入分区。

只按明确且唯一的关联组合来源。缺少关联的文件系统或逻辑盘继续显示在“其它”下，未知所属磁盘、偏移和分区容量保持未知，不创建占位磁盘。分区范围容量与文件系统容量不相等时分别展示。字段按语义选择来源，正常补充值不再被旧缺失标记遮盖；冲突保留来源证据，显示优先来源值。

存储刷新包含 Win32_DiskDrive、分页/转储角色和 Windows 版本补充，不依赖完整硬件刷新。管理页系统信息只保留存储上下文，CPU 和内存留在硬件页。不支持的可选电池类显示不可用；实际查询失败仍如实保留。失败刷新保留旧事实及其时间，重复刷新不累积失效状态行。

## 存储编辑边界

这些是产品创建范围，不是对 Windows 对象模型的重新定义。发现已有系统时保留其真实结构；不因编辑器只支持一种结构就丢弃其他对象、强行合并或修改采集结果。

| 项目 | 当前有效决定 |
| --- | --- |
| 编辑页面 | 保留存储结构编辑和磁盘分区编辑两页；管理页负责完整检查，结构编辑页不扩成第二个检查器 |
| 建池与虚拟磁盘 | 一个池最多新建一块虚拟磁盘；允许正式创建没有成员和虚拟磁盘的空池；创建池、虚拟磁盘、分区是三个独立但原子提交的动作 |
| 已有多虚拟磁盘 | 如实读取与展示；支持范围内可减少，不创建第二块，不因读取而自动“归一化” |
| 自动创建 | 自动创建虚拟磁盘、自动创建分区为软件偏好，不从当前所选对象结构反推开关。建池流程默认可自动创建一个基本数据分区；分区页可创建基本数据、EFI、MSR、Windows 恢复四种固定 GPT 类型，不开放自定义 GUID 或 MBR 创建 |
| 系统分区保护 | 禁止删除、格式化系统分区；不因磁盘包含系统分区，就禁用整块磁盘及其他分区的所有操作。改名、容量等已支持操作仍按各自适用规则判断；这不开放真实存储修改或未实现操作 |
| 分层 | 以性能层和容量层为主要路径，按介质提供分组和编辑；显示分组不等于已经创建 MSFT_StorageTier。保留已采集的空层/模板事实，界面可以折叠 |
| 备用与退役 | 以模拟层类型显示，名称为热备层、退役层；未归入已知层的成员显示在未划层。仅为统一投影，管理页可选，不生成 Windows 来源层，不以成员容量充当层容量；详细语义见 UnifiedModel |
| 提交方式 | 结构页：成员和非名称参数属于同一次草稿；已有对象改名按 Enter 独立及时提交，不受结构撤销/放弃影响；只读“待应用动作”显示合并后的净差异和规则原因，预览与应用使用同一计划。分区页：格式化与卷属性及时生效，每次动作单独提交并弹出成功或失败 |
| 参数 | 提供适用的交错、列数、冗余、容量等参数；层容量可输入 GiB 或选择 MAX，预配类型当前仅支持 Fixed；不能依据控件选项判定所有组合都受 Windows 支持 |
| 文件系统 | 模拟格式化支持 NTFS、ReFS、exFAT；NTFS 为默认。ReFS 没有与 NTFS 64K 同等的长期测试证据，格式化前确认，不是禁令 |
| 格式化方式 | 分区页的快速与完整格式化开关互斥且始终选中一项，默认快速；方式进入模拟操作计划和预览。完整方式不代表真实介质扫描或真实格式化，细节见[模拟编辑细节](SimulationEditingDesign.md) |
| 资源管理器 | 只对本机真实卷、有盘符且路径存在时打开；仿真禁用 |
| 扩缩容 | 2026-09-22 用户确认恢复普通数据分区的模拟扩展/压缩，包括系统/启动数据分区；不开放真实写入或保留分区扩缩。按模拟磁盘边界、相邻分区和已用容量校验，估算不冒充 Windows supported-size；本轮实现状态见 Plan |
| 排除项 | 新建 MBR、动态磁盘及其跨区/带区/镜像/RAID-5 卷、VHD/VHDX 功能、Manual 分配、Journal 作为独立设计路径、第二块虚拟磁盘、自由形式命令 |

历史设计中的“单盘 Mirror 仅警告仍放行”等例外不再生效。每种配置必须有可适用的 Windows 规则依据；不能以旧方案或旧测试要求恢复非法结构。未完成的表单可暂留界面，不得提交成有效模拟系统。

结构合法性和经验风险是两类规则：合法不等于推荐；有风险的受支持配置仍需明确警告或既定限制。研究结论必须保持：

```text
64K interleave + 64K NTFS cluster = current tested recommendation.
Windows 11 has not yet received equivalent testing because current storage hardware prices and the author's practical budget do not allow a second full test platform.
```

64K+64K 在当前测试中稳定；64K+256K 出现两阶段 NTFS 损坏；256K+64K 已发生失败，当前不推荐，不承诺未来复测；256K+256K 出现直接 NTFS 损坏、Event 55。256K interleave 不作为静默默认值。这些证据不等于其他文件系统或平台已受同等验证。

## 1.x 范围与架构约束

1.x 聚焦拓扑、管理编辑、监控、设置、数据安全和交付质量。“测试”页保持路线说明；V0.55 开发页已增加诊断日志路径与轻量“本次运行消息”，验证范围见阶段归档。完整测试工作区、外部基准执行、开发者和 AI 工作区留到 2.0。开发者模式默认关闭；启用后才显示硬件、测试、开发三页，硬件在管理之前。关闭后不能通过导航、快捷键、记忆页面或启动参数进入隐藏页；正常通知、异常处理和上下文帮助仍可使用。

保留 WinUI App + 每用户可见托盘 Agent 两进程，类型化命名管道和 Agent 单 SQLite 写入方；不引入 Windows 服务。详细技术所有权归 [Development](Development.md)。标题栏以存储系统下拉框显示和切换当前本机或模拟系统。保留现有拓扑布局。只读硬件页不显示重复页标题，以 Computer、System、Mainboard、CPU、Memory、VirtualMemory、Storage、GPU、Monitor、Network 十段纵向报告显示友好值，Memory 总体与模组分段，每段可横向查看多设备。刷新和导出按钮左对齐，不显示采集完成时间。管理页和硬件页的项名列均按内容自动宽度并设比项值更窄的上限；硬件页项名保持在横向滚动区外。设备列按内容自动宽度并设上限；单击项值选中同一设备组并将该组滚动到值区中央，组内文本可选择复制，不弹出原始字段对话框。两页属性表的缺失字段显示空白，不以破折号占位；未知、失败和真实零值继续按各自既有口径呈现。页面操作、即时反馈和各报告段使用同一纵向滚动。设备列与统一模型中的同类对象保持一致，界面只决定显示哪些字段，不按来源或设备属性隐藏对象；不隐藏软件 GPU、间接显示适配器或 Monitor。间接显示适配器在统一层按 D3DKMT 类型标志识别并使用显示侧名称，不冒充其关联的物理渲染 GPU。网络对象在统一层采用 `MSFT_NetAdapter` 的 `ConnectorPresent -or InterfaceType -ne 0` 条件，Storage 按 WinPool 管理页口径且不增加硬件页专用过滤。本机可独立刷新，当前系统可导出完整 JSON。模拟系统的非存储硬件只读。Storage 与管理页共用摘要及未知/失败/零值口径。采集、显示、缓存与导出保持原值，不做脱敏或隐私裁剪。

## 通知、上下文帮助与本次运行消息

业务提醒统一使用右下角固定大小的简洁消息卡片，不另设通知横幅，不显示“详情”或“关闭”按钮。普通消息短时间自动消失，点击后向右退出；错误消息较长时间自动消失，点击后向右退出并打开错误消息对话框，提示进入开发页查看详情。独立重复消息不合并。持续异常只在状态变化时通知，正常轮询不重复提醒；消息消失不代表问题解决。进度结束后清除，提交结果未知必须明确说明，不能当作失败或成功；模拟结果注明所属模拟系统。具体触发与呈现见[界面交互细节](InteractionDesign.md)，验证范围见 [Quality](Quality.md)。

控件用途、参数含义、单位、快捷键和禁用原因使用简短原生悬停提示；灰色禁用控件仍须能显示原因，不在控件外堆放灰色解释文字。对象及来源详情保留显式查看与复制入口，不自动弹出整份硬件报告。说明复用统一模型的来源、未知、失败和估算口径，不重新计算事实。

开发页没有页面大标题，左上“日志”区展示最近 200 条本次运行内存消息；双击条目打开可复制的详情。右上和下方功能区暂留空，下方小字提示人工智能入口正在开发。日志区仍显示当前实际 Diagnostics 路径供选择复制，不读取日志文件；支持清空和复制全部。消息只存内存，退出 App 后清空。关闭即时通知不删除记录，清空记录不消除持续异常。开发者模式不影响 App 运行期间的消息缓存；不补采 App 关闭期间事件，不新增日志文件读取、事件数据库、搜索、文件导出或完整用户操作审计。悬停、选择和普通进度变化不进入消息历史。

## 监控记录与状态提示

监控原始记录独立写入 `monitoring.db`，达到 1 GiB 后轮换；旧库后台以 7z 高压缩归档，完整性与内容哈希验证通过后不保留原始封存库。历史不自动删除，空间不足不得靠淘汰旧归档继续记录。软件不提供监控历史读取或回放。正常轮换保持采样连续，异常需如实显示记录延迟、暂停或缺口。

监控页左上角运行时持续显示本次运行时长，未运行显示“已停止”；正常诊断隐藏，异常进入右下角消息卡和本次运行记录，不再占据左上角横幅。轮换不重置时长，正常缓存淘汰不作为丢样警告；状态恢复记入记录，真实记录缺口不标作自动恢复。

设置页不提供“数据容量限制”，轮换阈值固定为 1 GiB。无标题的工具卡放在通用卡之后，当前只有 7Z 一行，按“默认/自定义”下拉选单、“打开路径”、路径文字顺序排列；下拉框与其它设置项同宽并对齐，不提供单独浏览按钮。默认使用便携包随附组件，选择自定义即打开文件选择器，已有自定义也可重新选择；取消不改变原配置。数据存储位置下拉选单后也提供“打开路径”和路径文字，打开当前实际数据目录；7Z 的按钮打开当前所选工具的所在目录，不启动工具。设置项简称“创建微软保留分区”，行为不变。设置页点击按钮配有图标。只检查工具文件存在，实际调用错误如实报告，不进行独立可执行性或能力探测，不静默回退自定义路径。采用最小进程调用器与 7z 适配器，不恢复旧工具管理系统，不提供安装、更新、下载或搜索。

监控轮换已在 V0.53 实现，执行与证据见[监控轮换阶段归档](Archive/20260921-monitoring-rotation/README.md)；后续设置页调整及验证见 [CHANGELOG](CHANGELOG.md) 和 [Quality](Quality.md)。CSV 仅覆盖当前活动库，不跨归档补齐会话；轮换期间落盘可短暂停顿，崩溃或缓冲耗尽不承诺零丢失。异常关闭只影响呈现，不删除数据或取消后台恢复。

## Windows 与交付

2026-09-16 确认：只提供便携版与安装版两种交付方式，两者使用同一产品版本并具有相同功能。相关页面统一由软件内置开发者模式控制，不再划分 Standard、Preview 等功能版本，不建立按发行版本区分的功能或数据模型。交付储备及实施前待核对项见[便携版与安装版交付方案](Design/WinPool-Distribution-Plan.md)。

最低受支持系统为 Windows 10 22H2 x64，主要平台为 Windows 11 24H2 / 25H2 x64；这是软件支持范围，不意味着所有 SKU/提供程序均可创建同一存储配置，也不意味着研究已经完成 Windows 11 等价测试。编译 TFM 不等于最低支持系统。ARM64、x86 和更早系统不属于公开保证。

当前只交付完整目录形式的无打包、自包含 x64 便携版。数据默认位于 `%LocalAppData%/WinPool`，可显式选择可写的程序旁 `Data`。签名 MSIX 在 V0.8–V0.9，Store 在 V1.0 完成之后；目前没有已发布的 MSIX 或 Store 页面。安装方式不增加存储权限，不改变进程架构；账号、包上传和正式发布另行授权。
