# WinPool 便携版与安装版交付方案

状态：2026-09-16 用户确认方向；安装版及统一发布流程尚未实施。适用基线：V0.53。当前能力与长期产品决定归 [Product](../Product.md)，实施前核对届时唯一活动 `docs/Plan.md`（若有）。本次仅更新文档，不启动打包或发布。

## 两种交付方式

WinPool 只有一套产品功能、一套源码和一个产品版本，提供便携版与安装版两种交付方式。不再划分 Standard、Preview 等功能版本，不引入 WinPoolEdition、独立 Preview 版本线或按发行版本控制页面的功能矩阵。

| 交付方式 | 当前状态与目标 |
| --- | --- |
| 便携版 | 当前已有无打包、自包含的 x64 运行目录；后续发布流程可将完整目录打包为压缩包，解压后运行 |
| 安装版 | 尚未交付；沿用 V0.8–V0.9 签名 MSIX 路线，Microsoft Store 在 V1.0 完成之后另行安排 |

同一产品版本的两种交付方式具有相同功能和开发者模式行为。开发者模式默认关闭；启用后显示硬件、测试、开发页，硬件位于管理之前。页面范围按 Product 和已确认计划演进，不通过另一个发行版本提前开放功能。

## 构建与数据

- 继续共用 App + Agent 两进程和现有运行树合并流程；共同文件按 SHA-256 校验，同路径不同内容应失败。
- 发布流程复用构建与验证步骤，仅在压缩包或安装包生成环节分流。打包参数表达交付方式，不进入业务模型、页面权限或数据库格式。
- 便携版保持自包含。安装版运行时依赖、签名和包身份在实施打包时明确，并通过干净环境验证；不预先声称已支持安装、升级或卸载。
- 同一产品版本共用数据格式和既有数据所有权。默认数据根与便携 Data 选择遵守 Development；不因交付方式另建业务数据库或 IPC 协议。
- 不承诺跨产品版本向前或向后兼容。当前旧格式明确拒绝策略继续有效；安装版升级、替换及卸载时的数据保留行为须在实施计划中明确。
- 内置开发者模式控制相关页面入口，不授予真实存储操作权限。依赖按实际功能需要选取，不建立 Preview 专用依赖集合。

## 实施前待核对

1. 安装版的包身份、签名、运行时依赖、托盘 Agent 启动及升级退出流程。
2. 安装版与便携版之间的程序替换、已有实例处理和数据位置行为；不因两种交付方式自动引入并行运行支持。
3. 压缩包格式、统一发布入口与输出命名；产品版本继续由 Directory.Build.props 唯一提供。

验收覆盖两种交付方式的启动、Agent、开发者模式一致性、数据保存与替换，以及安装版安装/升级/卸载和便携版移动后的行为。实际执行和证据按 Quality 记录；本次文档更新不代表这些检查已通过。
