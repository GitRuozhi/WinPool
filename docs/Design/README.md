# 设计储备

这里保存领先于开发、尚未进入版本计划的方案。设计领先不是过时或无效的证据；实施前仍可由开发者与 Agent 修改。目录中的文档不自动成为当前要求，不默认读取，不据此开始写代码。

每份设计只需明确状态、适用基线/条件和未决问题。状态可为“讨论中”“方向已确认、未排期”“已纳入指定 Plan”；只有被当前 Plan 明确采纳的部分进入实施范围。详细流程归 [Development](../Development.md)。

| 方案 | 当前定位 | 重新排期前核对 |
| --- | --- | --- |
| [通知、上下文帮助与轻量事件记录 Plan](WinPool-Information-System-Plan.md) | 方向已确认，未激活；仅本地编制，实施未开始 | 核对届时活动 Plan；开发页只显示日志路径和有界内存消息，不建设日志查看器或持久化事件系统 |
| [便携版与安装版交付方案](WinPool-Distribution-Plan.md) | 方向已确认；当前已有便携运行目录，安装版及统一发布流程未实施 | MSIX 打包、签名、运行时依赖、程序替换与数据保留；两种交付方式功能一致，相关页面由内置开发者模式控制 |

当前 Product/Development 和用户新决定优先，设计中的命令式措辞不构成实施授权。旧硬件重构方案与多版本发行方案已移入[设计审查归档](../Archive/20260916-design-review/README.md)：前者被现行实现替代，后者被便携版与安装版的统一功能决定替代。

纳入未来版本时只选择届时需要的部分，修正过期事实，记录尚未解决的选择，再进入唯一活动 `docs/Plan.md`；长期规则回填所属文档。被替代的设计才移入 Archive，不因暂未实施就归档丢失其讨论价值。
