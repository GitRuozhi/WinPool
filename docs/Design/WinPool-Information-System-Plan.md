## 目标与最小范围

统一现有通知、页面状态和上下文帮助的行为；开发页提供现有诊断日志路径，以及本次 App 运行期间的轻量消息列表。复用现有服务和模型，不新增数据库、持久化事件系统、后台进程、通用消息总线或全操作审计。

### 日志路径

- 开发页显示当前实际数据根下的 `Diagnostics` 完整路径，文本可选择复制；用户自行使用外部工具查看日志。
- 不在软件内读取、解析、预览、搜索或合并日志，不建立日志查看器。第一版无需新增打开文件夹或逐文件操作按钮。
- 数据根切换成功后更新路径；目录尚未生成时说明“尚未生成日志”，不为显示路径创建目录。
- 保留现有 DiagnosticLog 及按文件约 1 MiB 轮换、保留一份旧文件的策略，不在本计划中增加记录量或改变日志文件生命周期。
- 现有内存 CommandLog 不作为新增查看功能接入，不将其 500 条命令自动复制成另一套事件历史。现有诊断日志继续承担异常详情记录。

### 轻量事件记录

开发页子功能名称使用“本次运行消息”，明确退出 App 后清空。开发页仍受开发者模式控制，不新增一级导航。

- 复用现有全局通知入口，保留时间、级别、来源、标题、正文；已有错误码、系统或对象标识可随记录保留，不另建全链路操作追踪。
- 最多保留最近 200 条内存记录，超过移除最旧项。记录不得持有页面、控件、异常对象、完整来源事实或大文档引用；内容有长度边界，防止单条异常文本使缓存无界增长。
- 页面只提供简短列表、查看所选消息完整文本、清空、复制全部；不增加搜索、分页、复杂筛选、文件导出或历史数据库。
- 关闭即时通知不删除记录；清空消息列表不消除仍未恢复的页面异常，也不删除诊断日志。重新打开开发页保留当前 App 会话内消息。
- 开发者模式仅控制入口，消息缓存在 App 运行期间持续维护；切换开发者模式不清空。不补采 App 关闭期间的 Agent 事件，不承诺崩溃后或跨重启回看。
- 已有通知的成功、失败操作自然进入记录，不额外拦截每次用户操作。导航、选择、悬停、字段输入、普通采样和频繁进度更新不记录。
- 同一事件的重复通知合并，不让重复消息挤满 200 条；进行中提示不逐次追加，最终成功、失败或结果未知可记录。当前已确认的采集开始/结束即时提醒仍保留。

## 通知与状态的统一行为

沿用 ApplicationNotification、Presenter 和 GlobalNotificationService，尽量在现有职责内补齐；统一入口负责展示策略与消息记录，避免每个页面维护一份历史。

| 信息 | 展示与结束条件 | 记录规则 |
| --- | --- | --- |
| 成功、普通反馈 | 右下角短暂通知；沿用短时默认，悬停或键盘焦点停留时暂停自动关闭 | 进入本次运行消息 |
| 操作失败、需要处理的问题 | 保持可见直到用户关闭；有后续处理方式时提供明确说明，必要时查看详情 | 保留失败与已有错误码 |
| 持续异常 | 在相关页面保持显示，首次发生提醒，恢复后更新或移除异常状态 | 记录出现与恢复；重复合并 |
| 操作进度 | 相关页面或现有进度通知，完成、失败、取消、断流后正确结束 | 不逐次记录进度 |
| 输入错误、禁用原因 | 对应控件附近说明，悬停补充；不要求用户先点失败才知道原因 | 普通校验不记；实际提交拒绝按结果处理 |
| 风险确认、结果未知 | 需要决策时使用现有模态对话框，清楚说明目标、影响及下一步 | 最终提交反馈进入记录，结果未知不得写成失败或成功 |

- 严重程度与生命周期分开：提示性警告可短暂显示，持续故障和重要错误不得统一强制自动消失。AutoDismiss 等策略必须贯通各严重级别。
- 去重按事件语义键更新或合并，不只丢弃同键新正文；重复次数和最近发生时间可在同一条显示。仅对反复故障提醒限频，不省略已经明确要求的手动/自动采集最终反馈。
- 即时通知显示数量设有限上限，防止堆叠遮挡工作区；超过上限的处理不得静默丢弃重要错误。可用一个可展开的合并提醒承载，页面持续异常仍独立可见。
- 关闭通知表示已读或隐藏，不表示故障解决。恢复由真实状态触发；结果未知只有对账结果才能更新。
- 错误说明优先使用可理解的正文，错误码及可复制细节按需展开；不只显示原始异常或只有“失败”。不建立自动重试、撤销等未有业务支持的动作。
- 有明确对象的操作提示区分本机/模拟系统及目标，模拟成功不得暗示真实存储已修改。
- 保留当前自动存储、自动完整硬件及手动采集的独立进度与去重约定；历史加载和重连补读不生成虚假采集成功。
- 消息记录入口隐藏时，通知、错误详情、页面异常和处理说明仍然完整可用，不把必要信息仅放进开发页。

## 悬停说明与上下文详情

- 原生 ToolTip 继续承担短说明：按钮用途、快捷键、参数含义、单位、推荐值或禁用原因。统一文案与合理的换行/宽度，不新增自制浮窗框架。
- 键盘焦点和无障碍说明覆盖对应用途；重要禁用原因在附近可见，不仅依赖禁用控件自身的悬停事件。需要复制的长内容放入显式详情入口。
- 首批覆盖管理操作、结构编辑、分区编辑、监控与设置的现有交互；特别检查灰色按钮、MAX、Enter 改名、容量单位、布局参数和未知/不支持状态。
- 拓扑及表格保留现有悬停高亮，不因鼠标经过自动弹出整份设备报告。字段或对象详情沿用点击/右键入口，支持复制。
- 来源、单位、缺失状态、冲突和容量估算依据复用统一对象模型及当前投影，不另维护一套设备事实或重新计算容量；无来源、未知、零值和不适用保持区别。
- 持续监控状态遵守届时 Product 的约定。监控轮换计划要求正常诊断隐藏、异常逐项显示、恢复隐藏、真实记录缺口保留；其实施进度以 Plan 为准，本计划不抢先实现数据库轮换或历史监控读取。
- 软件中英文、主题、键盘访问和高对比度继续适用。日志与来源详情保持原值，遵守既有公开证据边界。
