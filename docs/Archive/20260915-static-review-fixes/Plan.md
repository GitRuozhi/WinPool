# 静态审查问题修复计划

状态：已完成
基线：`7cd2b7c`
输入：`docs/WinPool-static-review-7cd2b7c.md`

## 范围与固定决策

- F01/F05：控制管道为握手帧设置独立期限；连接级异常必须记录稳定代码并释放当前连接，监听器继续服务。监听任务自身异常由生命周期状态和托盘提示显式呈现。
- F02：监控持久化保存 `MonitorMetricKind` 当前全部 14 项，缺失值写入 `NULL`；读取和 CSV 保留缺失与真实零的区别。SQLite schema 按现行整版策略从 16 升至 17，不静默迁移或清理旧数据库。
- F03：模拟文档列表改为有界元数据分页，正文按 ID 单独读取；不提高 4 MiB IPC 帧上限。IPC 格式升至 8。
- F04：CommitId 绑定文档、前后哈希、目标修订、OperationId 和 PlanHash；相同请求重试返回不可变原回执，不同请求明确冲突；客户端对结果未知查询再次核验绑定。
- 保留用户添加的静态审查报告作为本次输入证据，不执行真实存储操作。

## 验收

- 持久化异常和零字节/半帧握手不会终止后续控制连接；不可恢复监听故障进入 Failed 并可见。
- 六类虚拟磁盘指标非零往返不丢失，缺失常规指标保持 NULL，CSV 可区分空值和零。
- 多份单体合法、合计超过 4 MiB 的模拟文档可通过分页元数据和逐份正文读取。
- CommitId 相同请求幂等、不同请求冲突；后续编辑后查询旧提交仍返回原修订和哈希。
- 全套自动测试、Release 构建、依赖漏洞审计通过；文档格式版本和验证数字同步更新。
