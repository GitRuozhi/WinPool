## 1. 目标与固定范围

将硬件页改为基本硬件报告，以用户提供的本地[内容样例](硬件报告内容样例.txt)为内容和排列参考，以管理页现有表格为视觉基线。样例中的值不是当前采集证据，文件名不定义软件隐私行为；本 Plan 的字段表和明确例外为实施范围。

KS/StatSys 是能力与实现参考：工作区 `Program/KS/StatSys.py`、`Full.yaml`，以执行时实际目录为准。只读核对 KS，不修改 KS，也不让 WinPool 在构建或运行时依赖 KS 目录、Python 程序或其 YAML。迁入的能力在 WinPool 现有采集模块内实现，避免另立通用采集框架。

补齐本计划字段所需的 KS 已有只读能力、统一事实与模型字段及呈现接线；不要求恢复 KS 全部项目。允许直接必要的固定采集和原生 API 补充，不把“只改展示”作为遗漏底层能力的理由。沿用 App + Agent、固定只读采集、现有数据库与 IPC 架构。

不增加主导航体系、硬件编辑、硬件模拟、存储编辑功能或真实存储写入；不恢复旧独立报告生产路径、13 类/154 项数量契约或软件隐私开关。

## 2. 页面与字段

- 页头仅有“刷新”“导出”两个按钮，沿用当前系统选择；正文按大类纵向排列，不增加页内导航、概览卡片、告警面板或快捷操作区。刷新忙碌及结果有可辨认状态；取消可复用刷新按钮状态或既有任务机制，不另加第三个页头按钮。
- 所有表格不显示表头，不出现“属性／本机／模组 1／显卡 1”等额外列标题；名称、型号等仍是正文数据行。
- 属性按行、对象按列，不横竖切换、不改为设备卡片。列绑定稳定对象身份，同一设备各属性不独立排序；同型号多设备、软件渲染器及虚拟适配器均保留。
- 复用管理页字体、行高、列宽、间距、分隔与窄窗行为。各段属性列对齐，设备列横向滚动、整页纵向滚动；检验嵌套滚动、换行与行高同步，不新增页内导航。
- Memory 总体信息与模组属性分段，两段均无表头、同样式。插槽总数、已用插槽和 ECC 不挂在第一条模组上，也不复制到每条模组。多个内存阵列的总体统计和混合/未知 ECC 必须有明确依据。
- 正文使用友好名称、格式化值和必要的缺失状态；标准字段名、原值、单位、来源、观察时间、选值依据及失败原因放属性详情，不逐行常驻来源类名、Returned 或展开框。详情支持键盘和读屏，单元格可识别所属设备及属性。

保留以下大类名称和顺序；不合并 Computer/System、Memory/VirtualMemory。不再删减非存储项目，国家或地区、时区不显示。

| 顺序 | 大类 | 必需正文项目 |
| --- | --- | --- |
| 1 | Computer | 主机名、制造商、型号、架构 |
| 2 | System | 名称、版本、内部版本、激活状态、语言、当前用户、本地超级管理员、电源计划 |
| 3 | Mainboard | 型号、主板厂商、BIOS 模式、BIOS 版本、BIOS 厂商 |
| 4 | CPU | 型号、基准速度、物理核心、逻辑核心、一级/二级/三级缓存 |
| 5 | Memory | 总体：插槽总数、已用插槽、ECC；模组：容量、速度、代际、型号 |
| 6 | VirtualMemory | 初始大小、最大值、页面文件位置 |
| 7 | Storage | 本地存储容量、外部存储容量、存储池数、物理磁盘数、虚拟磁盘数、分区数、可访问卷数 |
| 8 | GPU | 型号、驱动、专用/共享/总计显存、DirectX、总线/设备/功能 |
| 9 | Monitor | 型号、制造商、连接显卡、水平/垂直坐标、主显示器、水平/垂直分辨率、刷新率、位深、颜色格式、动态范围 |
| 10 | Network | 名称、硬件、链路速度、IPv4、IPv6、MAC、主网络 |

Storage 在原 Volume/Disk/Storage 区域只保留一段系统摘要，不展开设备、卷、池和层明细，不重复系统版本、CPU 或内存。完整系统事实仍保留并可导出。

## 3. KS 覆盖与统一模型

先在本计划执行记录中建立本范围的简短字段对应清单：报告项、KS 实现、当前采集来源、统一字段与设备关联、单位/选值、缺口及验证。它是本阶段验收清单，不是新的运行时字段目录；稳定字段约定最终随代码定义维护。

明确区分四种情况：KS 能力未移植、脚本结果未写入来源事实、事实存在但模型/呈现未接线、实际查询不支持或失败。前三种是实施缺口，不能以“未知”占位宣布完成。

- 优先核对 KS 的 DXGI/显示器读取、CPU 缓存及网络关联；复用其有依据的实现，不直接复刻历史样例值、基于顺序的关联或失败时补零。API、单位和语义依据在实施时查证。
- GPU 与显示器的设备身份、输出关联在模型/投影层完成；区分专用、共享、总显存及 DirectX 功能级别。保留软件适配器与无法关联的观察，不能把一块显卡的值填入全部显示器。
- 多 CPU 缓存、内存阵列与模组、页面文件、网卡与地址各自保持归属。明确缓存统计、配置速度、页面文件配置、默认路由及多地址的含义；无法确定的关系保留原因，不以名称或列表位置猜测。
- `WinPoolFacts` 保存带来源的观察；在现有 `WinPoolSystem`、选值机制和硬件呈现模块中补齐只读报告投影。UI 不直接匹配来源或汇总业务数据，不复制另一套可修改硬件模型。
- 字段贯通采集 → 来源事实 → 统一对象/选值 → 持久化与 IPC → 页面/详情/导出。保留原值、数据类型、单位、时间、来源及缺失原因；格式化不改写事实。
- 未采集、未知、不适用、读取失败、成功空集合和真实零值分别表达。失败刷新保留旧证据时显示其时间与本次失败；无对象的失败来源仍应在相应大类状态/详情中可查，不需要常驻告警面板。
- 不主动清理现有数据、不恢复旧格式回退。仅字段契约确实不兼容时调整对应内部版本并验证明确拒绝行为；保留现有迁移边界，不为历史名称顺便修改 schema。当前基线为 SQLite 16 / IPC 7 / 文档 3 / 来源事实 1。

## 4. 共用摘要与组件

以 `ManageComparisonProjector` 的 System 分支为存储摘要入口，抽取或扩展其共用投影；硬件页仅选择该投影中的存储项，不重新计算。两页项目顺序、统计口径、状态和条件显示一致。

允许同步修正管理页摘要的未知/失败表达：所需来源未采集或失败时，不将默认空集合或默认容量当成确定的零；部分证据和保留的旧证据有可追溯状态。来源成功且确实为零时才显示零或遵循两页共用的条件隐藏；未知不能仅因内部计数为零而被隐藏。保留当前分区联合体口径，不重新拆出独立卷分类。

管理页表格目前位于 `MainPage.xaml.cs`，不是已存在的独立控件。只抽取硬件页直接需要的样式、表格单元格或布局/滚动实现；不新建通用表格引擎，不改变管理页选择、导航及命令交互。相关管理页回归是验收范围。

## 5. 刷新、导出与原值

刷新复用现有只读 Hardware 用途与 Agent 协调，保留超时、取消、并发及迟到结果处理。只刷新目标本机系统；模拟/导入系统不可由本机结果覆盖，系统切换和离页时不向新目标错误应用旧结果。

导出调用当前系统的 `ExportActiveSystemAsync` / 系统文档 JSON 流程，复用封装、序列化、命名与保存选择器，不接分类 CSV、不另造硬件报告格式。导出对象在操作开始时确定，包含完整来源事实与存储信息；取消保存不报成功，失败明确反馈。

采集、模型、缓存、复制、日志和导出保持原值；本计划不含脱敏处理或隐私确认。检查本阶段触及链路有无残留裁剪，发现时按直接相关缺陷修正。历史 `sanitized_*` 列名不代表处理要求，不为重命名而改库；历史归档不追改。对外发布研究材料仍遵守根目录规则。
