## 2. 修复范围

### 2.1 开发页刷新诊断

**问题**

- `RefreshDiagnosticsAsync` 在请求完成前禁用按钮。
- 页面进入时自动调用刷新，但没有可见状态。
- 手动刷新使用 `CancellationToken.None`，无超时、无取消。
- Agent 侧诊断请求可能因为历史运行记录较多而耗时，按钮看起来永久不可用。

**修复方式**

1. 给刷新诊断请求增加超时，例如 `10s`。
2. 显示“正在刷新诊断…”状态。
3. 成功、失败、超时分别更新状态。
4. 页面进入时只自动刷新一次，并保持可再次手动刷新。
5. 防止自动刷新和手动刷新并发。
6. 页面离开时取消未完成刷新。

### 2.2 async void 事件处理器统一兜底

**问题**

- WinUI 事件处理器天然是 `async void`。
- 多个页面仍直接执行异步操作。
- 异常可能进入未处理路径。

**修复方式**

1. 增加一个轻量 UI 安全执行帮助方法。
2. 对高风险页面统一补齐：
   - 测试页 Start/Prepare/Cancel/Status。
   - 编辑页模拟操作。
   - 设置页偏好保存和外部工具检测。
   - 开发页诊断刷新和采集对照。
3. 异常时恢复控件状态并发布错误通知。

### 2.3 关键异步调用增加超时和取消

**问题**

- 多处使用 `CancellationToken.None`。
- Agent 卡住时 UI 可能长期无响应。

**修复方式**

1. 为 Agent IPC 请求建立统一超时帮助方法。
2. 重点覆盖：
   - 开发页诊断刷新。
   - 测试页 Agent 请求。
   - 设置页工具检测和安装。
   - 管理页导入导出。
   - 监控页导出。
3. 页面导航离开时取消相关任务。

### 2.4 异常日志和用户提示

**问题**

- 部分 `catch (Exception)` 只吞异常。
- 用户无法知道失败，排查缺少证据。

**修复方式**

1. 可恢复异常写入统一诊断日志。
2. 用户可见错误通过通知服务发布。
3. 不可恢复异常继续抛出。
4. 开发页事件日志保留可读诊断。

### 2.5 单实例重定向诊断

**问题**

- 重定向已有 `10s` 超时。
- 超时后缺少日志和可靠回退。

**修复方式**

1. 超时时记录诊断。
2. 尝试激活已有窗口。
3. 如果失败，给出可理解错误。
