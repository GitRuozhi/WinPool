## 1. 优先：字段缺失不能在编辑规则中变成 false / 0

**位置：** `src/WinPool.Application/WinPoolStorageProjection.cs`、`StorageEditRules.cs`。

**问题：** `Convert()` 将缺失、失败或 null 转成非空类型默认值。来源详情保留了状态，但业务快照可能把未知的系统角色当成 false，规则因此失去判断依据。

**修改：** 将关键字段的可用性贯通到规则；规则需要该字段却没有可靠值时返回“信息不足”。显示占位不能成为业务事实。只限制依赖缺失字段的操作，不阻断无关对象。

**验收：** 基本数据分区的启动/系统角色读取失败，复制为模拟系统后尝试格式化，不得因默认 false 放行。另测实际 false、0、null、未采集、失败的区别，以及无关字段缺失不误拦操作。

## 2. 优先：部分刷新不能丢失仍需保留的关联

**位置：** `src/WinPool.Application/WinPoolSystem.cs` → `WinPoolFactRefresh.Merge()`。

**问题：** 当前关系删除条件涉及任一被替换端点。磁盘刷新成功、分区刷新失败时，旧分区可能保留，但磁盘与分区的旧关系被删除。

**修改：** 依据关联采集的成功程度和有效替代证据决定更新，不能仅因端点刷新就删除关系。保留的旧证据应标明时间/状态，不冒充本次已验证；成功确认删除时仍应正确移除对象和关系。

**验收：** 覆盖“磁盘成功、分区失败”“池成功、虚拟磁盘失败”、成功空结果确认删除，以及迟到结果不得覆盖较新事实。不能出现悬空引用、重复对象或错误归属。

## 3. 修正：本地逻辑盘不能分类为网络磁盘

**位置：** `src/WinPool.Infrastructure.Windows/WinPoolFactCapture.cs`、`src/WinPool.Application/WinPoolSystem.cs`。

**问题：** `Win32_LogicalDisk` 被直接归为 `NetworkDisk`；存储投影虽过滤 DriveType，硬件页的统一对象分类没有同等处理。

**修改：** 在统一分类与来源关联中区分本地逻辑卷和网络映射，不在硬件页另补一套过滤。保留有效来源信息；不能为消除重复而直接丢弃本地逻辑盘观察值。DriveType 未知不能默认网络盘。

**验收：** 同时包含本地 C/D 盘与网络映射的输入，硬件页和管理页分类一致；同一卷不因多接口观察被错误计为多个设备。

## 4. 补齐：硬件页的失败说明和友好属性名

**位置：** `src/WinPool.App/HardwarePage.cs` 及统一属性展示服务。

**问题：** 分类只从已有对象生成，整类查询失败且没有对象时缺少具体原因入口；属性标题主要是原始类名和字段名。

**修改：** 无对象也能查看来源的失败/未采集状态；正常空结果不得误报失败。常用属性提供友好名称，标准项名和原始值在详情可查；未翻译扩展字段保留标准项名，不因此扩大为全字段翻译工程。

**验收：** 首次某类查询失败、没有缓存时，原因仍可查看；中英文、键盘访问正常。管理/编辑页现有卡片、表单和操作区不为技术字段改变主体布局。

## 5. 收口：退出无用旧生产路径，再更新版本与文档

**位置：** `src/WinPool.Infrastructure.Windows/InventoryPipeline.cs`、`WinPoolFactCapture.cs`，以及实际调用者。

**问题：** 采集仍经过旧快照投影和旧报告生成，再建立来源事实；部分来源关系依赖旧投影。当前基线的产品版本仍为 V0.51，活动计划也仍标实施中。

**修改：** 跟踪真实调用链，退出没有消费者的旧报告生产，集中重复的字段解释与关联构造。可重建的 `StorageSnapshot` 业务投影可以保留，不为名称不同而重写。有效 PowerShell/原生备用采集不能当作兼容代码删除；被替代内容按 AGENTS 归档或移出构建。

**验收：** 硬件页与管理页对同一对象、同一版本的共同事实一致；不再生成无用旧报告，关系可追溯来源。完成验证后按实际状态更新 Plan、Quality、CHANGELOG 等；产品版本仅从 `Directory.Build.props` 更新，不能只改版本号宣称完成。
