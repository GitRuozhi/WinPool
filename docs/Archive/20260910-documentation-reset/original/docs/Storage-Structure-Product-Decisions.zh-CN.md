别人把存储池做成能切很多空间的容量桶，重要参数留给向导或 PowerShell。WinPool 故意做成：一个分层池就是一块盘、一个卷，层跟盘走，改动先草稿再应用。

## 一池、一块虚拟磁盘、一个用户分区

设置、控制面板、Server Manager 都允许一个池切多块空间、一块空间再切多分区。WinPool 把这当成错误模型。要隔离某几块盘，就**新建一个池**，不在同一池里挑盘（不做 Manual）。已经误建成多虚拟磁盘的，只允许删到一块，界面上不能再切第二块。多分区是另一件事，不在建池/改池这条路上做。

## 分层是正路，不是可选项

别人把分层藏在 PowerShell 或 Server Manager 一个勾选里，工作站设置甚至没有。WinPool 默认就是性能层 + 容量层：SSD/HDD 一进池就按介质进层，热数据靠 Windows 分层，不靠 Journal，也不把回写缓存当产品中心。

## 层跟着盘走，不单独「创建层」

微软是先建空池、再勾分层、再切空间。WinPool：放进第一块 SSD 就有性能层，最后一块拿走层就不画。没有「添加层」这种操作。空的实体层不出现，避免假装有一个还没盘的层可以点。

## 热备、退役是可选的模拟层

Server Manager 用 Allocation 下拉（Automatic / Hot Spare / Manual）。WinPool 不把热备当默认，也不把退役做成隐蔽状态。池上两个开关，打开才画出「热备」「退役（未划层）」，拖进去才是那种身份。和性能/容量那种「有盘就自动出现」不是一类东西。

## 改结构先成一份草稿，一次应用

微软向导一步就算创建；WinPool 一度把「改成员」和「改属性」拆成两次提交，一点击就弹回。故意改成：拖盘和改参数都只动草稿，预览后人话确认再写入仿真。真实机器默认不能改。

## 建盘可以不建分区

别人向导常常绑死「建空间就格式化出一个卷」。WinPool 可以只留下一块 RAW 虚拟磁盘，分区到磁盘分区页再做。自动建那一个用户分区是常路，不是死路。

## 别人藏起来的参数在这里可改；看对象仍在管理页

设置/控制面板藏交错区、列数、介质类型，结果只能去 PowerShell，还踩不安全的默认。WinPool 在**改这份池**时给这些字段。管理页继续负责看健康、总线、不能入池原因。结构页不复制成第二份对象详情。

## 有研究依据的组合会拦或警告，微软默认不当推荐

256K 交织不能当静默默认。ReFS 能选，但不冒充已有和 NTFS 64K 同等长测。单 SSD 还开 Mirror 可以，但要说没有冗余。这些是故意和「向导下一步」对着干的。

## 过时磁盘格式不做，复杂功能由存储池承担

磁盘管理仍能新建 MBR、转成动态磁盘，并提供跨区 / 带区 / 镜像 / RAID-5。那些是过时磁盘格式。WinPool 不提供新建 MBR、动态磁盘、以及这些卷类型。过去堆在那里的复杂功能全部由存储池承担。

## 不做虚拟硬盘

磁盘管理可以创建、附加、分离 VHD / VHDX。WinPool 不支持 VHD 等虚拟硬盘类功能。

## 不在这条产品路上

第二块虚拟磁盘；Manual 分配；把 Journal 当设计路径；新建 MBR；动态磁盘和跨区 / 带区 / 镜像 / RAID-5；VHD 等虚拟硬盘；本页自由形态存储命令；把结构编辑当管理页用。
