## 目标与固定决定

- 新监控样本写入独立 `monitoring.db`；核心数据继续使用 `winpool.db`，两个库均由现有 Agent 管理，不增加常驻进程或服务；7z 仅在归档操作期间作为受控子进程运行。
- 不按时间、总容量自动删除监控历史，不通过降采样或汇总替代原始记录。历史清理由用户人工介入。
- 活动监控库达到 1 GiB（1,073,741,824 bytes）时触发轮换。统计主库与 WAL 的实际占用，阈值允许短暂超出，不是硬性停止记录上限。
- 旧库封存后进行一次高压缩级别的 7z 归档；完成校验后仅保留归档，不保留原始封存数据库。不重复压缩已完成归档。
- 软件不提供监控历史读取、检索、回放或历史解压缓存。归档校验与故障恢复所需的内部读取不属于历史查看功能。
- 正常监控、数据库轮换和压缩不显示诊断信息；左上角运行时持续显示运行时长，未运行显示“已停止”。异常逐项另起一行，同一项不换行。
- 本计划不涉及真实存储结构修改、发布、推送或仓库清理。

## 当前基线与实施边界

现有 Agent 将监控和核心数据写入同一个 `winpool.db`。监控写入采用内存队列和批量事务，默认队列容量 8192、批量上限 1000、攒批等待 250 ms；实时窗口淘汰不等于持久化丢样。现有容量偏好尚未接入轮换，汇总表和算法不是已实现的历史保留策略。

主要入口：`Agent/Program.cs`、`Monitoring/MonitoringSessionCoordinator.cs`、`Infrastructure.Sqlite/MonitorSampleBatchWriter.cs`、`SqliteMonitorSessionPersistence.cs`、`WinPoolSqliteStore.cs`、`StorageLocationManager.cs`（均位于 `src/WinPool.*` 对应项目），以及 App 的 `Services/MonitoringService.cs`、`MonitorPage.xaml` 和其代码后置文件。实施前按最新 HEAD 核对，不以本计划代替代码检查。

只拆监控会话、设备、原始样本及直接相关的监控持久化结构；库存、模拟文档、工作区、进程状态保持原所有权。存储健康事件本轮继续留在核心库。只读查看和现有实时采样语义不扩展。

现有旧库及其监控记录必须保留，不自动搬迁、删除或清空。优先使新监控库独立初始化而不强迫核心库格式变化；确需格式变化时遵守 Development 的旧格式明确拒绝策略，不绕过它静默迁移。监控库有独立格式版本，IPC 如增加诊断字段须同步版本、握手与测试。

删除设置页“数据容量限制”及其专用绑定、处理器、本地化文案和已无用途的偏好/请求字段；旧偏好中的遗留值不参与行为，不为此重置其它设置。此次以固定 1 GiB 为轮换阈值，不增加可配置阈值或历史总量上限。现有 CSV 导出需明确仅覆盖当前活动库可用的数据，不能再暗示跨归档的完整会话；不自动解压旧归档来补齐导出。不得在导出期间允许轮换删除其正在读取的库。

## 最小外部工具调用与设置

新增两个小型职责模块：进程调用器和 7z 适配器。优先放入现有合适项目，不恢复已退役的 `WinPool.ToolManagement`、`WinPool.Testing.Tools`、TestWorker 或 Broker，也不预建插件注册框架。

- 进程调用器：接收明确的可执行文件路径和结构化参数，隐藏窗口启动，处理取消、退出码、标准输出/错误输出及启动异常；支持流式二进制输出供哈希校验，避免将解压数据整体加载到内存。调用生命周期由 Agent 管理，有序退出或数据根切换时取消并等待本任务子进程退出，不影响用户自行启动的程序。
- 7z 适配器：生成压缩、完整性检查、流式解压校验所需的固定参数，解释退出码和失败原因，向归档协调器返回成功、失败或取消。进程退出不等于归档验证成功，仍须满足原库释放条件。
- 不实现安装、更新、下载、自动搜索、PATH 查找或自由命令输入；以后有实际工具需求时再增加适配器。

设置页新增“外部工具”卡片，当前只有 `7Z` 一行，包含路径输入框、浏览按钮和恢复默认按钮；用户可指定可执行文件路径。默认调用便携包随附的固定版本组件，按程序目录解析相对路径，移动便携目录后仍有效；自定义路径保存为绝对路径。

配置与调用前仅检查路径指向存在的文件，不额外执行可执行性检测、版本探测或操作能力预检。无法启动、权限不足、程序格式错误、参数不支持等在实际调用中处理并反馈；失败保留封存数据库。归档完整性与内容哈希校验不取消。

自定义路径失效时明确提示，不静默回退随附组件。正在进行的整次归档（压缩及后续校验）固定使用开始时确定的路径，设置变化从下一次归档任务或新的重试开始生效；恢复默认清除自定义覆盖。路径由 Agent 偏好单一持久化，App 经类型化请求更新，重启后保留；默认路径由实际运行程序位置解析，不在偏好中固化旧安装位置。

## 轮换与记录连续性

2026-09-16 用户确认采用固定活动文件名与内存缓冲的简化方案，替代原先“提前准备新库、后台 checkpoint 且不占写入关键路径”的要求。不采用临时编号活动新库及其后续提升改名流程。

1. 轮换前检查目标位置、所需空间及现有读写状态。在单一写入协调器中确定样本边界；采样持续，边界之后的数据进入有界内存队列，先排空并提交边界之前的旧库样本。
2. 协调 CSV 等读者，完成旧库 WAL checkpoint，确认已提交数据均进入主库，再关闭全部连接并释放文件句柄。不能直接重命名仍打开的主库或遗漏 WAL；checkpoint 未完成不得继续封存。
3. 将可独立读取的旧库改名封存，再在固定路径 `monitoring.db` 创建并初始化新库，补齐会话与设备元数据后消费缓冲样本。只有封存库及归档使用唯一代际编号，新活动库不使用临时编号名称。
4. checkpoint、关闭连接和新库初始化期间允许落盘短暂停顿，采样继续且由有限内存缓冲承接；旧库压缩和校验在后台串行执行，不占新库写入关键路径。
5. 各步保留持久化恢复记录并与文件事实核对，确保任意崩溃点可辨认已提交样本所属代，不覆盖已有文件。切换失败时，在能确认安全且旧库仍可写的条件下继续或恢复旧库记录，允许超过阈值并报告轮换失败；不能安全恢复时明确暂停持久化，保留数据与恢复状态，不覆盖新旧任一有效库。

会话 ID 跨轮换保持一致，在新库补齐必要会话和设备元数据，归档记录分段身份、时间范围与样本边界。按样本边界校验跨库无漏记、无重复；不得用时间戳单独去重，多个设备可共享采样时刻。无需建立通用分片框架。

正常轮换目标为不漏样、不重复，不能承诺断电时内存数据不丢失。缓冲容量按设备数、采样频率和预计切换时间验证；不使用无界队列。队列满、写入失败、记录暂停和重启发现的非正常结束须准确上报。仅对确知数量显示条数，无法确定的断电缺口不得伪造精确计数。

运行时长以当前实际监控会话为基准，采用单调计时，超过 24 小时不回绕；页面切换、App 重连同一 Agent 会话和数据库轮换不重置，新的监控会话重新计时。

## 压缩与可恢复归档

归档位于当前数据根下的专用目录，文件名带 UTC 时间范围与唯一代际编号；临时包、封存库和完成包可区分，绝不覆盖同名旧归档。

每代状态依次为：待封存、已封存、压缩中、验证中、归档完成、原库释放完成。可用最小持久化记录实现，不新增通用任务平台。状态与文件事实交叉核对，重启可恢复，不仅依赖内存标记。

- 压缩产物先写唯一临时文件，包含自包含数据库及清单；清单记录库格式、代际、会话关联、时间范围、样本数、数据库字节数和 SHA-256。
- 后台串行执行，限制 CPU、内存和并发，采样及新库写入优先。选用明确的高压缩级别，使用实际合成监控数据比较压缩率、耗时和峰值资源后固定参数，不预先承诺压缩比例。
- 采用可随便携交付提供的确定版本 7z 实现；实施时核实来源、再分发许可、依赖与 x64 打包方式。不假设用户安装了 7-Zip，不通过任意 PATH 程序执行，不接受自由命令文本。缺失或执行失败可见并保留原库。
- 对归档进行完整性检查，并从压缩包流式解压数据库内容计算 SHA-256，与封存原库比较；通过后发布为最终归档，再释放原始封存库。流式校验不建立历史查询缓存。
- 压缩失败、取消、校验失败、磁盘空间不足均保留原库及恢复所需文件；正常记录可继续时继续。重试有退避，不形成紧密循环；归档积压不得阻塞新库的正常写入。
- 崩溃在压缩、最终包发布或原库释放任一步时，恢复逻辑均不得误删唯一有效副本或生成重复完成归档。存在最终包和原库时先核验，不凭文件名删除。
- 不自动清理已完成归档。空间不足时先尝试安全继续当前库；无法持久化则明确暂停记录、保留可继续的实时监控并记录缺口，不淘汰历史来腾空间。

用户本次明确接受的“验证归档后不保留原始库”是产品自动归档的特定文件生命周期规则，仅适用于本功能自己封存且已完成校验的库及其临时产物，不扩展为开发 Agent 清理现有用户文件的权限。实施测试使用隔离合成数据；仓库文件处置仍遵守 AGENTS。

数据位置切换、有序退出和提权整套重启必须协调两个数据库、归档任务与文件句柄。切换数据根时包含活动库、待归档库、完成归档和恢复状态，验证目标完整后再切换指针；不跨根遗留正在写入或压缩的任务。不得直接沿用只识别 `winpool.db` 的复制、备份和 sidecar 排除逻辑。

## 左上角显示规则

正常运行只有一项：`运行时长：02:18:36`。未运行只有基础项：`已停止`。停止不自动清除尚未处理的真实异常。

异常示例（每条为一个独立单行项）：

```text
运行时长：02:18:36
⚠ 写入延迟：采样继续，数据暂存内存
⚠ 归档失败：原始数据库已保留
```

其他允许的提示包括 `⚠ 记录不完整：128 条样本未保存，当前记录已恢复`、`⛔ 记录已暂停：磁盘空间不足，实时监控继续` 和采样停止、通信中断、轮换失败的具体原因。只有实际确认实时采样仍在进行时才显示“继续”；通信中断时不得把未知状态报告为正常或已停止。

- 不显示正常设备数量、频率、最近成功、窗口数量、Agent 丢样合计、订阅队列、正常轮换/压缩进度或成功通知。
- 窗口正常淘汰不报警；订阅问题仅在影响实时显示时显示可理解的显示延迟提示，不称为数据库丢样。
- 延迟由待写积压年龄/写入进展等真实状态判断，正常 250 ms 攒批不报警。实施时固定并测试阈值和恢复条件，避免闪烁。
- 写入失败由实际持久化状态驱动，不能用 Agent 快照获取成功代替落库成功；数据库后台任务失败应及时传播。
- 临时延迟恢复后隐藏；真实漏记提示保留至用户关闭或新会话开始。归档失败提示保留至对应重试成功或用户关闭；关闭只影响呈现，不影响恢复任务或文件。新的失败应再次提示。
- 多问题纵向排列，记录暂停与漏记优先；不在同一行串联多个问题。同一项禁用自动换行，窄窗口可省略并通过悬停/可访问文本提供完整内容。中英文、主题和键盘可访问性保持一致。
- 不新增历史查看、归档浏览器或其他未确认功能入口。
