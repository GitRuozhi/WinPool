# WinPool V0.39a 修复计划

## 1. 版本定位

**版本：V0.39a**

V0.39a 是 V0.39 的稳定性修订版本，用于完成 V0.39 尚未完全收口的异步生命周期、IPC 请求超时、取消语义、失败可观测性和恢复诊断工作。

本版本不引入新的产品能力，不进入 V0.40，不进行 V0.4 视觉设计，不修改 IPC protocol/schema，不开放真实存储 mutation。

V0.39a 完成后，项目仍保持在 V0.39 系列。后续是否进入 V0.40，由新的独立计划决定。

---

## 2. 修复目标

V0.39a 需要解决以下几类问题：

| 目标                        | 要求                                                  |
| ------------------------- | --------------------------------------------------- |
| UI 请求不再无限等待               | 所有关键 UI→Agent / 本地长任务具有 timeout 和 cancellation      |
| `async void` 不泄漏异常        | WinUI 事件处理器中的异常必须被统一转换为用户可见状态                       |
| timeout 语义正确              | timeout 只表示客户端等待超时，不错误推断 Agent 未执行                  |
| 页面生命周期完整                  | 页面离开后取消未完成操作，或保证完成回调不再触碰旧页面                         |
| 恢复逻辑不被 UI cancellation 打断 | rollback / recovery 保持 best-effort 不可取消语义           |
| 静默失败可诊断                   | 空 catch、宽 catch、fire-and-forget 至少保留诊断证据            |
| 原 V0.39 遗留项完成             | single-instance redirect、Manage Import/Export 等必须纳入 |
| 不扩大产品边界                   | 不改 IPC schema，不做真实磁盘/池/卷修改                          |

当前部分 UI 请求仍直接使用 `CancellationToken.None`，而底层 Agent connection 会尊重调用方传入的 token，因此上层缺少 timeout 会形成实际无界等待风险。

# 3. P0 — V0.39a 必须完成

## V039A-001 — 建立统一 UI operation guard

**建议文件**

```text
src/WinPool.App/Services/UiOperationGuard.cs
src/WinPool.App/Services/AgentRequestGuard.cs
```

如纯逻辑需要测试，应把与 WinUI 无关的结果模型放入可测试项目，App 层仅保留薄适配。

### 实现要求

`UiOperationGuard` 负责：

* linked `CancellationTokenSource`
* 页面级 cancellation
* timeout
* timeout 与 external cancellation 区分
* 标准异常分类
* 内部诊断
* 对 UI 返回结构化结果

`AgentRequestGuard` 负责：

* 包装 Agent `SendAsync`
* 保留 Agent 返回的 `ApplicationStatus`
* 保留 messages
* 保留 correlation ID
* 区分 Agent rejection 和 transport failure
* 不改变 IPC protocol

建议结果模型：

```csharp
public enum UiOperationOutcome
{
    Succeeded,
    Rejected,
    Cancelled,
    TimedOut,
    TransportFailed
}
```

结果中至少保留：

```text
Outcome
ApplicationStatus?
Messages
CorrelationId?
DiagnosticCode?
OutcomeMayBeUnknown
```

### 关键语义

对于 Start Test、Cancel Test、System Support Execute、工具安装等有副作用请求：

```text
TimedOut != Failed
```

如果请求已经写给 Agent 后客户端等待超时，则：

```text
OutcomeMayBeUnknown = true
```

UI 不得自动重试，也不得直接断言操作未发生。

### 异常分类

Guard 至少覆盖：

```text
OperationCanceledException
IOException
UnauthorizedAccessException
ObjectDisposedException
InvalidOperationException
InvalidDataException
JsonException
```

`ArgumentException` 不应无条件全部吞掉。只有明确属于输入/路径校验的场景才转换成普通 UI 失败；可能代表程序缺陷的异常仍应进入诊断。

### 完成定义

* timeout 和页面取消得到不同 outcome
* Agent rejection 不被误判为 IPC failure
* UI event handler 不会因上述异常崩溃
* 有副作用请求支持 outcome unknown
* 有单元测试

## V039A-002 — TestPage IPC 全面接入 Guard

**文件**

```text
src/WinPool.App/TestPage.xaml.cs
```

当前 TestPage 在 Start、Cancel、状态查询、结果读取以及 System Support 等路径存在直接使用 `CancellationToken.None` 的情况。

### 必修路径

| 路径                             | Timeout |
| ------------------------------ | ------: |
| Prepare                        |     15s |
| Start Test                     |     15s |
| Cancel Test                    |     15s |
| status poll                    |   5–10s |
| result query                   |     10s |
| history                        |     10s |
| tool detection                 |     15s |
| RAMMap detection               |     15s |
| System Support review          |     15s |
| System Support execute request |     15s |
| export                         |     30s |
| Dite import                    |     30s |

### Start timeout

Start 请求超时后：

```text
不得：
“启动失败”
→ 立即恢复为完全可启动状态
→ 用户再次 Start
```

必须进行一次状态 reconciliation：

```text
查询当前 RunId / active run / Agent snapshot
```

如果确认已经启动：

```text
进入运行中状态
```

如果确认未启动：

```text
恢复 Start
```

如果仍无法确认：

```text
显示“启动状态未确认”
禁止盲目重复提交
```

### Cancel timeout

Cancel timeout 后：

```text
不得显示“已取消”
```

应查询 Agent 权威状态。

显示：

```text
取消状态未确认
```

直到确认 run 已停止或继续运行。

### Timer

`StatusTimer_Tick` 必须：

* 防止重入
* 5–10s timeout
* 捕获异常
* Agent 临时失败时降级，不崩溃
* 页面离开后停止

### 完成定义

停掉 Agent 或模拟卡住 pipe 时：

* Prepare 按钮恢复
* Start 按钮不会永久 disabled
* Cancel 按钮不会永久 disabled
* timer 不产生未处理异常
* history 不伪装成“无记录”
* 页面不崩溃

# 11. Execution recovery 可观测性

## V039A-012 — SafeOperationExecutors

**文件**

```text
src/WinPool.Execution/SafeOperationExecutors.cs
```

当前：

```csharp
RestoreAsync(receipt, CancellationToken.None)
```

是合理的恢复语义。

原因是：

```text
原操作即使已经取消
也仍然应该 best-effort rollback
```

所以 V0.39a **不要**把这里机械改成调用方 token。

当前真正的问题是恢复异常和执行异常会被宽 catch 转成单一失败结果，内部诊断完全消失。

### 修改

保留外部 contract：

```text
simulation.failed
windows-readonly.failed
```

但内部 diagnostic 至少记录：

```text
operation id
execution stage
exception type
exception message
recovery attempted
recovery succeeded
```

### 注释

在 `CancellationToken.None` 旁明确说明：

```text
Intentional: rollback continues after caller cancellation.
```

# 17. Timeout 默认规范

V0.39a 统一使用以下默认值：

| 类别                    |            Timeout |
| --------------------- | -----------------: |
| 普通 Agent query        |                10s |
| status poll           |              5–10s |
| Start Test            |                15s |
| Cancel Test           |                15s |
| Tool detect           |                15s |
| System Support review |                15s |
| Import / Export       |                30s |
| Inventory comparison  |                60s |
| Local inventory scan  |                60s |
| Download / installer  |            2–5 min |
| rollback / recovery   | 不使用页面 cancellation |

统一值应定义为常量或 policy，而不是散落 magic number。

例如：

```csharp
internal static class UiOperationTimeouts
{
    public static readonly TimeSpan Query = TimeSpan.FromSeconds(10);
    public static readonly TimeSpan Command = TimeSpan.FromSeconds(15);
    public static readonly TimeSpan Export = TimeSpan.FromSeconds(30);
    public static readonly TimeSpan Inventory = TimeSpan.FromSeconds(60);
}
```

## V0.39a

### Stability

- Added bounded timeout and cancellation handling for critical UI operations.
- Added normalized Agent request error handling without changing the IPC protocol.
- Added page-lifetime cancellation for Test, Development, Settings, Monitor, and Manage workflows.
- Hardened test start/cancel timeout handling with authoritative state reconciliation.
- Added timeout handling for inventory comparison, import/export, tool detection, and local inventory scans.
- Fixed silent history and local scan persistence failures.
- Improved diagnostics for single-instance activation failures.
- Improved rollback and system-support recovery diagnostics while preserving best-effort non-cancellable recovery semantics.
- Hardened shutdown, monitoring, broker, and fire-and-forget exception observation.

### Scope

- No IPC protocol or schema changes.
- No persistent storage schema changes.
- No real storage mutation capability added.
- No V0.40 visual or product work included.
