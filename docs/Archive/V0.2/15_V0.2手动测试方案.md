# WinPool V0.2 手动测试方案

## 1. 用途

本方案用于补齐当前自动化无法可靠操作的原生文件夹选择器、通知区域托盘菜单、UAC 弹窗和
跨主窗口生命周期验证。核心测试约 45～60 分钟；扩展迁移回退约 10～20 分钟。

本轮只做小型测试，不做填满卷、长时间压力或真实存储结构变更。

## 2. 安全边界

- 所有测试文件只写入 `D:\WinPool-V02-Manual-Test` 及其子目录。
- 不选择 C:、E:、网络盘、磁盘根目录或项目源码目录作为测试目录。
- 不执行初始化磁盘、清盘、分区、格式化、创建/删除存储池、Tier 或 VirtualDisk。
- E: 本轮只保持现状；不需要为了验收而修改其结构。
- R3 只测试 D: 的卷 Flush；不测试 TRIM/Optimize、临时文件清理、RAMMap 或临时电源计划。
- 若确认弹窗显示的目标不是 `D:\WinPool-V02-Manual-Test` 所在卷，立即取消并停止测试。
- 测试文件先保留，待结果记录完成后再通过 WinPool 登记的清理流程处理；不要直接删除项目证据。

## 3. 测试准备

1. 在资源管理器中创建空目录：
   `D:\WinPool-V02-Manual-Test`。
2. 确认 D: 至少有 2 GiB 可用空间。
3. 关闭其他高 I/O 程序，并暂时不要运行 Windows 磁盘优化、备份或大型下载。
4. 从以下 Release 文件启动：
   `D:\Coding\Research03_WinPool\Program\WinPool\src\WinPool.App\bin\Release\net10.0-windows10.0.26100.0\win-x64\WinPool.App.exe`
5. 欢迎页显示 V0.2 后按 `Return`，确认可以进入主界面。
6. 建议准备一个文本文件，按本文第 8 节记录结果；截图中不要主动展开或保存完整硬件序列号。

可选的只读进程检查命令：

```powershell
Get-Process WinPool.App,WinPool.Agent,WinPool.TestWorker,WinPool.ElevatedBroker -ErrorAction SilentlyContinue |
    Select-Object ProcessName, Id, StartTime
```

## 4. 核心测试

### MT-01 启动、托盘和单实例

步骤：

1. 确认通知区域出现 WinPool 托盘图标。
2. 保持当前窗口打开，再次双击上述 `WinPool.App.exe`。
3. 观察是否只激活已有窗口。
4. 用任务管理器或只读命令检查 App 数量。

通过标准：

- 存在一个可见托盘图标；
- 只有一个 `WinPool.App`；
- 第二次启动没有出现第二个主窗口、第二个 App PID 或错误弹窗；
- Agent 能连接，主界面没有持续显示断线错误。

### MT-02 六页导航和只读边界

步骤：

1. 依次按 `Ctrl+1`～`Ctrl+6`。
2. 确认依次到达 Manage、Edit、Test、Monitor、Development、Settings。
3. 在 Manage 查看 System、Pool、Tier、Disk、Partition 分类和本机/模拟拓扑。
4. 在 Edit 选择本机系统，确认真实本机修改控件不可用或明确拒绝。
5. 切换到模拟系统，做一次简单模拟重命名；再切回本机确认真实布局未变。
6. 在 Development 确认能查看诊断、计划、算法或事件，但没有自由命令输入/执行入口。

通过标准：六页均可到达、无崩溃；模拟修改有效；本机真实写操作仍不可用；Development
保持只读诊断性质。

### MT-03 Settings、工具、语言和主题

步骤：

1. 在 Settings 确认 About 显示 `V0.2`。
2. 检查外部工具状态：DiskSpd、RoboCopy、RAMMap 应显示可用；fio、Dite 应显示缺失。
3. 把语言切换到 English，依次访问六页，确认主要标题和按钮变为英文且无截断到不可用。
4. 把主题切换到与当前相反的 Light 或 Dark，再访问 Manage、Test、Monitor。
5. 恢复中文；主题可恢复原设置。
6. 不点击安装 fio/Dite，不修改外部工具自定义路径。

通过标准：版本和工具状态正确；中英文切换立即生效；相反主题下文字、卡片、按钮和图表可辨认；
没有因切换而重启 Agent、丢失主界面或产生异常窗口。

### MT-04 App 内 DiskSpd 小型测试

在 Test 页设置：

| 字段 | 值 |
| --- | --- |
| 测试场景 | `I/O 基准 / I/O benchmark` |
| 外部工具 | `DiskSpd` |
| 工作负载 | `随机混合 70/30 / Random mixed 70/30` |
| 测试文件大小 | `0.06 GiB` |
| 块大小 | `64 KiB` |
| 线程数 | `1` |
| 队列深度 | `2` |
| 持续时间 | `5 秒` |
| 写入比例 | `30%` |
| 预热 | `1 秒` |
| 冷却 | `0 秒` |
| 重复次数 | `1` |
| RAMMap/调度/电源计划/批次 Flush | 全部关闭 |

步骤：

1. 点击“选择文件夹”，选择 `D:\WinPool-V02-Manual-Test`。
2. 检查页面显示的目标、可用空间、预计写入量和计划摘要。
3. 点击“准备计划”；确认目标仍是 D: 登记目录且没有 R3 动作。
4. 点击“开始测试”，阅读二次确认后选择“确认开始”。
5. 观察 TestWorker 状态、步骤状态和结果，等待运行结束。
6. 刷新历史，选中该运行并导出 `ZIP` 或 `JSON` 到
   `D:\WinPool-V02-Manual-Test\Exports`。

通过标准：

- 原生文件夹选择器能返回 D: 目录；
- 计划只包含登记目录内的文件，不出现 E:、C:、磁盘号或自由命令；
- 测试完成状态为 Succeeded，能看到吞吐、IOPS 和延迟；
- 历史中存在该运行；导出成功且文件非空；
- DiskSpd 结束后没有残留 `diskspd` 或 `WinPool.TestWorker` 进程。

### MT-05 取消和恢复收敛

步骤：

1. 复用 MT-04 设置，只把持续时间改为 `30 秒`。
2. 开始后等待 3～5 秒，点击“取消测试”。
3. 等待页面进入 Cancelled 或等价终态。
4. 确认界面可以重新准备计划并启动下一次测试。

通过标准：取消不是 Failed/崩溃；Agent 仍在线；外部工具和 TestWorker 在合理时间内退出；
历史保留取消记录；下一次计划不被旧运行锁死。

### MT-06 RoboCopy 生成、复制和完整校验

在 Test 页设置：

| 字段 | 值 |
| --- | --- |
| 测试场景 | `生成、RoboCopy 复制与验证` |
| 复制验证 | `FullHash` |
| 测试文件大小 | `0.02 GiB` |
| 重复次数 | `1` |
| RAMMap/调度/电源计划/批次 Flush | 全部关闭 |

其余字段保留有效默认值，目标继续使用 `D:\WinPool-V02-Manual-Test`。

步骤：准备计划、核对目标、确认开始、等待生成→RoboCopy→验证全部结束；刷新历史，选中运行，
尝试与 MT-04 运行一起比较，然后导出一次结果。

通过标准：生成、复制、完整 SHA-256 验证均成功；RoboCopy 0～7 的成功返回不会被误报为失败；
比较视图能显示结果或明确说明两个工作负载不可比较，而不是崩溃；导出成功。

### MT-07 后台持续监控和主界面重连

步骤：

1. 打开 Monitor，勾选“后台持续监控”，选择 1 秒或默认采样频率，点击“开始监控”。
2. 保持主界面打开 2 分钟，观察 D: 或其他磁盘活动、读写速度和诊断更新时间。
3. 按 `Alt+F4` 关闭主窗口，确认托盘图标仍存在。
4. 等待 3 分钟；期间可在 D: 复制一个普通小文件以产生可见 I/O，但不要写 E:。
5. 双击托盘图标或重新运行 `WinPool.App.exe`。
6. 回到 Monitor，确认仍是同一后台会话、窗口恢复且关闭期间有数据。
7. 点击“导出数据”，保存到 `D:\WinPool-V02-Manual-Test\Exports`。

通过标准：关闭 App 不停止 Agent/监控；重开后能重连并看到跨关闭时段的数据；导出文件非空；
没有出现第二个 Agent 或第二个 App 实例。

### MT-08 R3/UAC：只执行 D: 卷 Flush

前提：Test 页目标仍明确显示 `D:\WinPool-V02-Manual-Test`。

步骤：

1. 在“测试前系统操作”选择 `Flush 测试卷 / Flush test volume`。
2. 点击“审阅操作”。
3. 检查确认框明确写明目标是当前所选测试目录所在卷，并再次确认它是 D:。
4. 若目标正确，点击“确认执行”；若出现 UAC，只确认签名/路径属于当前 WinPool 打包 Broker。
5. 等待“系统操作完成”及审计结果。

通过标准：有明确警告和二次确认；一次性 Broker 执行后退出；结果可见；不修改分区、卷格式、
存储池、Tier 或 VirtualDisk；C:/E: 均未成为操作目标。

### MT-09 托盘完整退出

步骤：

1. 保持 App 打开，确认没有测试正在写入；Monitor 可处于后台运行状态。
2. 右键通知区域 WinPool 图标，选择“退出”。
3. 等待最多 20 秒。
4. 用任务管理器或第 3 节只读命令检查进程。

通过标准：App、Agent、TestWorker、ElevatedBroker、DiskSpd、RoboCopy 等本轮受监督进程全部退出；
托盘图标消失；没有服务或完全静默的 WinPool 后台进程。

若 20 秒后仍有进程，先截图和记录 PID/进程名，不要立即清理证据；只在记录完成后精确结束
本轮 WinPool 进程，不要按模糊名称批量终止其他程序。

## 5. 扩展测试：数据位置往返回退

本项不是首次 45～60 分钟冒烟的必要条件，但要严格完成 `14_V0.2测试版最小验收.md`
仍需执行。

1. 确保没有活动测试；停止 Monitor。
2. Settings 中记录当前数据位置及显示路径。
3. 从“标准位置”切换到“软件目录（便携）”，核对计划摘要、文件数、字节数和目标路径。
4. 确认后等待 App/Agent 完成停止、复制、校验和单实例重启。
5. 验证历史、监控记录、设置和模拟文档仍可读取。
6. 再切回“标准位置”，重复核对和确认。
7. 验证来源数据仍保留，没有被移动或删除。

任一步骤若显示 SQLite quick_check、清单哈希、sidecar、指针提交或 Agent 停写错误，立即停止，
保留两侧目录和错误截图，不要手工覆盖数据库或指针文件。

## 6. 立即停止条件

出现以下任一情况，不再继续后续测试：

- 任何计划、确认框或路径出现 E:、C:、磁盘根目录或未选择的目标；
- 出现初始化、清盘、分区、格式化、存储池、Tier、VirtualDisk 修改动作；
- 弹出自由 PowerShell、cmd、任意参数或未知可执行文件；
- 文件系统错误、Event 55、卷掉线、永久写失败或异常容量变化；
- 取消或托盘退出后受监督工具仍持续写盘；
- App/Agent 重启后数据库无法打开、历史消失或 quick_check 失败。

## 7. 判定规则

- MT-01～MT-09 全部通过：V0.2 核心手动冒烟通过。
- 任一项“部分通过”仍按未通过处理，记录实际现象，不凭推测补写结果。
- MT-04、MT-06、MT-07、MT-08、MT-09 是当前最重要的阻断项。
- 扩展数据位置往返回退通过后，才能关闭最小验收中的迁移人工缺口。
