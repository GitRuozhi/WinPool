# V0.2 算法目录与验证计划

## 1. 目的

V0.2 不允许把重要判断散落在页面事件或基础设施适配器中。每个影响容量、布局、
选择、执行安全、测试结果或健康判断的算法都必须：

- 有稳定 `AlgorithmId`；
- 有版本；
- 有明确输入、输出、单位和溢出策略；
- 有置信度；
- 有测试向量；
- 有来源和限制；
- 推测性算法在文档、代码注释、日志和 UI 中标记 `【推测，待验证】`。

算法存在不等于允许执行真实存储结构修改。当前机器允许受控文件型测试和已批准的
测试辅助操作。

## 2. 公共数学规则

### ALG-MATH-001：容量单位

- 内部容量统一使用无符号 64 位字节数。
- UI 的 KiB/MiB/GiB/TiB 使用 1024 进制。
- 用户输入必须明确单位，不使用当前区域设置猜测。
- 所有乘法、加法使用 checked 运算。
- 超出范围返回验证错误，不截断。

置信度：`Validated`。

### ALG-MATH-002：向上/向下对齐

```text
AlignDown(value, alignment) = value - value mod alignment
AlignUp(value, alignment) =
    value                         if value mod alignment = 0
    value + alignment - value mod alignment otherwise
```

要求 `alignment > 0`，并在 `AlignUp` 中检查溢出。

置信度：`Validated`。

### ALG-MATH-003：百分比

```text
percentage = numerator / denominator * 100
```

- `denominator = 0` 时返回 unavailable，不返回 0。
- 活动率 UI 限制在 0–100%，原始值单独保留。

置信度：`Validated`。

## 3. 稳定身份与重新扫描

### ALG-ID-001：对象身份优先级

按对象类型使用以下优先级：

1. Windows 提供的稳定唯一 ID；
2. 多个非敏感稳定字段的规范化组合摘要；
3. 系统范围内的复合键；
4. 明确标记为 unstable 的临时键。

禁止把盘符、显示名称或列表位置作为唯一身份。

置信度：`Derived`。各设备类别需用真实热插拔、盘符变化和重启逐项验证。

### ALG-ID-002：扫描后选择恢复

1. 按原稳定 ID 查找。
2. 找不到时按当前分类和合法关系查找最相关对象。
3. 再使用该分类的上次选择。
4. 最后使用排序后的第一个对象。
5. 没有对象时清空选择。

置信度：`Validated`，继承现有 Core 测试。

## 4. 拓扑和分类

### ALG-TOPO-001：完整拓扑投影

输入为存储对象和显式关系，输出为无环展示树：

1. 系统为根。
2. Windows Storage Pool 和 Primordial Pool 为真实池节点。
3. Network、Other 为逻辑组，不计入池数量。
4. Tier 和 VirtualDisk 作为 Pool 子结构。
5. PhysicalDisk 可在需要时显示引用节点，但同一容器内不重复实体。
6. Partition 是 OS Disk 下的叶节点。
7. 对缺失关系生成 warning，不虚构实体。
8. 检测关系环并截断为诊断节点。

置信度：`Validated/Derived`；已存在规则继续测试，异常图新增属性测试。

### ALG-TOPO-002：相关对象切换

关系优先级：

- Partition -> 所属 Disk；
- Disk -> 所属 Pool；
- Tier -> 所属 Pool；
- Pool -> 上次或首个相关 Tier/Disk；
- VirtualDisk -> 当前产品定义的分类目标；
- NetworkDisk -> Partition 分类。

多候选按拓扑顺序、稳定 ID 排序，禁止依赖哈希集合枚举顺序。

置信度：`Validated`。

### ALG-LAYOUT-001：等宽流布局

沿用现有 `EqualFillFlowLayout` 的纯算法语义：

- 每行在可用宽度内均分；
- 最后一行也填满；
- 过窄时至少一项；
- 间距单独扣除；
- 不返回负宽度。

置信度：`Validated`。

### ALG-LAYOUT-002：池权重布局

- Pool 权重取其最大存储 lane 的结构权重。
- 按确定性顺序装入行。
- 计算宽度时归一化权重并扣除间距。
- 零或非法权重回退为 1。

置信度：`Validated`，继承现有测试并增加极端宽度测试。

## 5. 存储容量与规划

### ALG-CAP-001：现有对象可用容量

对已存在 Windows 对象：

- Windows 报告值是当前事实来源。
- 不用理论公式覆盖 `Size`、`AllocatedSize`、`FootprintOnPool` 或
  `SizeRemaining`。
- 不同来源冲突时保留全部来源并产生 finding。

置信度：`Validated`。

### ALG-CAP-002：候选 Pool 理论容量

同容量、固定列数情况下：

```text
stripeCount = floor(minSelectedDiskBytes / interleave)
rawStripeBytes = stripeCount * interleave * columns
```

随后按 resiliency 的 data columns 估算逻辑容量。

该算法不能覆盖 slab、元数据、对齐、故障域、异构磁盘和 Windows 实际分配策略。

置信度：`【推测，待验证】`。只作为计划预估，UI 必须显示范围和限制。

### ALG-CAP-003：支持的 Tier/VirtualDisk 大小

优先顺序：

1. Windows 只读 API/命令返回的 supported size；
2. 已验证的原生等价查询；
3. 理论估算。

第 3 项必须标记 `【推测，待验证】`，不得作为自动执行参数。

### ALG-CAP-004：Tier 比例与最大值

- 每个 Tier 单独保存目标大小。
- 计划展示逻辑大小、预计物理占用和保留空间。
- 不从总容量按比例静默分配。
- 自动建议只生成候选，不替代用户审阅。

自动选择“最佳比例”属于 `【推测，待验证】`。

### ALG-COL-001：列数检查

- `NumberOfColumns >= 1`。
- 列数不得超过满足当前 resiliency/fault-domain 的可用磁盘数。
- 对 parity、mirror 和 tiered layout 分别验证。
- Windows 返回的 supported size 和 validation 结果优先于本地推导。
- `n - 1` 不是所有家庭配置的无条件默认。

置信度：基础约束 `Derived`；最佳列数建议为 `【推测，待验证】`。

### ALG-ALIGN-001：Interleave 与 Cluster

- 两者必须为受支持的 2 的幂。
- V0.2 内置经过本项目验证的默认值：64K/64K。
- 64K/256K、256K/64K、256K/256K 显示已知风险。
- 推荐信息必须带测试系统与证据范围。
- 不把 Windows 默认值自动当成推荐值。

置信度：项目结论部分 `Validated`；未测试组合为 `Speculative`。

## 6. 分区规划

### ALG-PART-001：新分区范围

1. 获取磁盘未分配区间。
2. 按系统要求和所选 alignment 向上对齐起点。
3. 按 alignment 向下对齐结束。
4. 排除 MSR、EFI、Recovery 和其他保留范围。
5. 验证 `start < end`。
6. 生成明确的未使用尾部空间。

置信度：`Derived`；真实执行前必须以 Windows supported size 再验证。

### ALG-PART-002：扩展

```text
maxEnd = nextPartitionStart or diskUsableEnd
maxGrowth = AlignDown(maxEnd - currentEnd, alignment)
```

- 只允许进入相邻未分配区。
- 不跨越其他分区。
- 对 VirtualDisk/Volume 的限制由未来 executor provider 再验证。

置信度：模拟算法 `Validated`；真实执行约束 `Derived`。

### ALG-PART-003：压缩

```text
minimumSize = max(
    filesystemReportedMinimum,
    usedBytes + requiredReserve,
    alignment)
```

Windows 未提供可靠 minimum 时不生成真实执行计划。

`requiredReserve` 的自动百分比属于 `【推测，待验证】`；V0.2 只用于模拟建议。

### ALG-PART-004：初始化与 MSR

- 初始化清除模拟分区并建立新 partition style。
- GPT 且设置开启时模拟创建 16 MiB MSR。
- MBR/GPT 选择和容量限制显式展示。
- 当前机器只生成模拟计划。

置信度：模拟行为 `Validated`。

## 7. 操作计划 DAG

### ALG-PLAN-001：步骤排序

1. 每个步骤声明依赖。
2. 使用 Kahn 算法拓扑排序。
3. 存在环时拒绝计划。
4. 同时使用稳定步骤 ID 排序，保证相同输入产生相同计划。
5. 每个修改步骤之后插入对应验证步骤。

置信度：`Validated`。

### ALG-PLAN-002：PlanHash

1. 规范化环境、系统、目标、参数、步骤和算法版本。
2. 字典键按 ordinal 排序。
3. 数值使用不依赖区域的格式。
4. UTF-8 序列化。
5. 计算 SHA-256。

显示文本、时间戳和本地化字符串不进入 hash。

置信度：`Validated`。

### ALG-LOCK-001：资源锁

- 锁键为环境 + 系统 + 稳定对象 ID。
- 父对象修改与所有子对象冲突。
- 只读查询共享锁。
- 修改计划排他锁。
- 多锁按规范化键排序获取，避免死锁。

置信度：`Derived`；需并发和故障注入验证。

## 9. 监控与数据算法

### ALG-MON-001：时间规范化

- 采样用单调时钟计算间隔。
- 持久化同时保存 UTC 时间。
- 系统时间回拨不产生负间隔。
- UI 以会话相对时间绘制。

置信度：`Derived`。

### ALG-MON-002：吞吐刻度

1. 取当前可见序列最大值。
2. 最小上限为 100 KiB/s。
3. 向上取友好刻度。
4. 缩放使用迟滞，避免每帧跳动。

迟滞比例属于 `【推测，待验证】`，需用录制会话验证可读性。

### ALG-MON-003：丢样

- channel 满时按明确策略丢弃最旧或最新样本。
- 默认建议丢弃最旧、保留最新 UI 状态。
- 每次丢样累计计数并写会话 finding。

默认策略属于 `Derived`，必须用高负载测试验证。

### ALG-ROLLUP-001：时间聚合

每个时间桶保存：

- first/last；
- min/max；
- arithmetic mean；
- 样本数；
- missing count；
- 总读写字节的时间积分。

Rollup 不替代原始证据，默认不自动删除原始样本。

置信度：`Validated/Derived`。

## 10. 健康和异常判断

### ALG-FIND-001：已知结构 finding

保留现有：

- busy pool；
- legacy dynamic volume；
- MBR disk；
- 不健康状态；
- 关系缺失。

每项 finding 明确来源、严重度、对象和解释。

### ALG-FIND-002：busy 与 corruption

- 单独的 busy、Tier Optimization 延迟或吞吐下降不判定为 corruption。
- corruption 需要文件系统/Storage Spaces 错误、只读/脱机、写入失败或明确事件证据。
- 事件 55/98/312 和 `ERROR_DISK_CORRUPT` 作为证据输入，不由性能曲线推断。

置信度：`Validated`，与研究结论一致。

### ALG-ANOM-001：测试异常检测

MAD、IQR、趋势断点和稳态检测可以实现，但全部初始标记
`【推测，待验证】`：

- 只标记异常，不删除数据；
- 展示算法版本和阈值；
- 允许查看原始序列；
- 不能自动生成“硬件故障”结论。

## 11. 验证登记

建议在 SQLite `algorithm_registry` 和测试证据中保存：

```text
algorithm_id
version
confidence
source_reference
assumptions
test_vector_version
last_validated_at
validated_environment
known_limitations
```

验证过程：

1. 单元测试数学和边界。
2. 属性测试大量随机输入。
3. 固定录制数据回放。
4. 与当前 V0.13/Dite/Windows 报告对照。
5. 在用户提供的可写环境进行真实验证。
6. 更新置信度和限制。

没有完成第 5 步的写入型 Storage Spaces 算法不得标记为 `Validated`。
