# V0.2 架构与内部 Application Contracts

## 1. 架构原则

1. UI 只表达状态和意图，不直接调用 PowerShell、外部测试工具、SQLite 或文件系统。
2. Application 层组织用例、权限、安全、事务和跨模块流程。
3. Domain 层保存稳定身份、关系、规则和纯算法。
4. Infrastructure 实现端口，不反向定义业务模型。
5. 查询与操作意图区分；只读查询不隐式升级为写入。
6. 每个长任务都可取消、可观察、可审计，并有明确终止状态。
7. 内部 contracts 可以在测试阶段演进，不承诺公共兼容性。
8. 序列化文档和 SQLite schema 是内部实现，不等于公共 API。
9. 后台持续监控不依赖主界面进程存活。
10. 外部工具必须通过类型化适配器调用，不向 UI 暴露自由命令行。

## 2. 领域边界

建议拆分为以下 bounded contexts：

- `Inventory`：发现本机、导入系统和模拟系统，规范化存储对象。
- `Workspace`：当前页面、系统、分类、对象选择和拓扑高亮。
- `Simulation`：对模拟文档执行存储操作。
- `Execution`：把意图转换为计划，完成验证、授权、执行和审计。
- `Testing`：定义工作负载、调度任务、采集指标和生成结论。
- `Monitoring`：持续采样、会话、展示、汇总和导出。
- `ToolManagement`：发现、版本、安装、自定义路径、完整性和能力。
- `ProcessCoordination`：托盘 Agent、命名管道、Worker 和完整退出。
- `Persistence`：快照、偏好、历史、测试和监控数据。
- `Presentation`：双语、主题、通知、对话框和视觉状态。

跨上下文只通过 Application contracts、领域事件或不可变数据传输对象协作。

## 3. 稳定身份

所有对象必须使用结构化身份，禁止把显示名称、盘符或数组位置作为永久主键。

```csharp
internal readonly record struct SystemId(Guid Value);
internal readonly record struct StorageObjectId(
    SystemId System,
    StorageObjectKind Kind,
    string ProviderKey);
internal readonly record struct SessionId(Guid Value);
internal readonly record struct OperationId(Guid Value);
```

规则：

- 本机身份绑定经过规范化的机器身份，但不得把明文硬件序列号写入数据库。
- 模拟和导入系统每次创建新 `SystemId`。
- 盘符是属性，不是身份。
- Windows 对象重新扫描后优先通过稳定系统键映射。
- 无法建立稳定键时使用明确标记的临时键，UI 必须能展示“不稳定身份”诊断。

## 4. Application contracts

以下接口是目标语义示例；实现时可以调整方法名和 DTO，但必须保留职责边界。

### 4.1 查询

```csharp
internal interface IStorageSystemQuery
{
    Task<StorageSystemView> GetSystemAsync(
        SystemId systemId,
        CancellationToken cancellationToken);

    IAsyncEnumerable<StorageChange> WatchSystemAsync(
        SystemId systemId,
        CancellationToken cancellationToken);
}

internal interface IWorkspaceQuery
{
    Task<WorkspaceState> RestoreAsync(CancellationToken cancellationToken);
    Task<IReadOnlyList<ObjectComparisonRow>> CompareAsync(
        SystemId systemId,
        StorageObjectKind category,
        CancellationToken cancellationToken);
}
```

### 4.2 用例命令

```csharp
internal interface IApplicationCommandHandler<TCommand, TResult>
{
    Task<TResult> HandleAsync(
        TCommand command,
        CancellationToken cancellationToken);
}

internal sealed record RequestOperationPlan(
    SystemId SystemId,
    OperationIntent Intent,
    IReadOnlyDictionary<string, object?> Parameters);
```

UI 提交的是类型化命令，不提交自由文本命令。

### 4.3 执行计划

```csharp
internal interface IOperationPlanner
{
    Task<OperationPlan> BuildAsync(
        OperationRequest request,
        CancellationToken cancellationToken);
}

internal interface IOperationPolicyEvaluator
{
    Task<PolicyDecision> EvaluateAsync(
        OperationPlan plan,
        ExecutionContext context,
        CancellationToken cancellationToken);
}

internal interface IOperationExecutor
{
    ExecutionCapability Capability { get; }

    IAsyncEnumerable<ExecutionEvent> ExecuteAsync(
        AuthorizedOperation operation,
        CancellationToken cancellationToken);
}
```

`AuthorizedOperation` 只能由安全协调器创建，普通 UI 或业务代码不能自行构造。

### 4.4 采集

```csharp
internal interface IInventoryProvider
{
    InventoryProviderKind Kind { get; }
    Task<InventorySnapshot> CaptureAsync(
        InventoryRequest request,
        CancellationToken cancellationToken);
}

internal interface IInventoryComparer
{
    InventoryComparison Compare(
        InventorySnapshot reference,
        InventorySnapshot candidate);
}
```

PowerShell 和原生 Windows 实现都位于该端口之后。

### 4.5 测试与监控

```csharp
internal interface ITestPlanner
{
    TestPlan Compile(TestDefinition definition, TestTarget target);
}

internal interface ITestRunner
{
    IAsyncEnumerable<TestEvent> RunAsync(
        AuthorizedTestRun run,
        CancellationToken cancellationToken);
}

internal interface IMonitorSource
{
    IAsyncEnumerable<MonitorSample> SampleAsync(
        MonitorRequest request,
        CancellationToken cancellationToken);
}
```

文件型 `AuthorizedTestRun` 必须绑定明确测试根目录、登记文件清单和允许的辅助操作；
不能因为属于 Test 页面而绕过存储结构保护或路径限制。

### 4.6 外部工具

```csharp
internal interface IExternalToolRegistry
{
    Task<ToolState> DetectAsync(
        ToolId toolId,
        CancellationToken cancellationToken);

    Task<IReadOnlyList<ToolState>> ListAsync(
        CancellationToken cancellationToken);
}

internal interface IExternalToolAdapter
{
    ToolId ToolId { get; }
    ToolCapabilities Capabilities { get; }

    ToolInvocation BuildInvocation(
        TestStep step,
        AuthorizedTestWorkspace workspace);

    IAsyncEnumerable<ToolEvent> ParseAsync(
        ToolProcessStreams streams,
        CancellationToken cancellationToken);
}

internal interface IExternalSystemSupportToolAdapter
{
    ToolId ToolId { get; }
    ToolCapabilities Capabilities { get; }

    ToolInvocation BuildInvocation(
        AuthorizedSystemSupportAction action);
}

internal interface IToolInstaller
{
    Task<ToolInstallPlan> PlanAsync(
        ToolId toolId,
        CancellationToken cancellationToken);

    Task<ToolInstallResult> InstallAsync(
        AuthorizedToolInstall install,
        CancellationToken cancellationToken);
}
```

`ToolInvocation` 是适配器产生的不可变可执行文件、参数数组、工作目录、环境变量、
输入输出编码和超时，不是用户可编辑的整行 shell 命令。DiskSpd、fio、RoboCopy
使用测试工具适配器；RAMMap 使用系统辅助工具适配器，把已授权的缓存清理枚举映射为
经过测试的固定参数数组。

## 5. 用例返回模型

所有 Application 用例使用统一结果语义：

```csharp
internal sealed record ApplicationResult<T>(
    ApplicationStatus Status,
    T? Value,
    IReadOnlyList<ApplicationMessage> Messages,
    CorrelationId CorrelationId);
```

`ApplicationStatus` 至少包括：

- `Succeeded`
- `Rejected`
- `Cancelled`
- `Failed`
- `PartiallyCompleted`
- `RequiresAuthorization`
- `RequiresEnvironment`

错误必须包含稳定错误码、用户文本键、诊断文本和相关对象，但不得在持久化日志中泄露敏感硬件信息。

## 6. 任务和事件模型

所有长任务采用同一生命周期：

```text
Created
  -> Planning
  -> Validating
  -> AwaitingAuthorization
  -> Queued
  -> Running
  -> Verifying
  -> Succeeded | Failed | Cancelled | PartiallyCompleted | Rejected
```

要求：

- 每次状态变化写入事件。
- 事件包含 UTC 时间、相关 ID、步骤、进度和脱敏诊断。
- UI 通过订阅事件更新，不轮询具体基础设施。
- 取消是请求，不伪装成立即完成。
- 应用崩溃后可从数据库判断最后已知状态。
- 不自动重放存储结构修改任务。
- 只读扫描和监控可按显式策略恢复。
- 文件型测试崩溃后只恢复状态和证据；是否继续写入必须由用户确认。

## 7. 幂等、并发和锁

- 操作请求有唯一 `OperationId`。
- 计划包含规范化参数摘要和 `PlanHash`。
- 同一计划不能被重复授权后静默重复执行。
- 锁作用于稳定对象身份，不作用于显示名称。
- 读取可以并发；修改型计划与相关对象的其他计划互斥。
- 测试目标与监控可以并发，但必须报告采样干扰。
- Agent 是 SQLite 主写入协调者；Worker 通过命名管道提交事件和批次。
- 数据库写入由独立写入队列串行提交，读取使用独立连接。
- 并发冲突返回明确状态，不用最后写入覆盖。

## 8. 数据与附件边界

SQLite 保存结构化状态和高容量指标；大型文件仍保存在数据根目录：

```text
<data root>/
  winpool.db
  Attachments/
  Exports/
  Imports/
  TestArtifacts/
  MonitoringArtifacts/
  Tools/
  Logs/
```

- 数据库保存附件相对路径、大小、SHA-256、类型和来源。
- 导入文件先复制到隔离区并校验，再解析。
- 导入内容永远作为数据，不解释为脚本或命令。
- 标准/便携切换迁移数据库与附件，并保留旧位置。
- 当前阶段不保证旧 JSON 自动迁移；必要数据通过显式手工工具导入。
- 外部工具默认安装在用户确认的位置；数据库只保存配置、版本、来源和哈希，
  不把工具二进制作为数据库附件。

## 9. 算法置信度

每个非平凡算法登记以下信息：

- `AlgorithmId`
- 版本
- 输入和输出
- 假设
- 参考来源
- 验证数据集
- 置信度

置信度：

- `Validated`：已由本项目实验或权威定义验证。
- `Derived`：由已验证规则推导，已有测试但缺少完整实机覆盖。
- `Speculative`：合理推测，尚未完成实机验证。

`Speculative` 在中文文档中统一写作 `【推测，待验证】`，代码必须使用类似注释：

```csharp
// 【推测，待验证】ALGO-IO-007：
// 该队列深度调整规则尚未在目标 Storage Spaces 配置上完成对照实验。
```

UI 显示推测性建议时必须展示“待验证”，不能包装成确定结论。

## 10. 不冻结公共 API

V0.2 不提供稳定公共 API。以下内容均可在测试阶段改变：

- C# 接口命名和程序集划分；
- SQLite schema；
- JSON 导入导出 envelope；
- 测试定义格式；
- 内部事件结构；
- 模拟系统 schema。

只有当 Application contracts 在多个内部模块中稳定、测试覆盖充分且对象模型不再频繁变化后，才单独评估公共 API。
