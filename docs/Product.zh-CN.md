## 目标

WinPool 是第三方 Windows 存储系统桌面应用。长期目标是用统一界面替代割裂的“磁盘管理”和“存储空间”图形体验，集中呈现存储拓扑、测试、监控和可审阅操作。

产品应清晰表达系统、存储池、存储层、物理磁盘、虚拟磁盘、分区、卷、网络存储与其他逻辑组之间的关系，同时不隐藏重要参数。

## 产品原则

- 同时呈现完整存储拓扑和聚焦的操作工作区。
- 所有拟执行操作必须明确、可审阅、类型化且可审计。
- 将模拟和只读发现作为一等能力。
- 集成测试、监控、比较与证据导出，但不捆绑或重新实现外部基准引擎。
- 内部契约应足以支持未来开发者和 AI Agent 使用，但目前不冻结公共 SDK、插件 API、数据库契约或线协议。
- 保持双语、主题感知、键盘可访问、高对比度和响应式桌面行为。

## 产品边界

WinPool 可以通过只读采集器检查本机、编辑持久化模拟系统、执行登记目录文件测试、监控支持的设备，以及执行经过明确审阅的辅助动作。

真实存储结构修改不属于 V0.3 产品边界。在此产品线期间，WinPool 不得初始化、清理、格式化、创建、删除、修复或调整真实磁盘、分区、卷、存储池、存储层或虚拟磁盘。V0.5 是最早可通过经过审阅的类型化计划引入这些操作的阶段；产品并非永久只能模拟。

从 V0.5 起，每次真实修改都有两类明确授权：

- 开发 Agent 每次执行实际修改前，必须立即向开发者请求批准，明确说明操作和目标；先前、宽泛或隐含的批准均不适用。
- 产品用户在当前会话显式选择“本机真实修改”选项，即授权执行 V0.5 的受控真实操作。UAC 提权或 Real 模式本身不构成同意，且同意不得预选或持久化。

真实修改路径必须保留类型化操作、目标校验、操作预览和审计记录。模拟仍为默认路径，自由形式存储命令仍不属于产品边界。

DiskSpd、fio、Dite、RoboCopy 和 RAMMap 保持独立安装。WinPool 只通过类型化适配器和经过校验的目标发现或调用它们，不捆绑其引擎。

## 当前架构线

V0.3 保留已接受的 V0.13 视觉基线和 V0.2 多进程重写：

- 一个无打包 WinUI 3 App；
- 一个可见的每用户托盘 Agent 和 SQLite 写入者；
- 一个隔离 TestWorker；
- 一个一次性提权 Broker；
- 类型化命名管道 IPC 和默认拒绝执行策略。

项目版本只采用 `Va.bc`。架构里程碑只写到 `Va.b`；数据库 schema 修订号、算法 ID 和 IPC 兼容标识属于内部契约，不构成额外项目版本。

## 已确认开发路线

用户于 2026-08-12 确认以下产品路线。它定义的是各阶段目标，并不授权绕过产品边界、替代活动 Plan，也不表示某阶段已完成。当前本地实施版本为 V0.39，属于 V0.3 迭代线。

| 阶段 | 目标 | 状态或约束 |
| --- | --- | --- |
| V0.1 | 交付最小原型，确定基本前端视觉方向。 | 已完成的历史基础。 |
| V0.2 | 完整重构代码，确定基础架构和开发规则。 | 已完成的历史基础。 |
| V0.3 | 修复代码缺陷，保证正常运行。 | 已在 V0.39 完成最终最小修正检查点。剩余原生、人工和平台证据继续如实记录，不会因版本确认而写成通过。 |
| V0.4 | 补完美术与视觉打磨，完善已有功能和基本交互。 | 下一正常阶段，从 V0.40 开始；保持可访问性和已接受的结构基线。 |
| V0.5 | 补完管理和编辑工作流，形成可替代旧版 Windows 存储 GUI 的现代化功能体验。 | 首个允许在开发者和产品用户显式授权模型下引入受控真实存储结构操作的阶段。 |
| V0.6 | 补完测试和监控功能。 | 外部工具仍须通过类型化适配器和显式目标校验接入。 |
| V0.7 | 补完面向开发的功能和 AI Agent 功能。 | 内部模型稳定前，不冻结公共 SDK、插件 API、数据库契约或线协议。 |
| V0.8 | 补完剩余已批准功能，关闭已知的发布阻断缺陷和质量缺口。 | 未来未知缺陷不能预先宣称已经修复；验收必须以记录的证据为准。 |
| V0.9 | 进入内测，在定义好的受支持 Windows 平台矩阵上测试并修复问题。 | 矩阵必须明确 Windows 版本、版本类型、架构、硬件/设备覆盖和所需人工证据。 |
| V1.0 | 发布正式版。 | 必须通过已批准的 V0.9 发布就绪门；tag、二进制上传和 GitHub Release 仍需分别明确授权。 |

每个实施阶段都需要各自确认的 `docs/Plan.md`。默认拒绝执行器、存储编辑模拟优先、只读盘点、数据脱敏和外部工具边界在整个路线中持续生效；V0.5 的真实修改是对“只允许模拟”规则已定义且须明确授权的例外。
